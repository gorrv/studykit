Topic 07 · Logic programming

Introduction to Logic Programming

describe the problem; let inference find the answer
The founding idea
The main idea behind logic programming is to combine logic and programming:
  • Logic is used to express knowledge, describe the problem, etc.
  • Inference is used to compute, manipulate knowledge, and obtain a solution to the problem.

Topic 01 put it in one line: "programs describe a problem rather than defining an algorithmic implementation."

Advantages and disadvantages

Advantages — note which one is special
  • Knowledge-based programming
  • A declarative style of programming: the program says what should be computed, rather than how it is computed
  • Precise and simple semantics
  • The same formalism can be used to specify a problem, write a program, and prove properties of the program
  • The same program can be used in many different ways

The first points are shared with functional languages, but the last point is specific to logic programming languages. If an exam asks what distinguishes logic from functional programming, this is the answer — and the reverse example below is the evidence.

The example that makes the point

reverse([],[]). reverse([H|T],List) :- reverse(T,Z), append(Z,[H],List).

A

variable in position 2
?- reverse([1,2,3],X). X = [3, 2, 1].

B

variable in position 1
?- reverse(X,[3,2,1]). X = [1, 2, 3].

C

no variables at all
?- reverse([1,2,4],[3,2,1]). false.
The observation to quote
The variable X was used in different argument positions in A) and B), and no variables were used in C). This is because unlike in a functional programming language, there is no intrinsic notion of "input" and "output" variables.

One program, three uses: compute the reverse, invert the computation, and check a claim. A Haskell reverse :: [a] → [a] can only ever do the first.

Disadvantages
  • The ability to support efficient arithmetic and input/output operations such as file handling is provided at the expense of the declarative semantics.
  • Most logic languages are restricted to a fragment of classical first-order logic. There are languages based on more powerful logics, but they are not widely used.

Syntax basics: terms, atomic formulas, literals

Domain of computation: terms
The set of terms is defined using:
  • variables, represented by X, Y, Z, …
  • function symbols, with fixed arities, represented by f, g, h, … or a, b, c, … for constants of arity zero

A term is either a variable, or has the form f(t₁, …, tₙ), where f is a function symbol of arity n and t₁, …, tₙ are terms.

If a is a constant, f a binary function, g a unary function, and X, Y variables, these are all terms:

X a g(a) f(X, g(a)) Y f(f(X, g(a)), Y) g(f(f(X, g(a)), Y))
Predicate symbols, atomic formulas, literals
  • Let p, q, r … represent predicate symbols, each with a fixed arity.
  • If p is a predicate of arity n and t₁, …, tₙ are terms, then p(t₁, …, tₙ) is an atomic formula, A, B, …
  • A literal is an atomic formula A, or a negated atomic formula ¬A.

Think of a predicate symbol as expressing a relationship between elements of the domain — e.g. father_of(peter,paul).

With rainy, snowy unary predicates, temperature binary, celsius a unary function symbol, tuesday and zero constants:

temperature(tuesday, celsius(zero)) ¬rainy(tuesday) snowy(X)
The rule that all the exercises test
Only terms can be used as arguments in predicates. And note celsius(zero) is a (unary) functional term — not a predicate. Predicates and functions look alike but live at different levels: functions build terms; predicates make statements about them. A predicate can never appear inside another predicate's arguments.

Horn clauses

Definition
A Horn clause is a disjunction of literals of which at most one may be positive. So it may have:
  • a single positive literal and some negative literals;
  • a single positive literal (and no negative literals);
  • or only negative literals.

A Horn clause with one positive literal (the first two cases) is called a definite clause. Note: this terminology is not uniform — in some books all Horn clauses are called definite clauses.

Facts, rules, goals and programs

Fact

A definite clause comprising a single positive literal A.

Rule

A definite clause with some negative literals:  A ∨ ¬B₁ ∨ … ∨ ¬Bₙ

Goal

A Horn clause containing only negative literals: ¬B₁ ∨ … ∨ ¬Bₙ, written :- B₁, B₂, …, Bₙ.  A goal can be thought of as a query to the program.

Programs are sets of definite clauses, so they are composed of facts and rules.

Why a rule is an implication written backwards
Recall that A ∨ ¬B₁ ∨ … ∨ ¬Bₙ can be re-written as
¬(B₁ ∧ B₂ ∧ … ∧ Bₙ) ∨ A
which is equivalent to
(B₁ ∧ B₂ ∧ … ∧ Bₙ) → A

In Prolog parlance we read the implication backwards: "A, if B₁ and B₂ and … and Bₙ". The "if" is the symbol :- and the conjunction is a comma:

A :- B₁, B₂, …, Bₙ
More on facts
Facts are unconditional statements about the world. They can be used in the base case of recursive definitions, and in Prolog they must appear before rules:
factorial(0,1). factorial(X,N) :- X>0, X1 is X-1, factorial(X1,N1), N is X*N1.

Note that we cannot pass "X-1" directly as an argument to factorial, so we must first instantiate the result of this operation to the variable X1. (This will not work if X is not bound in the call to factorial.)

Why X-1 can't be passed directly — this catches everyone
In Prolog, X-1 is a term — the compound -(X,1) — not a computed number. It would be matched syntactically against 0 in the base case and never unify. Arithmetic only happens when you explicitly ask for it with is. This is the clearest example of what the list of disadvantages meant by "efficient arithmetic … at the expense of the declarative semantics".

Variables are universally quantified

Used in a program, all clauses are individually universally quantified on all variables. For example, the clauses

likes(X, P) ∨ ¬based(P, Y) ∨ ¬likes(X, Y) attends(X, Y) ∨ ¬registered(X, Y) ∨ ¬likes(X, Y)

actually represent the universally quantified formulas

∀X∀P∀Y ((based(P, Y) ∧ likes(X, Y)) → likes(X, P)) ∀X∀Y ((registered(X, Y) ∧ likes(X, Y)) → attends(X, Y))

The informal procedural mechanism

Program: rainy(tuesday).  temperature(tuesday, celsius(0)).  snowy(X) :- rainy(X), temperature(X, celsius(Y)), Y =< 0.   Query: :- snowy(X).

1:- snowy(X).look for clauses with the same predicate in the head
2:- rainy(X), temperature(X, celsius(Y)), Y =< 0.a match was found — replace snowy(X) by the body of the matching clause, replacing variables as required (substitutions)
3:- temperature(tuesday, celsius(Y)), Y =< 0.solve rainy(X) by replacing X by tuesday
4:- 0 =< 0.solve the next literal by replacing Y by 0
5□  succeeds"=<" is built-in — so the original goal succeeds
What just happened, in Part-1 vocabulary
That is a transition system: configurations are goals, and one transition replaces the selected literal by the body of a matching clause, under a substitution. Topics 3–4 built exactly this machinery for SIMP. Topic 08 will make it formal — it is called SLD-resolution.

Variable substitutions

Definition
Values are terms associated to variables by means of automatically generated substitutions.
  • A substitution is a partial mapping from variables to terms, with a finite domain.
  • Written σ = {X₁ ↦ t₁, …, Xₙ ↦ tₙ}; dom(σ) denotes {X₁, …, Xₙ}.

Notice that we always replace variables with terms (not the other way around), because only variables can be replaced and not all terms are variables.

Application is simultaneous — the detail worth dwell on
A substitution σ is applied to a term t or literal L by simultaneously replacing each variable occurring in dom(σ) by the term associated to it. The result is written tσ or Lσ.

Consider σ = {X ↦ Y, Y ↦ a}. σ is a set. If we applied it in sequence, say left to right, we would effectively replace X by a in t. In fact, we need to replace X by Y at the same time that we replace Y by a.

tf(f(X, g(a)), Y) σ{X ↦ g(Y), Y ↦ a} tσf(f(g(Y), g(a)), a)
L¬p(X, X, f(g(a), Y)) σ{X ↦ f(a,b), Y ↦ Z, Z ↦ b} Lσ¬p(f(a,b), f(a,b), f(g(a), Z))

The second example makes two points at once: variables that do not appear in the term are not affected, and the Y ↦ Z mapping does not then trigger Z ↦ b — simultaneity again.

Why substitutions exist: the informal motivation
Consider the goal :- r(a). and the program p(a). p(b). q(a). r(X) :- p(X), q(X).

We would like to "resolve" the negative literal r(a) in the goal with an instance of the positive literal r(X), but we need to "commit" to X being bound to the constant a first. This is done by applying σ = {X ↦ a} to the rule, giving the instance r(a) :- p(a), q(a).

Summary of clauses in Prolog

Four facts that decide how a program behaves
  • A program in Prolog is a list of facts and rules, using its own syntax.
  • In first-order programs, all variables are assumed to be universally quantified.
  • The order in which the clauses are defined is critical to the evaluation of the program, because resolution is applied in program appearance order.
  • Within a goal, a selection function chooses the next literal to resolve. In Prolog, the selection function always chooses the left-most literal in the goal.

If the query succeeds, the variables correspond to the answers and are obtained as a by-product of the resolution process.

"Answers as a by-product" is a genuinely strange idea — sit with it
You never return anything in Prolog. You ask whether a goal can be proved; the proof requires binding variables; and those bindings are the answer. That's why the same program runs "forwards" and "backwards" in the reverse example — nothing in the clause distinguishes an input from an output.

The running example program of §8.2, with five facts and a rule:

based(prolog, logic). based(haskell, maths). likes(claire, maths). likes(claire, logic). likes(max, logic). likes(X, P) :- based(P, Y), likes(X, Y).
Exercise · informal reading

Program:

  • The first two facts state that Prolog is based in logic and Haskell in Maths.
  • The next two state that "claire" likes maths and logic and that "max" likes logic.
  • The rule states that someone will like any language which is based on a subject they like.

Queries:

  • :- likes(claire, haskell). — Does claire like Haskell?
  • :- likes(max,L), likes(claire,L). — Is there something that both Max and Claire like?
  • :- likes(Z, prolog). — Does anybody like Prolog?

Notice that even the operators are predicates

hot(Day) :- temperature(Day, celsius(Temp)), Temp > 30. heatwave(Day, Day) :- hot(Day). heatwave(First, Last) :- hot(First), follows(First, Next), heatwave(Next, Last).

Lists in Prolog

Like in functional programming, linked lists are a very important data structure and have their own special syntax.

  • The constant [] denotes the empty list.
  • The built-in | is the "cons" operator that joins an element X to the front of a list L: [X | L].
  • [X | [Y | [Z | []]]] is abbreviated to [X, Y, Z].
Matching
The pattern [] only matches with the empty list and the pattern [H|T] only matches with a non-empty list.

The query [H|T]=[1,2,3] succeeds with H = 1, T = [2,3]. In general H is the head of [H | T] and T is the tail. Built-in predicates for common operations: member/2, length/2, sort/2, …

append/3

The predicate append(S, T, U) expresses that the result of appending the list T onto the end of list S is the list U (pre-defined):

append([], L, L). append([X | L], Y, [X | Z]) :- append(L, Y, Z).

Three queries worth asking about — what do they do, and what answers do they get?

QueryWhat it doesAnswer
:- append([0], [1, 2], U)Concatenates, forwardsU = [0,1,2]
:- append([1, 2], X, [0])Asks what to append to [1,2] to get [0]fails — [0] is shorter than [1,2]
:- append(X, [1, 2], U)Leaves both X and U openinfinitely many solutions: X=[], U=[1,2]; X=[A], U=[A,1,2]; …

Language limitations: negation

What you cannot write
Prolog programs are composed of definite clauses, which contain exactly one positive literal. This means it is not possible to directly state facts involving negative statements, nor rules with a negative literal in the head:
p(a). OK ¬p(b). not allowed! r(X) :- p(X). OK ¬r(X) :- p(X). not allowed!

Why the restriction? General resolution

Computation is done in terms of the resolution rule:

A ∨ B
¬A ∨ C
Res
B ∨ C

Any two clauses can be "resolved" as long as they contain complementary literals, potentially generating multiple results. Resolving A ∨ B with ¬A ∨ ¬B ∨ C gives either:

  • B ∨ ¬B ∨ C  (from resolving A and ¬A)
  • A ∨ ¬A ∨ C  (from resolving B and ¬B)
Two difficulties with unrestricted clauses
  1. Clauses can be resolved in multiple ways.
  2. We need to arbitrarily choose the next pair of clauses to resolve.

To address these, clauses in a program must have exactly one positive literal (they are "Definite") and clauses in the goal contain only negative literals.

The consequences — and where the name SLD comes from
  • The resolution of a program clause with a goal can be made unique and deterministic (if we use program order and employ a selection function) — "Selective".
  • The resolvent of two clauses will either be empty or generate a new goal — "Linear".

Selective · Linear · Definite — SLD-resolution, the semantics Prolog is built on. Topic 08 makes it formal. Notice this is an argument you can reconstruct: the restriction to Horn clauses is not arbitrary, it is exactly what makes resolution deterministic enough to be a programming language.

Negation as failure

The principle
To mitigate the lack of logical negation, Prolog uses a weaker form called negation as failure. Informally: failure to prove a literal A is taken as proof that ¬A follows.

Using this principle, a negative literal ¬A is allowed to appear in the body of a clause (and hence in the goal too). In Prolog it is written \+.

p(a). q(a). s(b). r(X) :- p(X), q(X), \+ s(X).

In this program ¬p(b), ¬q(b) and ¬s(a) are indirectly assumed to be true, since their positive counterparts fail.

QueryResultWhy
:- p(a).succeedstherefore :- \+ p(a). fails
:- q(a).succeedstherefore :- \+ q(a). fails
:- s(a).failstherefore :- \+ s(a). succeeds
:- r(a).succeedsbecause p(a), q(a) and \+ s(a) all succeed
:- \+ r(a).failsbecause r(a) succeeds
:- r(b).failsbecause p(b) fails, and so on
Negation as failure is not logical negation
It is negation relative to what the program happens to say. \+ s(a) succeeds not because the program asserts that s(a) is false, but because it fails to prove it — the closed-world assumption. Anything not derivable is treated as false. That's why these negative facts are called "indirectly assumed".

Language limitations: disjunction

Why A ∨ B cannot be represented faithfully
Each clause is a disjunction of literals of which at most one is positive, so a genuine disjunction of two positive literals is not expressible.
  • If we added the facts A. and B., we would get A ∧ B, which is logically stronger than A ∨ B  (A ∧ B ⊢ A ∨ B, but A ∨ B ⊬ A ∧ B).
  • We can re-write A ∨ B as ¬A→B or ¬B→A, giving the rules B :- \+ A. and A :- \+ B. — but due to how negation as failure works, this does not have the same effect as a "true" disjunction.

Exam-style takeaways

Key things to nail for Topic 07
  1. The core idea — logic expresses knowledge/describes the problem; inference computes and obtains a solution.
  2. Advantages — knowledge-based; declarative (what not how); precise and simple semantics; one formalism for specification, program and proof; the same program can be used in many different ways. Know that only the last is specific to logic programming.
  3. The reverse example — three queries, X in different argument positions and none at all, because there is no intrinsic notion of input and output variables.
  4. Disadvantages — efficient arithmetic and I/O come at the expense of the declarative semantics; most logic languages are restricted to a fragment of classical first-order logic.
  5. Prolog's five facts — Colmerauer and Roussel, early 1970s; NLP and AI; syntax = the clausal fragment of classical FOL; semantics = SLD-resolution with automatic backtracking; impure (non-logical primitives).
  6. Terms — built from variables and function symbols with fixed arity (constants = arity zero). A term is either a variable or f(t₁,…,tₙ).
  7. Atomic formulas and literals — p(t₁,…,tₙ) is atomic; a literal is A or ¬A. Only terms can be arguments of predicates.
  8. Do the validity exercises — why (X,a), g(f), q(g(Y),a) and ¬p(q(g(Y),g(a))) all fail.
  9. Horn clause — a disjunction of literals of which at most one is positive; three shapes. Definite clause = exactly one positive literal.
  10. Fact / rule / goal — single positive literal; positive plus negatives; only negatives (written :- B₁,…,Bₙ., a query). Programs are sets of definite clauses.
  11. The rewriting — A ∨ ¬B₁ ∨ … ∨ ¬Bₙ ≡ ¬(B₁∧…∧Bₙ) ∨ A ≡ (B₁∧…∧Bₙ)→A, read backwards as A :- B₁,…,Bₙ.
  12. Classify and translate clauses — the 8.2 exercise, including recognising q(a) ∨ p(b,g(X)) as not a Horn clause.
  13. Facts before rules; and why X-1 cannot be passed directly to factorial — you must bind it with is first.
  14. All clauses are universally quantified on all their variables — be able to write out the ∀-form of a rule.
  15. Substitutions — a partial mapping from variables to terms with finite domain, σ = {X₁↦t₁,…}; dom(σ). We always replace variables by terms, never the reverse.
  16. Application is simultaneous — know the σ = {X↦Y, Y↦a} caution, and be able to compute tσ and Lσ for the two worked examples.
  17. Order matters twice — clause order (resolution proceeds in program appearance order) and literal order (Prolog's selection function always chooses the left-most literal). Answers are a by-product of resolution.
  18. Built-in predicates — operators, is, call/1, fail/0, !/0 (cut), ',', =.., write, nl. The p/n notation.
  19. Lists — [], [X|L], the abbreviation; [] matches only the empty list and [H|T] only a non-empty one; head and tail. Write member/2, length/2, reverse/2 (both versions) and append/3.
  20. The three append queries — forwards, failing, and infinitely many solutions.
  21. Negation limitation — no negative facts, no negative heads. The resolution rule and the two difficulties with unrestricted clauses.
  22. Why definite clauses — resolution becomes unique and deterministic (Selective) and the resolvent is empty or a new goal (Linear). Together with Definite: SLD.
  23. Negation as failure — failure to prove A is taken as proof of ¬A; written \+; be able to run the six sample queries on the p/q/s/r program.
  24. Disjunction — cannot be represented faithfully; adding both facts gives the stronger A ∧ B; rewriting via \+ does not behave like true disjunction.
