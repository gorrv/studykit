Machines With No Memory

DFAs, NFAs, and how a set of states replaces guessing

The previous topic ended with a matcher that has to guess and come back. This one is what you build so that it never has to. A finite automaton has no memory beyond which state it is in — that is the whole restriction — and it turns out to be exactly enough for regular expressions, with the useful side effect that matching costs one step per character no matter what the pattern is.

A deterministic finite automaton

Five things
A(Σ, Qs, Q₀, F, δ)
Σan alphabet — the characters it can read
Qsa set of states
Q₀one of them is where it starts
Fsome of them accept
δa transition function: a state and a character give a state
Running it is as simple as it sounds: start at Q₀, read the characters one at a time, follow δ. When the input runs out, accept if you are standing on a state in F.
δ might not be defined everywhere
There need not be an entry for every state and character. If the machine reads something it has no move for, it is stuck — and a stuck machine rejects.

This is worth being comfortable with rather than avoiding. A partial δ is often the clearest way to write a machine down, and "no transition" and "a transition to a state that can never accept" say the same thing. Some definitions insist on a total δ and add a dead state to absorb everything; that is the same machine with more boxes drawn.

Nondeterminism

One change, and it is a different kind of machine
δ now gives a set of next states rather than one — possibly empty, possibly several. The machine is allowed to be in more than one place.

Acceptance means: some path through the machine ends on an accepting state. Not all of them, and you do not have to say which.

That sounds like it needs a search, and it is why an NFA is so much easier to write: you can guess where the interesting part of the string starts instead of remembering how you got here.
Running one without searching
Do not try one path and come back. Carry the set of states you could be in and take them all forward together: for each state in the set, follow the transitions for the character just read, and union the results.

One pass, one set per character, no backtracking. This is exactly the thing the exponential matcher in the previous topic was not doing — and the reason it is possible here is that a finite automaton has nowhere to store anything except which state it is in, so the set of possibilities can never be larger than the number of states.

The subset construction, and why it closes the loop
If running an NFA means tracking a set of states, then a DFA whose states are those sets does the same job with no set arithmetic left at run time. Build it once: start from the set containing Q₀, and for each set and character work out the set you land in, adding any set you have not seen before.

The result is an ordinary deterministic machine. It can have up to 2n states for an n-state NFA, and in practice almost never does, because only the reachable sets get built.

That is the whole chain. A regular expression becomes an NFA, the NFA becomes a DFA, and the DFA matches in one table lookup per character — no guessing, no backtracking, and no pattern that can make it take exponential time.

Takeaways

If you remember five things
  1. A DFA is five things: alphabet, states, a start state, accepting states, and a transition function.
  2. δ may be partial. No transition means stuck, and stuck means rejected.
  3. An NFA's δ gives a set, and it accepts when some path accepts.
  4. Run an NFA by carrying the set of possible states — one pass, no backtracking.
  5. The subset construction makes that a DFA, doing the work once instead of per match. Up to 2n states in theory, far fewer in practice.
Things that catch people out
  • Thinking an NFA is more powerful than a DFA. It is not — it recognises exactly the same languages, just more conveniently.
  • Reading "accepts if some path accepts" as "accepts if all paths accept".
  • Forgetting that a stuck DFA rejects rather than erroring.
  • Expecting the subset construction to blow up. The bound is 2n; the reachable sets are usually a handful.
  • Building a DFA by hand and forgetting a character in some state, which quietly makes it partial.
