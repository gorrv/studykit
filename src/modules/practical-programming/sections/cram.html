Topic 01 · first steps in C++

The shape of a program
#include <iostream>, int main() { … return 0; }, not inside a class, no String[] args.
g++ -std=c++11 -o hello hello.cc then ./hello — a native executable, no JVM.
A prototype int answer(); lets you define the body later.
Semicolon after a class’s closing brace.
The one that matters
Coordinate b = a;copy constructor two objects
Coordinate & r = a;reference one object, two names
const Coordinate & c = a;const reference one object, read-only through c

Parameters the same way: by value copies, by reference aliases, by const reference aliases without permission to modify. References cannot be null and cannot be reseated.
Constructors
Coordinate(int xIn, int yIn) : x(xIn), y(yIn) { }

Members are constructed before the body runs. Everything follows:
• member with no default constructor ⇒ the initialiser list is the only option
• member that is const or a reference ⇒ likewise
• otherwise the body version compiles, and default-constructs then assigns — one operation more than needed

Writing any constructor removes the free default one, so Coordinate b; and vector<Coordinate> v(2); both stop compiling. push_back never needs a default constructor.
const
int getX() const { return x; } — the method promises not to modify.
Through a const reference only const methods may be called, so const spreads from wherever you first wrote it.
Const is one-way: a const T & may bind to a modifiable object, never the reverse. Hence, given const Coordinate & getStart(), Coordinate & b = j.getStart(); is the one line of the four that fails.
Operators
For a == b with a of type A, b of type B, provide one of
class A { public: bool operator==(const B & rhs) const; };
bool operator==(const A & lhs, const B & rhs);
The member goes on the left type; the free function works when you cannot edit that type.

ostream & operator<<(ostream & o, const Coordinate & rhs) — must return the stream, because cout << x << y is (cout << x) << y. Cannot be a member, since the left operand is the stream; pair it with a public write(ostream &) const when it needs privates.
Traps
  • Expecting Coordinate b = a; to alias, as Java would.
  • Missing semicolon after a class body.
  • Returning a non-const reference to a member, breaking your own invariants.
  • Forgetting const on getters.
  • Putting operator== on the right-hand type.
  • Returning void from operator<<.
  • Reading an uninitialised int, or off the end of a vector — both undefined behaviour, neither reported.

Topic 02 · pointers and ownership

Stars
string ca string
string * ba pointer to a string
*bthe string b points at
&ca pointer to c
b->size()same as (*b).size()

* removes a star, & adds one, both sides must match. Pointers can be nullptr; references cannot. Comparing pointers compares addresses — the Java == trap, back again.
new and delete
Every new needs a delete, on every path out — the early return is where leaks really come from. new [] pairs with delete []; mixing them is undefined behaviour, not an error.

Prefer vector: it knows its size and frees itself when it falls out of scope. int & operator[](int) returns a reference, which is what makes v[i] += 1 work; the const int & operator[](int) const overload is the one chosen through a const vector<int> &.
The four the compiler writes
Default constructor (only if you write no constructor at all), copy constructor, assignment operator, destructor. Ask for the default back with C() = default;.

b = a; is b.operator=(a); and c = b = a; is c.operator=(b.operator=(a));, so operator= returns C & — return *this;. this is a pointer; *this is the object. The copy constructor’s parameter must be a reference, or copying the argument would need the copy constructor.
The Rule of Three
Need one of copy constructor, assignment operator, destructor — need all three. They exist for one reason: the class owns something the compiler cannot copy or release.

Copy constructor: str = new string(*(other.str)), guarding nullptr.
operator=: self-check, delete the old, deep copy, return *this.
Destructor: delete str.

Shallow copy ⇒ two objects share one string ⇒ they see each other’s changes, and both destructors free it.
Traps
  • Comparing pointers when you meant the things they point at.
  • Missing the delete on an early-return path.
  • delete where delete [] was needed.
  • A deep copy constructor with a shallow assignment operator.
  • An assignment operator that deep copies but never frees what it overwrote.
  • Freeing the old string without a if (this == &other) guard — a = a; then reads freed memory.
  • Returning by value from operator=.

Topic 03 · templates and the STL

Templates
template<typename T> class C { T * elements; ... }; — the argument is part of the type, and the compiler generates the class once per type used.

template<typename T> const T & max(const T &, const T &); — call as max<int>(a,b) or let deduction work it out. Two different argument types make deduction fail; it never promotes one to the other.

pair<A,B> has first and second. tuple<...> is read with std::get<0>(t) — a free function, and the index must be a compile-time constant.
Iterators
begin() is the first element; end() is past the last and must never be dereferenced. Loop with !=, not <.

insert(itr, x) — inserts before itr, returns an iterator to the new element.
erase(itr) — returns an iterator to what is now there. Use itr = c.erase(itr); when removing in a loop.
find(k) — returns end() if absent. Check before dereferencing.

Vector iterators support begin() + 2 (contiguous); list iterators do not (nodes and links). A range-for is exactly a begin/end loop — anything with both can be used with it, including your own classes.
Function objects and maps
A class with operator() is a function object; comp(a,b) is comp.operator()(a,b). It can carry state, which a function pointer cannot. Pass one in when operator< would have to mean two different things.

map is a search tree ordered by key, using less<K> by default: template<typename K, typename V, typename Comp = less<K>>.

An element is pair<const K, V> — the key is const because the tree is ordered by it. Loop with auto &.

insert copies a finished pair; emplace forwards the pieces to the node’s constructor (perfect forwarding), as emplace_back does for a vector. Both return pair<iterator, bool>, and both do nothing if the key is already there. m[k] = v does overwrite.
Traps
  • t.get<0>() instead of std::get<0>(t).
  • pair<int,string> & looping a map — the key is const.
  • Expecting deduction to promote int and double.
  • Dereferencing end(), or find’s result unchecked.
  • ++itr after erase(itr).
  • begin() + 2 on a list.
  • Expecting insert/emplace to overwrite an existing key.

Topic 04 · ownership and moving

Value categories
lvalue — names something that is still there afterwards: a variable, *p, a[i], a call returning T &.
rvalue — a temporary: a literal, a + b, a call returning T, and std::move(x).

lvaluervalue
T yyesyes
T & yyesno
const T & yyesyes — and extends its life
T && ynoyes
The classic failure: void f(double &) called with an int. The conversion makes a temporary and the non-const reference will not bind.
Moving
A T && parameter means this argument is expendable, so the function may take its contents. That is all move semantics is. 
unique_ptr & operator=(unique_ptr && other) {
  delete d; d = other.d; other.d = nullptr; return *this;
}
Overload preference: for an rvalue, T && beats const T &; for a modifiable lvalue, T & beats const T &; const T & is the fallback that takes everything.

std::move is a cast. It moves nothing; it makes an lvalue look like an rvalue so the stealing overload is picked. A moved-from object is valid and unspecified — usually empty.
unique_ptr
Deletes what it owns when it goes out of scope. Copy constructor and copy assignment are = deleted, so there is exactly one owner; move constructor and move assignment hand ownership over.

get() — the raw pointer, ownership unchanged. Never delete it.
reset(q) — deletes what was held, then takes q.
release() — hands back the raw pointer and deletes nothing. Drop it and it leaks.
explicit operator bool() — so if (p) works. Without explicit, p + 1 also compiles.
Flags and traps
-Wall -Werror -g -D_GLIBCXX_DEBUG — more warnings, warnings as errors, debug info, and standard-library bounds checking.
Comparing int i with v.size() is a warning; cast or change the type.
A Makefile recipe line must start with a tab.
A non-void function with no return compiles by default and is undefined at run time — one of the things -Wall -Werror catches.

Topic 05 · inheritance

Syntax
class Bikes : public Coordinate instead of extends. Base built in the initialiser list, : Coordinate(x, y), not the body. Base version reached as Coordinate::printDetails(); there is no super.

virtual void f() = 0; makes the function pure virtual and the class abstract. No abstract keyword.
Dispatch
Without virtual, the declared type decides, at compile time. A Coordinate & referring to a Bikes calls Coordinate::printDetails. This is the opposite of Java.

With virtual, the object decides. Every object of the class carries a hidden first member pointing at its class’s vtable, and the call reads the address from there. Cost: 8 bytes per object, one indirection per call.

override is optional and worth writing — it turns a mistyped signature into an error.

Virtual destructor whenever a class has any virtual function, or deleting through a base pointer never destroys the derived part.
Layout
Members in order, base subobjects first, each aligned to its own size; the vtable pointer, if any, before all of them.
two ints → 8  ·  plus one more int in a derived class → 12  ·  add a virtual function → 16 and 24.

With multiple inheritance only the first base sits at offset 0; converting to a pointer to any later base shifts the address, and casting back shifts it back.
Slicing
Coordinate c = someBikes; copies only the Coordinate part, silently, and what remains behaves as a Coordinate even through virtual calls. So: vector<Coordinate> slices; vector<Coordinate*> works but leaves deleting to you; vector<unique_ptr<Coordinate> > with emplace_back(new Bikes(...)) is the answer.
The four casts
static_cast — checks at compile time that the types are related; nothing at run time. Downcasting with it is undefined if you are wrong.
dynamic_cast — checks at run time. nullptr on failure for pointers, std::bad_cast for references. Needs a vtable: a non-polymorphic source is a compile error.
const_cast — the only one that removes const.
reinterpret_cast — no checks of any kind.

Casting up, derived to base, needs no cast at all.

Scala 01 · values and types

Types
Int (32-bit, the JVM’s), Long, BigInt (exact), Float/Double, String, Char (a 16-bit number), Boolean.
Compound: List[Int], Set[Double], (Int, String), List[(BigInt, String)], List[List[Int]], Option[Int].

Square brackets, not angle. List[Int] and List[String] are unrelated types.
Int arithmetic, which is the JVM’s
(1 + 2) / 2 → 1 — Int division discards the fraction.
-7 / 2 → −3 — truncates towards zero, and -7 % 2 is −1.
2147483647 + 1 → −2147483648 — wraps, silently.
1 / 0 throws ArithmeticException; 1.0 / 0 is Infinity.
A literal too big for an Int is a compile error — only results wrap.
def
def fname(a1: T1, ..., an: Tn): R = { ... }
No return — the last expression is the value. Annotate the return type; it is the only place the compiler checks you meant what you wrote.

def average(xs: List[Int]): Int = xs.sum / xs.length has two bugs in one line: Int division, and division by zero on Nil. The honest type is Option[Int].
val, var, and lists
val binds once — reassignment does not compile. var is a box.

x :: xs allocates one cell whose tail is xs; xs is unchanged and its cells are shared. Constant time.
:: is right-associative, so 1 :: 2 :: 3 :: Nil reads from the right. Any operator ending in a colon is.
::: joins, and copies its left argument — so xs ::: List(y) in a loop is quadratic. Build with :: and reverse.
