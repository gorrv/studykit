Topic 01 · First Steps in C++

Objects You Can Hold

copies, references, const, and coming to C++ from Java

Most of this topic reads like Java with different punctuation, and most of it is. The part that is not is worth the whole week: in Java a variable is a handle to an object, and in C++ a variable can be the object. Coordinate b = a; compiles in both languages, means something different in each, and gives you no warning either way.

The smallest program, and how to run it

Hello, world
#include <iostream>

int main() {
  std::cout << "Hello, World!\n";
  return 0;
}
g++ -std=c++11 -o hello hello.cc then ./hello

main is not inside a class, returns an int exit code, and takes no String[] args. Returning 0 means success — and may be omitted from main alone, where the compiler supplies it.
There is no JVM
The compiler produces an executable — hello on Linux or macOS, hello.exe on Windows — which the operating system runs directly. Nothing interprets bytecode at runtime, which is where the performance argument comes from, and why C++ turns up in networking, finance, games, engine management, and robotics on low-power CPUs.

The flip side is that the binary is built for one platform. Java’s “compile once, run anywhere” and C++’s “compile for each target, run fast” are the same trade seen from two ends.
Functions, and why prototypes exist
int answer();          // a prototype: the signature, no body

int main() {
  printAnswer(answer());
}

int answer() { return 42; }   // the body, later
The compiler reads a file top to bottom and must know a function’s signature before it meets a call. Declaring the prototype first lets you define the body anywhere — which is what makes mutually recursive functions possible at all, and what header files are for.
Use std::vector, not arrays
#include <vector>
using std::vector;

vector<int> numbers(10);      // ten ints
numbers[i] = i;
numbers.resize(20);           // grows; arrays do not

vector<vector<int>> nums {
  {1, 2, 3},
  {4, 5, 6},
  {7, 8, 9}
};                            // rows need not be the same length
std::string is essentially a vector of characters, supports + to join and [] to index, and #include <fstream> gives ofstream writer("filename.txt"); which you then << into exactly like cout.
Two things Java did for you that C++ does not
No default initialisation. int x; as a local variable holds an indeterminate value. Reading it is undefined behaviour — which does not mean “an unpredictable number”, it means the standard places no constraint on what the program does at all. Do not run it, observe a value, and reason from that.

No bounds checking. There is no ArrayIndexOutOfBoundsException. Reading off the end of a vector is undefined behaviour and usually silent. v.at(10) does throw, and is worth the extra keystrokes while you are learning.

Objects, and the constructor that has to run

A class
class Coordinate {
protected:
  int x;
  int y;
public:
  Coordinate(int xIn, int yIn) : x(xIn), y(yIn) { }
};
class, not public class. Access specifiers head sections rather than each member, and everything before the first one is private. Note the semicolon after the closing brace — the commonest first-week compiler error.

: x(xIn), y(yIn) is the initialiser list, and it runs before the constructor body.
No new
Coordinate a(4, -3);
Coordinate b = a;
a and b are Coordinates. Not references to Coordinates — Coordinates, living in this function’s frame and destroyed when it returns. The second line runs the copy constructor, which the compiler writes for you if you do not, copying each member. So b is a second object, and changing one cannot affect the other.

This is the line to fix in your head. It is the same eleven characters as in Java and it does something else.

This will not compile
Coordinate a(4, 2);
Coordinate b;          // looks for Coordinate()
Coordinate b; asks for the default constructor — one taking no arguments — and this class has only Coordinate(int, int). Writing any constructor suppresses the free default one, which is exactly the point: an object that requires two coordinates should not be constructible without them.

The same requirement appears indirectly: vector<Coordinate> coords(2); default-constructs two elements, so it fails too. vector<Coordinate> coords; followed by coords.push_back(Coordinate(4, -2)); never needs one.
Why insisting on construction is worth something
A Java method taking a String can be handed null, and a.length() then throws at runtime. The C++ equivalent taking a string cannot: a string parameter is a string, empty at worst. References cannot be null either.

You can still produce null pointers in C++ if you go looking. The point is that a large amount of ordinary code has nowhere to put one, so an entire category of runtime failure stops being available.

Copies and references

The three ways to take a parameter
Coordinate inby value a copy is made; changes are lost on return
Coordinate & inby reference an alias for the caller’s object; changes stick
const Coordinate & inby const reference no copy, and no changes permitted — look but don’t touch

A reference is another name for something that already exists. It cannot be null, and it cannot be reseated to refer to something else later.
const is contagious
void printX(const Coordinate & in) {
  cout << in.getX() << endl;    // only compiles if getX is const
}

int getX() const { return x; }    // ...so mark it
Through a const reference you may only call methods that promise not to modify the object, and a method promises that by writing const after its parameter list. Add one const and you will find yourself adding several — which is the language telling you which of your methods are observers and which are mutators. Marking every observer const from the start is much less work than retrofitting it.
Returning a reference hands out the keys
Coordinate & getStart() { return start; }   // caller can modify start
const Coordinate & getStart() { return start; }  // caller can only read
With the first, j.getStart().setX(0) reaches inside the Journey and changes a member from outside the class. That defeats the point of the encapsulation: if Journey also cached a distance, it would now be wrong, and Journey would have no way to know.

Given const Coordinate & getStart(), of the four lines below the second is the one that fails:
Coordinate a = j.getStart(); — fine, it is a copy
Coordinate & b = j.getStart(); — refused, that would discard const
const Coordinate & c = j.getStart(); — fine
const Coordinate d = j.getStart(); — fine, a const copy

Const is one-way: you may always promise not to modify something modifiable, never the reverse.

Operators

The Java trap this fixes
new String("Dave") == new String("Dave") is false in Java — two objects, and == compares handles. In C++, string a = "Dave"; and string b = "Dave"; gives a == b as true, because string defines operator== to compare contents.

For your own class nothing compares anything until you say how. There is no inherited equals to fall back on and no default — a == b on two Coordinates is a compile error until somebody writes the operator.

Does a == b resolve, and does << chain?

Two questions with definite answers. Both predictions are checked against a real compiler in this module’s test suite.
operator<<, and the two-part solution
ostream & operator<<(ostream & o, const Coordinate & rhs) {
  o << rhs.getX() << "," << rhs.getY();
  return o;                    // without this, nothing can follow
}
cout << "It is at " << a << endl; is ((cout << "It is at ") << a) << endl, so each call has to hand back the stream for the next one. Return void and the final step becomes void << endl, which does not exist.

It cannot be a member of Coordinate, because the left operand is the stream. When the operator needs the class’s privates, the usual answer is a public write(ostream &) const on the class and a free operator that calls it: 
void write(ostream & o) const { o << x << "," << y; }

ostream & operator<<(ostream & o, const Coordinate & rhs) {
  rhs.write(o);
  return o;
}

Takeaways

What to be able to do without thinking
Say what a line makes. Given Coordinate b = a; versus Coordinate & b = a;, say how many objects exist and what happens to one when you change the other.

Choose a parameter form. Reading only and it is a class? Const reference. Modifying the caller’s object? Reference. Actually want your own copy? By value, and say so deliberately.

Write a constructor with an initialiser list, and know that members are built before the body runs.

Mark observers const. Then const references to your class are usable.

Write operator== and operator<< — the first as a member on the left type or a free function on both, the second as a free function returning ostream &.
Traps
  • Forgetting the semicolon after a class’s closing brace.
  • Expecting Coordinate b = a; to alias, as it would in Java.
  • Passing large objects by value without meaning to, then wondering why changes vanish.
  • Returning a non-const reference to a member and breaking your own invariants.
  • Forgetting const on getters, then finding const references unusable.
  • Writing operator== on the right-hand type and expecting a == b to find it.
  • Returning void from operator<<.
  • Reading an uninitialised int and treating what you saw as its value.
The one-sentence version
In Java a variable names a way to reach an object; in C++ a variable can be the object itself, so the language needs separate spellings for “another one like it” and “another name for it” — and almost everything else here follows from keeping those two apart.
