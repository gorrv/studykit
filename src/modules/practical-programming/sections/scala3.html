Programs That Meet Reality

default arguments, Try, regular expressions, Sets, and a crawler

Everything so far has been a function on values you supplied. This topic is the first one where the program talks to something outside itself — a page that might not load, text that might not be the shape you expected — and the tools are the ones that make failure a value rather than a crash.

Default arguments

A parameter that fills itself in
def collatzHelper(n: Int, a: Int = 0): Int = ...

collatzHelper(7, 3)   // n = 7, a = 3
collatzHelper(7)      // n = 7, a = 0
Useful for the accumulator a recursive function needs but a caller should not have to think about: the helper takes it, the first call does not have to pass it.

A default lets you leave off the end of the argument list. To skip something in the middle you have to give the later ones by name — collatzHelper(a = 3) — and once a name is used, everything after it must be named too, because position no longer means anything. Named arguments can also be reordered freely.

When it might fail

Try, and a value to fall back on
def get_page(url: String): String = {
  Try(fromURL(url)("ISO-8859-1").take(10000).mkString)
    .getOrElse { println(s"Problem with: $url"); "" }
}
Try(...) runs the expression and catches whatever it throws, giving back Success(value) or Failure(exception). Like Option, it turns a crash into a value — and keeps the exception, which Option would have thrown away.

getOrElse then supplies a default. The signature says String, and it means it: a page that will not load comes back as the empty string and the crawl carries on.

take(10000) is not politeness. Without it, one enormous page stops the whole program.
s"..." — string interpolation
The s before the quotes lets $name and ${expr} stand for values inside a string: s"Visiting: $n $url". Without the s it is just those characters.

Regular expressions

Writing one
val http_pattern = """"https?://[^"]*"""".r

val email_pattern =
  """([a-z\d\.-]+)@([\da-z\.-]+)\.([a-z\.]{2,6})""".r
"""…""" is a raw string: no escape processing, so a backslash is a backslash and you write the pattern as the regex engine wants to see it. .r turns the string into a Regex.

The four brackets at each end of the first one are not a typo — three open the raw string and the fourth is a quote character that is part of the pattern. It matches the quotes around a URL in the HTML, which is why the matches include them.
Using one
def unquote(s: String) = s.drop(1).dropRight(1)

def get_all_URLs(page: String): Set[String] =
  http_pattern.findAllIn(page).map(unquote).toSet
findAllIn gives every match, map(unquote) strips the quotes the pattern deliberately included, and toSet throws away the duplicates — a page that links to the same place twice should not be crawled twice.

A Set has no order and no repeats. That is the right shape here and worth choosing deliberately: the alternative is remembering to de-duplicate later, which is the kind of thing nobody remembers.
What this pattern does when it cannot cope
It does not fail. Nothing anchors either end of it, so when the address is not the shape it expects, it matches part of one instead: 
Ada@example.com          →  da@example.com
ada@example.technology   →  ada@example.techno
ada@example.museum       →  ada@example.museum
ADA@EXAMPLE.COM          →  no match at all
The first two are worse than a miss. A harvester using this pattern collects addresses that look plausible and do not exist, and nothing anywhere reports a problem.

A regex is a cheap approximation of a shape. The useful question is never "is it correct" but "what does it do to the cases it was not written for" — and unanchored patterns answer that with a confident wrong answer. Try the awkward page in the tool.

The crawler

Twelve lines, and it works
def crawl(url: String, n: Int): Unit = {
  if (n == 0) ()
  else {
    println(s"Visiting: $n $url")
    val page = get_page(url)
    for (u <- get_all_URLs(page))
      crawl(u, n - 1)
  }
}
The recursion is the whole design. n counts down to zero, which is the base case; each page's links are crawled one level shallower. There is no queue, no loop and no visited set — the call stack is doing the bookkeeping.

() is the value of type Unit, and the return type says this function is run for its effect rather than its answer.
What it does not do
It does not remember where it has been. A page reachable by two routes is fetched twice; a pair of pages that link to each other is fetched over and over until the counter runs out. Only the depth limit stops it, and it stops it by giving up rather than by being finished.

On a real site that is somebody else's bandwidth, and it is the difference between a crawler and a nuisance. The fix is a set of visited URLs — which is the same Set that was already being used for the links.

Depth, repeats and cycles

A small web of six pages, one of which links back. Turn the visited set on and watch the fetch count stop growing.
The harvester is the same shape, with an answer
def emails(url: String, n: Int): Set[String] = {
  if (n == 0) Set()
  else {
    val page = get_page(url)
    val new_emails = email_pattern.findAllIn(page).toSet
    new_emails ++ (for (u <- get_all_URLs(page))
                     yield emails(u, n - 1)).flatten
  }
}
Same recursion, but returning Set[String] instead of Unit. The base case is the empty set rather than (), and the results are combined with ++ on the way back out.

The flatten is doing real work: the for-comprehension yields one Set[String] per link, so the whole thing is a Set[Set[String]] until it is flattened. Forgetting it is a type error, which is the good kind of mistake.

Takeaways

If you remember five things
  1. A default fills in the end of an argument list. To skip earlier ones, use names — and after the first name, everything must be named.
  2. Try(...).getOrElse(d) turns a thrown exception into a value, so one unreachable page does not stop the program.
  3. """…""" is a raw string, and .r makes it a regex. findAllIn gives every match.
  4. Set has no order and no duplicates — the right shape for "the links on this page".
  5. Recursion with a countdown is the crawl. The depth limit bounds it; only a visited set stops it repeating itself.
Things that catch people out
  • Expecting a default to let you skip an argument in the middle.
  • Forgetting the s on an interpolated string, and printing $url.
  • Writing a regex in an ordinary string, where \d needs escaping twice.
  • Trusting a regex to be a correct definition of an email address.
  • Crawling without a visited set, and hammering one server.
  • Forgetting flatten, and ending up with a set of sets.
