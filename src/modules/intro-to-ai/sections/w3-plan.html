Topic 03 · Part 1 · Automated planning

Classical Planning

describing a world well enough that a general solver can act in it

What AI planning is

Definition

Given:

  • An initial state I
  • A goal state G
  • A set of actions A, each with preconditions and effects

Find:

  • A plan — a sequence of actions that bring the system from I to G.
  • More interesting: an optimal plan — the best way to reach the goal state.
Where it sits in the module
  • Problem modelling — graph search, heuristic search, adversarial search
  • Constraint satisfaction problems
  • Automated planning — in general, planning is more powerful than CSP (CSPs can be modelled as planning problems)
How this differs from everything so far
In Topic 01 you were handed a graph. In Topic 02's CSPs you were handed variables and constraints. Here you are handed nothing but a description in a language, and the state space is generated from it — the graph is implicit and astronomically large.

That's what "more powerful than CSP" means: a CSP has a fixed set of variables to fill in, whereas a planning problem has an unbounded sequence of actions to choose, and the same fact can be made true, destroyed and made true again.

The logistics domain

The running example
Cargos, trucks and locations. Initial state: cargos scattered across locations. Goal: all cargos at a destination point. Constraints in the real version include fuel, truck capacity, number of drivers…
Problem modelling — what we must define
  • The objects involved in the problem.
  • The relations between the objects.
  • The set of possible actions, with preconditions and effects.

And so: we need a formalism (a language) to describe objects, relations and actions.

Objects and relations

Objects

  • The cargos c1 … cn
  • The trucks t1 … tm
  • The locations l1 … lk

Relations

  • Pairs of locations can be connected: connected(li, lj)
  • Each truck is in a location: at(ti, lj)
  • Each cargo can be in a location: at(ci, lj)
  • Each cargo can be on a truck: on(ci, tj)
Note what a "relation" really is
These are predicates over objects, and a state is nothing more than the set of them that currently hold. at is used for both trucks and cargos — the same predicate, different object types — which is exactly the generality that lets one action definition cover every truck and every cargo at once.

From general description to specific problem

Initial state, goal state, and the closed-world assumption
  • Initial state — we have to list all the objects of our problem and all the true relations among the objects.
  • Closed-world assumption: what is not listed is assumed to be false.
  • Goal state — we have to list all the relations we want to be true.
The worked instance — 2 trucks, 3 cargos, 8 locations
at(c1,l3)   at(c2,l4)   at(c3,l8)
at(t1,l1)   at(t2,l5)
connected(l1,l2)  connected(l2,l3)  connected(l3,l4)  connected(l3,l8)
connected(l4,l7)  connected(l5,l6)  connected(l6,l7)  connected(l7,l8)

From the closed-world assumption it follows that, for example: l1 and l6 are not connected, truck t1 is not at location l8, all trucks are empty, and so on.

Goal state: all cargos in location l6.

Why the closed-world assumption matters so much
Without it you would have to write down every false fact too — with 8 locations and 2 trucks that's already dozens of negative statements, and it grows quadratically. CWA lets the initial state be a short list of positives.

The price: the model must be complete. If you forget to state connected(l2,l3), the planner doesn't ask — it silently concludes the road doesn't exist and returns a worse plan, or none. Most "the planner gave a stupid answer" bugs are a missing fact in the initial state.

The actions

Informally
A truck can move from one location to another · a cargo can be loaded into a truck · a cargo can be unloaded from a truck.
More formally — for each action we define three things
  • The parameters — which objects are involved?
  • The preconditions — what needs to be true for the action to be applied?
  • The effects — how does the state change after execution?

The two sentences to memorise
  • Preconditions are described through a set of relations that must be true in a state for the action to be applicable.
  • Effects are described by adding or deleting relations.
Read the delete effects carefully — they are where the meaning lives
Load adds on(c,t) and deletes at(c,l). Without the delete, the cargo would be on the truck and still lying at the location — the model would let you load one crate onto every truck in the country. The delete list is what stops the world from accumulating contradictions.

Also note Move has no connected(to, from): roads are directed unless you list both ways. And Load and Unload are exact mirrors — one action's add list is the other's delete list, which is what makes the two undo each other.

A plan

Truck1: l1, l2, l3, load(c1), l4, load(c2), l7, l6, unload(c1), unload(c2)
Truck2: l5, l6, l7, l8, load(c3), l7, l6, unload(c3)

Note that t1 and t2 can move in parallel.

And then the scaling question
What if we have 75 locations, 40 cargos, 12 trucks + aeroplanes (or more)?

You are not going to write that plan by hand. We need a planner.

The parallelism remark is a hint about Part 3
Classical planning produces a sequence, so it must arbitrarily interleave the two trucks even though nothing forces an order. Recovering the fact that independent actions can overlap is what durative actions and temporal planning are for.

Exam-style takeaways

Key things to nail for Part 1
  1. Given I, G and A (each action with preconditions and effects); find a plan — a sequence of actions taking the system from I to G. Optimal = the best such sequence.
  2. Planning is more powerful than CSP — CSPs can be modelled as planning problems.
  3. To model a domain you define objects, relations between them, and actions with preconditions and effects — and you need a language to write it in.
  4. An action has three parts: parameters (which objects), preconditions (what must be true), effects (how the state changes).
  5. Preconditions are relations that must hold; effects add or delete relations.
  6. Be able to fill in the Move / Load / Unload table from memory, delete effects included.
  7. Closed-world assumption — the initial state lists all objects and all true relations; anything not listed is assumed false.
  8. Domain vs problem — the domain formalises the space of all possible problems (relations and actions); a problem instance adds the initial state and the goal.
