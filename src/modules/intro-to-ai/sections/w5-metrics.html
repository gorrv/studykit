Topic 05 · Part 2 · Introduction to Machine Learning

Is My Algorithm Any Good?

measurement instead of proof

Training and test sets

Definitions — supervised learning vocabulary
  • Training set — the portion of the data used for the learning. We give our program both data and labels for a portion of the data.
  • Test set — the untouched portion of data used to evaluate our model after it is trained. We 'hide' the test labels from the algorithm in that phase.
The word doing the work is "untouched"
Measuring a model on the data it was trained on tells you nothing — a model that simply memorises every training example would score perfectly and be useless. The test set is a stand-in for data the model will meet in the real world, and it only works as a stand-in for as long as the model has never seen it.

Hold on to that word. In Part 3 a third split appears — the validation set — for exactly this reason, and "untouched" is why.

Accuracy, and its trap

Definition
Given a classification algorithm and a test set, the accuracy is the proportion of correct predictions done by the algorithm over all predictions in the test set.
The slide's question: "an algorithm has 99% accuracy. Is it good?"
Well, it depends.

Example. An algorithm takes an X-ray image of a person's lungs and predicts a rare disease D. Assume 1% of the population has disease D.

A very simple algorithm achieves 99% accuracy. Which one?

One that says "no" to every single input.

Work the numbers — take 10,000 patients
100 have the disease, 9,900 don't. The always-"no" model:
  • gets all 9,900 healthy people right,
  • gets all 100 sick people wrong,
  • accuracy = 9,900 / 10,000 = 99%.

It is 99% accurate and catches zero cases of the disease. This is called the class imbalance problem, and the general lesson is: accuracy is only meaningful relative to the base rate. On a problem where 99% of answers are "no", 99% accuracy is what you get for doing nothing at all.

Precision, sensitivity, F1

This example suggests accuracy alone may not be a sufficient metric
  • Precision — proportion of true positives over true positives and false positives.
    precision = TP / (TP + FP)
  • Sensitivity (or recall) — proportion of true positives over true positives and false negatives.
    recall = TP / (TP + FN)
  • F1 score — harmonic mean between sensitivity and precision.
    F1 = 2 / (recall−1 + precision−1)  =  2·P·R / (P + R)

The four boxes everything is built from — the confusion matrix:

Actually
positivenegative
predicted positiveTPtrue positiveFPfalse positive
predicted negativeFNfalse negativeTNtrue negative
How to remember which is which, and never mix them up
Both fractions have TP on top. Only the denominator differs, and each denominator is a column or a row of the matrix:
  • Precision = TP / (TP + FP) — the predicted-positive row. "Of everything I flagged, how much was real?" It punishes false alarms.
  • Recall = TP / (TP + FN) — the actually-positive column. "Of everything that was real, how much did I catch?" It punishes misses.

Note that neither uses TN. That is the whole point: in the rare-disease problem TN is the enormous number that lets accuracy hide the failure, and precision and recall simply refuse to look at it.

Why the harmonic mean, and not the ordinary average?
Because the harmonic mean is dragged down by the smaller number, so you cannot score well by being brilliant at one and hopeless at the other.

Take precision = 1.0 and recall = 0.02:

  • ordinary mean = (1.0 + 0.02) / 2 = 0.51 — looks respectable;
  • F1 = 2(1.0)(0.02) / (1.02) = 0.039 — correctly awful.

F1 is high only when both are high. Every classifier can trade one for the other (flag everything → recall 1, precision terrible; flag only the single most certain case → precision 1, recall terrible), so a single number that resists that trade is what you want.

The slide's question, worked

"Which of precision or sensitivity would have highlighted the weakness of the previous algorithm? Assume 0.01% of true positives."
Sensitivity (recall).
Why — on 10,000 patients with the always-"no" model

The model never predicts positive, so TP = 0 and FP = 0, and all 100 sick patients are missed: FN = 100, TN = 9,900.

  • Accuracy = (0 + 9900) / 10000 = 0.99 — hides everything.
  • Recall = 0 / (0 + 100) = 0 — exposes it immediately.
  • Precision = 0 / (0 + 0) = 0/0, undefined — it cannot even be computed, so it tells you nothing.

That is what the slide's "assume 0.01% of true positives" is for. Let the model be very slightly less useless, so it flags a handful of cases and gets them right: now FP = 0 still, so precision = 1.0 — a perfect score — while recall stays near 0.

Precision would have looked perfect. Recall is the one that exposes the weakness.

The general rule this illustrates
Recall is the metric that catches "does nothing" models. Whenever the cost of a miss is much worse than the cost of a false alarm — disease screening, fraud detection, safety systems — recall is the metric to lead with.

Flip it and precision leads: for spam filtering, a missed spam is a mild annoyance but a real email in the junk folder is a disaster, so false positives are what hurt.

The deck's closing note on balanced test sets
"What about a balanced test set, in which classes have equal number of samples? Accuracy not terrible, F1 score still interesting."

Balance the classes 50/50 and the always-"no" trick collapses — it now scores 50%, not 99% — so accuracy becomes informative again. But F1 is still worth reporting, because accuracy still treats a miss and a false alarm as equally bad, and in most real problems they are not.

Metrics for regression problems

The three definitions
Assume our regression predicts real numbers. Call the predictions ŷ₁ … ŷₙ and the true values y₁ … yₙ. Then:
MetricFormula
MAE
Mean Absolute Error		 (1/n) Σi=1n |ŷi − yi|
MSE
Mean Squared Error		 (1/n) Σi=1n (ŷi − yi)²
RMSE
Root-Mean-Squared Error		 √[ (1/n) Σi=1n (ŷi − yi)² ]
Why three of them, when they measure the same thing
  • MAE treats every unit of error equally. Being wrong by 10 is exactly ten times as bad as being wrong by 1.
  • MSE squares first, so being wrong by 10 is a hundred times as bad as being wrong by 1. It is dominated by the worst predictions, which makes it very sensitive to outliers.
  • RMSE is MSE's square root, purely so the number is back in the original units. If you're predicting prices in pounds, MSE is in pounds-squared and means nothing to a human; RMSE is in pounds.

Useful fact: RMSE ≥ MAE always, with equality only when every error has the same magnitude. The gap between them tells you how uneven your errors are.

Exam-style takeaways

Key things to nail for Part 2
  1. Training set = the portion used for learning, data and labels. Test set = the untouched portion used to evaluate after training, with the labels hidden.
  2. Accuracy = proportion of correct predictions over all predictions in the test set.
  3. Be able to tell the 99% story — with 1% prevalence, an algorithm that always says "no" scores 99% accuracy and catches nothing.
  4. Precision = TP / (TP + FP) — of what I flagged, how much was real. Punishes false alarms.
  5. Sensitivity / recall = TP / (TP + FN) — of what was real, how much I caught. Punishes misses.
  6. F1 = 2 / (recall−1 + precision−1), the harmonic mean — high only when both are high.
  7. Recall is the metric that exposes the always-"no" model; precision would report 1.00 or be undefined. This is the slide's question.
  8. Neither precision nor recall uses TN — which is exactly why they survive class imbalance.
  9. On a balanced test set accuracy is "not terrible", but F1 is still interesting.
  10. MAE, MSE, RMSE — write all three formulas. MSE punishes large errors quadratically; RMSE restores the original units; RMSE ≥ MAE.
