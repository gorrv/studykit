CSPs: Introduction

when only the answer matters, not how you got there

It's not the journey, it's the goal

The shift
Typically when you think of search you think of path planning — you know the goal and want to find out how to get there.

But in some problems we only care about finding a goal state: fill in all the values in a way that is valid.

  • Respect rules of where items/values can be placed.
  • Respect validity relationships.
  • All that matters is that we satisfy those rules and constraints — not in which order you filled in the puzzle.
Why this changes the algorithm
In Topic 01 the path was the answer, so cost and ordering mattered. In a Sudoku or a colouring, the sequence you wrote the values in is irrelevant — nobody grades your filling-in order. That single observation is worth an exponential factor, and it's cashed in later under the word commutativity.
Why plain search wastes effort here
You can use an informed search on the map-colouring problem. But it is largely wasteful: there are lots of invalid states, and ordinary state-space search happily generates and stores them because it only checks whether a state is the goal, never whether it is valid.

What a CSP is

Definition — three components
  • A finite set of variables X {x₁ … xₙ} — defines all elements that need to be given a value in the problem.
  • A set of domains D {D₁ … Dᵢ} — defines what possible values can be assigned to each variable, {v₁ … vⱼ}.
  • A set of constraints C {C₁ … C_k} — the rules that dictate a relation between variables in X. Each constraint Cᵢ is a pairing of scope and relation.

A CSP solution is an instantiation of all variables in X using values in D that satisfies all constraints in C.

CSP solvers search through incomplete but consistent solutions (partial assignments).

"Scope and relation", and "incomplete but consistent"
A constraint has a scope (which variables it talks about — e.g. ⟨SA, WA⟩) and a relation (which combinations are allowed — e.g. all pairs where the two differ). Separating them is what lets a solver reason about a constraint without knowing what problem it came from.

"Incomplete but consistent" is the search space: partial assignments that break no constraint so far. Not every one leads to a solution, but every one is worth extending — and anything inconsistent is thrown away immediately rather than expanded.

Map colouring

The problem
Map of Australia. Colour each region {red, green, blue} so that no neighbouring regions are the same colour.
As a CSP — memorise this instantiation

X = {WA, NT, Q, NSW, V, SA, T}

D = {{red, green, blue}, {red, green, blue}, …} — one copy per variable

C = {SA≠WA, SA≠NT, SA≠Q, SA≠NSW, SA≠V, WA≠NT, NT≠Q, Q≠NSW, NSW≠V}

Two details people lose marks on
T (Tasmania) appears in X but in no constraint — it's an island, so it neighbours nothing. It still needs a value; it just can never fail. And SA appears in five of the nine constraints, because South Australia touches everything. That asymmetry is exactly what the variable-ordering heuristics in Part 4 detect.

The constraint graph

A CSP with binary constraints draws as a graph: nodes are variables, edges are constraints.

SA (degree 5) is the hub; T is isolated. Nine edges, matching the nine constraints.
Read the heuristics straight off the picture
Degree = how many constraints a variable is in. SA has degree 5, T has degree 0. "Most constraining variable" in Part 4 literally means "pick the highest-degree node" — so the graph is not decoration, it's the data structure the heuristics run on.

n-Queens as a CSP

The formulation from the lectures
  • X = {xij} — one variable per square of the board.
  • D = {0, 1} — empty or queen.
  • C =
    Σi,j Xij = N
    (Xij, Xik) ∈ {(0,0), (0,1), (1,0)}
    (Xij, Xkj) ∈ {(0,0), (0,1), (1,0)}
    (Xij, Xi+k, j+k) ∈ {(0,0), (0,1), (1,0)}
    (Xij, Xi+k, j−k) ∈ {(0,0), (0,1), (1,0)}
Decoding those constraints
The set {(0,0), (0,1), (1,0)} is just "not both 1" written out as an explicit relation — the missing pair is (1,1). Applied to:
  • Xij, Xik — same row i, two columns → no two queens share a row;
  • Xij, Xkj — same column j → no two share a column;
  • Xi+k, j+k and Xi+k, j−k — the two diagonals.

And Σ Xij = N forces exactly N queens on the board — without it, all-zeros would satisfy everything.

This is a deliberately clumsy modelling
One variable per square means n² variables and a global sum constraint. A tighter model uses one variable per column with domain {1…n} = the row its queen sits in, which makes "no two in a column" free and reduces the problem to row and diagonal constraints. The lectures use the square version because it shows off scope and relation explicitly — but if a question asks you to "model n-Queens efficiently", the column version is the better answer.

Exam-style takeaways

Key things to nail for Part 3
  1. The shift — some problems care only about reaching a valid goal state, not about the path or the order of assignment.
  2. Ordinary search is wasteful here — it generates lots of invalid states because it tests for goal, not validity.
  3. The three components — variables X, domains D, constraints C. Each constraint is a pairing of scope and relation.
  4. A solution is an instantiation of all variables in X using values in D satisfying all constraints in C.
  5. Solvers search incomplete but consistent partial assignments.
  6. The Australia CSP verbatim — X = {WA, NT, Q, NSW, V, SA, T}; D = {red, green, blue} each; C = {SA≠WA, SA≠NT, SA≠Q, SA≠NSW, SA≠V, WA≠NT, NT≠Q, Q≠NSW, NSW≠V} — nine constraints.
  7. The constraint graph — nodes are variables, edges are constraints; SA has degree 5, T degree 0.
  8. n-Queens — X = {xij}, D = {0, 1}, and the constraints: Σ Xij = N plus "not both 1" on rows, columns and both diagonals.
  9. Be able to formulate an unseen problem as a CSP — this is the standard exam question. Name the variables, give each a domain, then list the constraints.
