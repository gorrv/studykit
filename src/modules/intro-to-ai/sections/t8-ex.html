Exercise 1

Using the example given before with A and B, what is q⋆(A) and q⋆(B)?

The suggested set-up was A ∼ N(10, 1) and B ∼ N(11, 4). By Definition 8.2, q⋆(a) = E[Rt | At = a] — the expected value of the reward distribution, and the expected value of N(µ, σ²) is µ.

answer q⋆(A) = 10 and q⋆(B) = 11. The optimal action is B.
The three things this one-line question is checking
  • q⋆ is the mean, not the maximum and not any observed reward. B can and will pay less than A on plenty of individual pulls.
  • The variance is irrelevant to q⋆. B's σ² = 4 makes it noisier, not better or worse. It affects how hard B is to identify, not what it is worth.
  • This is exactly the number the agent never sees. You can answer it only because you were handed the distributions; an agent playing Example 8.1 has to approach 10 and 11 through Qt.

Exercise 3

For each of the two strategies, discuss whether they could be considered doing too much exploration or exploitation, and why. (a) A greedy algorithm — the next action is determined by the highest average reward given so far. (b) A random algorithm — it just picks the next action at random.

answer Greedy does far too much exploitation; random does far too much exploration. Neither uses the other mode at all.

(a) The greedy algorithm — pure exploitation.

  • It acts on its current estimates and nothing else. Every step is spent on the arm that currently looks best.
  • The failure mode is the one the notes name in §8.5: it gets ‘stuck’ in any action with a positive value and misses ones possibly much better. With Q₁(a) = 0 and positive rewards, an arm that pays well once may be the only arm ever tried.
  • A single lucky sample is never corrected, because correcting it would require sampling a rival — which greedy will not do. Equally, a single unlucky sample of the truly best arm is fatal: it will never get a second chance.
  • Its one saving grace: ties are randomised, so at t = 1 it does pick uniformly. After that it can narrow to one arm forever.

(b) The random algorithm — pure exploration.

  • It gathers information beautifully — every arm is sampled 1/k of the time, so all its estimates converge to the true q⋆.
  • And then it throws that information away. Nothing it learns ever changes what it does. It is not really a learning algorithm at all.
  • Its expected reward per step is the average over all arms, forever — 0 on the N(0, 1) testbed of Figure 8.4, which is why the random curve is flat at zero.
The point the exercise is setting up
Both are extreme, and in opposite directions — which is what makes them the two endpoints of a single dial. “A balance between greedy and random could be a possible way forward”, and ε-greedy is exactly that dial: a weighted coin between (a) and (b), with ε as the weight.

If a question asks you to argue rather than classify, the strongest line is about information: greedy never buys any, random never spends any, and the useful algorithms do both.

Exercise 4

Consider a 50-armed bandit problem. What is the probability, at each time t, that a random method selects the optimal action?

By Definition 8.4 the random method takes each action with probability 1/k, independently of everything that has happened. There is exactly one optimal action — the notes justify uniqueness in §8.4: the probability of drawing two exactly equal values from a normal distribution is null. With k = 50:

Pr(At = optimal) = 1/50 = 0.02
answer 1/50 = 0.02 = 2%, at every t, forever — it never improves.
The follow-up worth pre-empting
“At each time t” is doing real work in the question. The answer is constant in t, which is the whole indictment of the random method: after a million steps it is still 2%. Contrast ε-greedy, whose probability of the optimal action rises towards its ceiling of 1 − ε + ε/k as the estimates converge.

For k = 50 and ε = 0.1 that ceiling is 0.9 + 0.002 = 90.2%. Same problem, forty-five times better, from one weighted coin.

Exercise 5

A 2-armed bandit at t = 10, with q⋆(a₁) = 2 and q⋆(a₂) = 2.3. Using ε-greedy with ε = 0.5, what is the probability that the optimal action is selected at step t = 10, when (i) Q₁₀(a₁) = 2.4, Q₁₀(a₂) = 2.1; (ii) Q₁₀(a₁) = 2.1, Q₁₀(a₂) = 2.4; (iii) Q₁₀(a₁) = 2.4, Q₁₀(a₂) = 2.4?

First: the optimal action is a₂, because q⋆(a₂) = 2.3 > 2 = q⋆(a₁). The q⋆ values are used only for that — the agent's choice depends on the Q's alone. With k = 2 and ε = 0.5, the random branch gives each arm ε/k = 0.25.

Pr(a₂) = ε·(1/k)  +  (1 − ε)·Pr(greedy picks a₂) = 0.25 + 0.5·Pr(greedy picks a₂)
caseQ₁₀(a₁), Q₁₀(a₂)greedy takesPr(greedy → a₂)Pr(optimal a₂)
(i)2.4, 2.1a₁00.25 + 0.5·0 = 0.25
(ii)2.1, 2.4a₂10.25 + 0.5·1 = 0.75
(iii)2.4, 2.4tie → randomise½0.25 + 0.5·0.5 = 0.5
answer (i) 0.25  ·  (ii) 0.75  ·  (iii) 0.5
Three ways to lose the marks here
  • Answering 0 for case (i). Even when greedy points the wrong way, the random branch still reaches a₂ with probability ε/k = 0.25. The greedy branch is not the only route.
  • Answering 1 − ε = 0.5 for case (ii). The greedy action also collects its share of the random branch: 0.5 + 0.25 = 0.75.
  • Forgetting the tie rule in case (iii). Definition 8.5 randomises among the maxima, so the greedy branch itself is a coin flip. Answering 0.75 (treating a₂ as “the” greedy choice) or 0.25 (treating a₁ as it) both miss it.

Sanity check on the whole answer set: the three cases are 0.25 < 0.5 < 0.75, in the order estimates point away → estimates tie → estimates point at it. The middle case must sit exactly halfway, and it does.

Exercise 6

Both random and greedy methods are particular cases of the ε-greedy method. What should you set ε to in order to obtain, respectively, the greedy and random methods?

answer ε = 0 gives the greedy method. ε = 1 gives the random method.

Straight from Definition 8.6, which says: with probability ε act randomly, with probability 1 − ε act greedily.

  • ε = 0 — the random branch fires with probability 0, so every step is arg maxa Qt(a). That is Definition 8.5 exactly, ties and all.
  • ε = 1 — the greedy branch fires with probability 0, so every step is uniform over the k arms. That is Definition 8.4 exactly.
Why the question is asked at all
It fixes the shape of ε as a dial between two named extremes, not a free parameter with arbitrary meaning. Every claim in §8.5 then reads as a statement about position on that dial — and it is worth noticing that Figure 8.4 plots both endpoints and two interior points of the same one-parameter family.

A likely follow-up: does some ε strictly dominate? No. Larger ε learns faster but pays more forever; smaller ε learns slower but pays less. The best ε depends on how long you intend to play — which is precisely why §8.5 is careful to say ε = 0.1 wins at 500 steps while ε = 0.01 wins in the long run.

Exercise 7

Assume the ε = 0.1 line in Figure 8.4 is close to stabilising, and will stabilise before an average reward of 2. If we add the line for ε = 0.75, at 500 steps do you expect its average reward to be: (1) lower than random, (2) between random and greedy, (3) between greedy and ε = 0.01, (4) between ε = 0.01 and ε = 0.1, or (5) higher than ε = 0.1?

answer (2) — between random and greedy.

The argument. Once the estimates have roughly converged, an ε-greedy agent spends a fraction (1 − ε) of its steps on the best arm and a fraction ε on a uniformly random arm, so its average reward is about

(1 − ε)·q⋆(best)  +  ε·(mean arm value)

On this testbed the arm values come from N(0, 1), so the mean arm is worth 0 and the second term vanishes. The reward is therefore roughly proportional to (1 − ε):

ε≈ (1 − ε) × q⋆(best)simulated at 500 steps
1 (random)0≈ 0.00
0.750.25 × 1.54 ≈ 0.39≈ 0.38
0 (greedy)— stalls early, does not reach q⋆(best)≈ 1.04
0.010.99 × 1.54 ≈ 1.52 eventually≈ 1.22
0.10.90 × 1.54 ≈ 1.39≈ 1.36

So ε = 0.75 lands near 0.39 — clearly above random's 0, and clearly below greedy's ≈ 1.0. Option 2. Turn ε = 0.75 on in the testbed tool and the curve appears exactly there.

Where the 1.54 comes from, if you want the number rather than the shape
It is the expected maximum of 10 independent standard normals ≈ 1.54 — the value of the best arm on an average testbed. You are not expected to know it; the hint in the question (“ε = 0.1 stabilises before 2”) exists so you can work backwards: if ε = 0.1 stabilises at 0.9·q⋆(best) and that is under 2, then q⋆(best) is a bit over 1.5, and 0.25 of it is around 0.4.

The qualitative argument alone earns the answer: ε = 0.75 spends three quarters of its steps choosing uniformly at random — which is worth 0 — so it cannot do much better than a quarter of the best arm's value, and that is well below what even greedy manages. The only genuinely tempting wrong answer is (1), on the thought that "more randomness is worse than random"; but ε = 0.75 still exploits a quarter of the time, so it must strictly beat pure random.

What the trace is actually demonstrating
  • The first three steps are forced. Every arm has N = 0 and therefore +∞, so a₁, a₂, a₃ come out in index order. This is always how a UCB trace starts, for any rewards.
  • a₃ is picked twice in a row and then dropped. Its 6 at t = 3 made it the leader; the 0 at t = 4 halved its average to 3 and it is never seen again in these eight steps. UCB reacts fast to a bad sample because the estimate moves and the interval shrinks at the same time.
  • a₁ is exploited three times running (t = 5, 6, 7) — UCB is not obliged to alternate. It only moves on when the exploitation term stops covering the shrinking exploration term.
  • A₈ = a₂ is the whole point of the chapter. At t = 8, a₂ has the worst estimate of the three (Q = 3.5 against a₁'s 4.75) but it has been pulled once, so its interval is by far the widest — 2√(2.0794/1) = 2.884 against a₁'s 1.442. It wins on uncertainty, not on merit. That is Figure 8.5, arrived at by arithmetic.
  • And it was right. a₂'s second reward is 7, lifting Q(a₂) to 5.25 — the best of the three. An ε-greedy agent would have reached that only by luck; a purely greedy one, never.
Three arithmetic slips that derail the whole table
  • Using log₁₀ instead of ln. ln 8 = 2.0794, log₁₀ 8 = 0.9031. Everything downstream changes.
  • Counting the current pull in Nt. N is pulls prior to t. At t = 8, a₁ has been pulled 4 times (t = 1, 5, 6, 7), not 5.
  • Putting c inside the square root. It is c·√(ln t / N), not √(c·ln t / N). With c = 2 that is a factor of √2 wrong on every exploration term.

Keep a running (N, Q) pair per arm in the margin and update it after each pick — that alone prevents all three.
