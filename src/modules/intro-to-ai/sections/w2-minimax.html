Adversarial Search: Minimax

searching when someone is trying to stop you

A second agent changes everything

The setup
How do you solve a search problem when there is a second agent? They have their own goals, and they may:
  • act to help us — a cooperative agent;
  • act to hinder us — an adversarial agent.

This lecture takes the second case: two-player games.

The rules of the abstraction
  • Two players: MAX and MIN.
  • MAX moves first, then they take turns until the game is over.
  • At the end, points are awarded to the winner and penalties given to the loser.
Why the names
The whole game is scored on one number, from MAX's point of view. MAX wants it large, MIN wants it small — so MIN's goal is not "win" in some separate sense, it's "make MAX's number as small as possible". That single shared scale is what makes the algorithm work; you never need two sets of values.

Compare Topic 01: there the world was indifferent, so a plan you found stayed valid. Here every second move is chosen by someone who wants your plan to fail, so you must plan for the worst reply, not the convenient one.

Game trees

Definition
A game tree is a tree where nodes are game states and edges are moves. Three types of node:
  • Max nodes — options for the Max-Player
  • Min nodes — options for the Min-Player
  • Terminal nodes — final outcomes
Structure
  • The root is either MAX or MIN.
  • Children of MAX nodes are MIN nodes or Terminal nodes.
  • Children of MIN nodes are MAX nodes or Terminal nodes.
  • Terminal nodes, and only them, have no children.

Evaluation function: values or payoffs associated with terminal nodes.

The layers alternate because the turns alternate
There is nothing deep about "MAX layer, MIN layer, MAX layer" — it's just whose turn it is at that depth. Depth 0 is MAX's move, depth 1 is MIN's reply, depth 2 is MAX again. The only place a number enters the tree from outside is at the terminals; every other value is computed from below.

Read the jump
Tic-Tac-Toe is fully solvable by brute force — 765 states is nothing. Chess is 1037 times bigger; Go is beyond absurd. The rest of this topic exists because you cannot look at the whole tree. Minimax is the correct-but-impossible algorithm; alpha-beta is the first thing you do about it.

The minimax value

Definition
The optimal strategy can be found from the minimax value of each node.

MINIMAX(n) = the utility for MAX of being in the corresponding state, assuming that both players play optimally.

  • MAX prefers to move to a state of maximum value.
  • MIN prefers to move to a state of minimum value.
The three words that carry the definition
"utility for MAX" — one scale, MAX's. "assuming both play optimally" — this is a worst-case guarantee, not a prediction; if MIN blunders, MAX does at least as well, never worse. And the value is computed bottom-up: a terminal's value is given, an internal node's value is the max or min of its children.
The recipe
  1. Terminal node → its payoff.
  2. MIN node → the smallest of its children's values.
  3. MAX node → the largest of its children's values.
  4. The move to play at the root is the edge leading to the child whose value equals the root's.

The worked example

The tree from the lectures: root A is a MAX node with moves a₁, a₂, a₃ to MIN nodes B, C, D, each with three terminal children.

B = min(3, 12, 8) = 3 · C = min(2, 4, 6) = 2 · D = min(14, 5, 2) = 2 · A = max(3, 2, 2) = 3, so MAX plays a₁.
Notice the 12 and the 14
B contains a 12 and D contains a 14 — the two juiciest numbers in the tree — and neither has any effect on the answer. MIN will never hand them over. Only the worst child of each MIN node matters, which is exactly the fact alpha-beta exploits in Part 2.

The line the lecture flags as important
Minimax explores the complete game tree using depth-first search. Can we improve the algorithm?
Why those two complexities, and why they matter
The space bound O(b·d) should look familiar — it's DFS's b·m from Topic 01, because minimax is a DFS. That means memory is fine. The problem is entirely O(b^d) time: for chess, b ≈ 35 and d ≈ 100, so 35100 nodes. Alpha-beta attacks the exponent's base; it does not change the fact that the exponent is still there.

Exam-style takeaways

Key things to nail for Part 1
  1. A second agent may be cooperative or adversarial; two-player games take the adversarial case.
  2. MAX moves first, players alternate, points to the winner and penalties to the loser.
  3. Game tree — nodes are game states, edges are moves; Max nodes, Min nodes, Terminal nodes; only terminals have no children; the evaluation function gives terminal payoffs.
  4. MINIMAX(n) = utility for MAX of being in that state, assuming both players play optimally.
  5. Compute bottom-up — MIN nodes take the minimum of their children, MAX nodes the maximum.
  6. The worked tree — leaves 3, 12, 8 | 2, 4, 6 | 14, 5, 2 give B = 3, C = 2, D = 2 and A = 3 via move a₁.
  7. Complexity — time O(bd), space O(b·d); complete if the tree is finite; optimal if the opponent is optimal.
  8. Minimax is a depth-first search over the complete game tree — this sentence sets up alpha-beta.
  9. The scale of the problem — Tic-Tac-Toe ~765 states, draughts 5×1020, chess 8.73×1039, Go 2×10170.
