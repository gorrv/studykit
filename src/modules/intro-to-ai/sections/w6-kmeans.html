Week 06 · Part 1 · Unsupervised Learning

K-Means Clustering

finding groups when nobody tells you what they are

Unsupervised learning

The setting
In the unsupervised learning setting, we look for patterns in the data without having the labels of such data points.

For example, given pictures of cats and dogs, an unsupervised algorithm may be able to identify two groups of similar pictures in the dataset — without, of course, being able to 'name' them.

A very common technique to do that is clustering. This week covers two: K-Means and Hierarchical clustering.

"Without being able to name them" is the whole difference from Week 5
A supervised classifier trained on labelled photos outputs "cat". A clustering algorithm outputs "group 2" — it has found that some photos resemble each other more than others, and that is all. Nothing in the data says which group is the cats.

This also means there is no accuracy, no precision, no F1 — there is no right answer to compare against. So the quality of a clustering has to be judged from the data's own geometry, which is exactly what "within-cluster variance" is for.

Example 6.1 — where should p₄ go?

The set-up
Six points, and we want K = 2 clusters. It is unclear which cluster point p₄ should belong to. Should we have
C̃₁ = {p₁, p₂, p₃, p₄}   and   C̃₂ = {p₅, p₆}   (6.1)

or, instead,

Ĉ₁ = {p₁, p₂, p₃}   and   Ĉ₂ = {p₄, p₅, p₆}   (6.2)
Figure 6.1 — p₄ sits awkwardly between the lower-left trio and the upper-right pair.

Within-cluster variance

The key question, and the answer
What does it mean to be a better cluster assignment than another? To answer, we need a metric for within-cluster variance, V(Ck) — the value we want to minimise. We use the squared Euclidean distance:
V(Ck) = (1 / |Ck|)  Σi,i′ ∈ Ck  d(pi, pi′)²   (6.3)
d(pi, pi′)² = Σj=1D (pij − pi′j)²   (6.4)
Three details that decide whether your answer is right
  1. We do not count each pair i, i′ twice. For a cluster of 4 points there are 6 terms, not 12 — it is every unordered pair.
  2. The distance is squared, and stays squared. No square root anywhere in V.
  3. You divide by |Ck| — the number of points, not the number of pairs. A 4-point cluster with 6 pair-terms is divided by 4.

The notes even flag their own abuse of notation here: Ck is made of points pi, not indices i, so strictly the sum should be over pi, pi′ ∈ Ck. "You would be correct to feel something is off."

The notes' worked calculation — V(Ĉ₂) where Ĉ₂ = {p₄, p₅, p₆}
V(Ĉ₂) = (1/3) [ d(p₄,p₅)² + d(p₄,p₆)² + d(p₅,p₆)² ]
        = (1/3) [ 13 + 13 + 2 ]
        ≈ 9.33

Checking the three terms: d(p₄,p₅)² = (4−6)² + (4−7)² = 4 + 9 = 13 · d(p₄,p₆)² = (4−7)² + (4−6)² = 9 + 4 = 13 · d(p₅,p₆)² = (6−7)² + (7−6)² = 1 + 1 = 2.

Where this is going
Compute V for both candidate clusterings, add up each pair, and the one with the lower total wins. That is Exercise 1 — worked in full in Part 3, and the answer settles where p₄ goes. Do it yourself first; the calculator below will mark it.

The algorithm

Why we need one at all
There are too many cluster assignments to check. Considering only K = 2, the number of assignments for n = 20 is
220 − 1 = 1,048,575

That may not look like much, but the number grows exponentially in n, becoming intractable very quickly on realistic data sets.

Definition 6.2 — the K-Means Clustering Algorithm
Let p₁ … pn ∈ ℝD be a set of points and K the desired number of clusters. Then:
  1. Select K different data points to be the initial cluster centres at time t = 0, µk(0). There are no clusters yet at t = 0. Move time to t = 1.
  2. At time t, assign each data point pi to the cluster Ck(t) with the closest cluster centre µk(t−1). Break ties by assigning the point to the cluster centre with the lowest index among the closest ones.
  3. For each cluster, recalculate the cluster centre as the average of all its points:
    µk(t) = (1 / |Ck(t)|) Σi ∈ Ck(t) pi   (6.5)
  4. If clusters changed, go back to step 2 with t + 1. If clusters have not changed, stop and return the final clusters.
Four things worth noticing in that definition
  • The initial centres are actual data points — "select K different data points" — not arbitrary coordinates. Later centres are averages and generally are not data points.
  • The tie-break is specified: lowest index wins. This is unusual for a textbook and it matters — Exercises 2 and 3 both hinge on a tie at p₄, and the tie-break is what sends it one way or the other.
  • The stopping test is on the clusters, not the centres. If no point changes cluster, the centres cannot change either, so it is equivalent — but the notes phrase it in terms of clusters.
  • K is an input. K-means does not discover how many clusters there are; you have to tell it. (Hierarchical clustering, in Part 2, gives you every K at once.)
In two words
Assign, then average. Assign every point to its nearest centre; move every centre to the mean of what it caught; repeat until nothing moves.

The note under Figure 6.2, and why it matters for exam bookkeeping
"In a real implementation, iteration number 5 would not even start. That is because at the end of iteration 4 we would identify that clusters have not changed from the end of iteration 3, and therefore terminate."

So the figure draws five panels but the algorithm does four iterations. If asked "how many iterations does it take?", the answer is the number at which the clusters first repeat — here 4, because iteration 4 reproduced iteration 3's clusters.

Watch p₁ across the table: it starts as its own centre in C₁, and by iteration 3 it has migrated to C₂. A point can leave the cluster it seeded. And C₁ shrinks to the single outlier p₇ = (1,1) — K-means will happily spend a whole cluster on one distant point.

A few words on initialisation

The problem and the two fixes
Definition 6.2 does not specify how to choose the initial centres, and a bad choice can lead to a local minimum that is not a global minimum — as Exercise 3 demonstrates. Two main ways to address this (which can be combined):
  1. Run the clustering several times, with several random initialisations, and pick the best one.
  2. Select your initial centres in a smart way — for example, do not take points that are too close to each other, as it may lead to bad local minima or take too long to finish.

Both are used by scikit-learn's K-means: the number of restarts is the parameter n_init, and k-means++ selects initial centres from an empirical probability distribution over the points.

The terminology footnote is worth reading twice
The notes are careful: "a global minimum is, in particular, a local minimum. So our worry is to land on another local minimum, that is, one that does not happen to also be a global minimum." And: there may be more than one global minimum — several assignments that are equally good and better than anything else.

So the correct phrasing in an exam is "a local minimum that is not global", not "a local rather than a global minimum".

Why comparing to centres is enough

The nagging question
Step 2 assigns each point to its nearest centre. But V(Ck) was defined over all pairs of points. How can just looking for the closest cluster centre be enough?
Proposition 6.3  — flagged in the notes as non-examinable
Let Ck be a cluster and µk its centre. Then its within-cluster variance is equal to two times the sum of squared distances from each point to the cluster centre:
(1/|Ck|) Σi,i′ ∈ Ck d(pi, pi′)²  =  2 Σi ∈ Ck d(pi, µk)²   (6.7)

By reducing the sum of distances to cluster centres, one also reduces the sum of within-cluster variances. That is what makes step 2 legitimate.

Remark 6.4 — and why this justifies squared Euclidean distance specifically
The proposition justifies the use of Euclidean distances (or their squares) as what we minimise. If we had used Manhattan distance instead, it is not clear how we would be minimising distances by deciding a point's cluster only from the closest cluster centre.

In other words: the identity is a property of the squared Euclidean metric and the arithmetic mean, not a general fact. Swap the metric and "assign to nearest centre, then average" stops being guaranteed to reduce the objective. That is not an idle remark — Part 2's hierarchical clustering deliberately uses Manhattan distance, and it can, precisely because it never uses centres.

Careful — the factor of 2 only works if you count each pair twice
Check Proposition 6.3 on the notes' own cluster. Ĉ₂ = {p₄, p₅, p₆} has V = 9.33, and its centre is µ = (17/3, 17/3). Summing squared distances to that centre:
d(p₄,µ)² = (4 − 17/3)² + (4 − 17/3)² = 2 × (5/3)² ≈ 5.556
d(p₅,µ)² = (6 − 17/3)² + (7 − 17/3)² ≈ 0.111 + 1.778 = 1.889
d(p₆,µ)² = (7 − 17/3)² + (6 − 17/3)² ≈ 1.778 + 0.111 = 1.889
Σ = 9.333

That is V exactly — so with the chapter's own convention the identity is V(Ck) = Σi d(pi, µk)², without the 2. Doubling it would give 18.67.

The two statements are reconciled by which pairs the left-hand sum runs over. Equation 6.3 as used in the chapter counts each unordered pair once — "we do not count each pair i, i′ twice", and V(Ĉ₂) = (1/3)(13 + 13 + 2). Proposition 6.3's factor of 2 needs the sum over ordered pairs, which is twice as big. It is the same theorem, stated against a different reading of Σi,i′.

This changes none of the exercises and the proposition is non-examinable, but if you are asked to verify it numerically, use the convention you computed V with and say so. The variance calculator above prints both columns so you can see them line up.

Exam-style takeaways

Key things to nail for Part 1
  1. Unsupervised learning looks for patterns without labels; clustering can find the groups but cannot name them.
  2. V(Ck) = (1/|Ck|) Σi,i′∈Ck d(pi,pi′)² with d² the sum of squared coordinate differences. Each pair counted once; divide by the number of points.
  3. Be able to compute V by hand — V(Ĉ₂) = (1/3)(13 + 13 + 2) ≈ 9.33 is the model answer.
  4. A better clustering is the one with lower total within-cluster variance.
  5. The four steps of Definition 6.2 — pick K data points as centres; assign each point to the nearest centre (ties to the lowest index); recompute each centre as the mean of its cluster; repeat until the clusters stop changing.
  6. Why we need it — brute force is exponential; for n = 20 and K = 2 there are 220 − 1 = 1,048,575 assignments.
  7. K-means can converge to a local minimum that is not global, and the initialisation decides which. Two fixes: many random restarts (n_init), and choosing initial centres cleverly (k-means++).
  8. Proposition 6.3 (non-examinable) — within-cluster variance equals twice the sum of squared distances to the centre, which is what licenses "assign to nearest centre". Remark 6.4: this is specific to Euclidean distance.
  9. Be able to run K-means by hand for two or three iterations on six to eight 2-D points. This is the most likely calculation question in the whole topic.
