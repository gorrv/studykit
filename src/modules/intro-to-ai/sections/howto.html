How To Compute It

every calculation in the module, as steps you can follow
How to use this page
The theory page tells you what things mean. This page tells you what to actually write down, in order, when a question says "compute", "find" or "apply".

Each recipe is: what you are given → the steps → a tiny worked example → the check and the trap. If you can run all of these, the calculation marks are safe.

Run a search algorithm

BFS · DFS · UCS · Greedy · A*

Given: a graph with edge costs, a start, a goal, and (for greedy/A*) a table of h values.

  1. Put the start in the frontier.
  2. Pick the frontier node with the smallest f, where f is:
    BFS → depth  ·  DFS → deepest first  ·  UCS → g
    Greedy → h  ·  A* → g + h
  3. If it is the goal, stop. Otherwise move it to the explored set.
  4. Add its neighbours to the frontier with their g values (cost so far).
  5. Repeat from 2.

Worked: from ARAD, children are A (g 118, h 329), B (g 75, h 374), D (g 140, h 253). A* takes f = 118+329 = 447, 75+374 = 449, 140+253 = 393 → expand D.

⚠ Trap: g is the cost from the start to that node, not the cost of the last edge. Add it up along the path.

✓ Check: A* and UCS must return the same total cost if h is admissible.

Check a heuristic is admissible
  1. For each node, work out the true cheapest cost to the goal (h*).
  2. Compare: admissible means h(n) ≤ h*(n) for every n.
  3. One violation anywhere and it is not admissible.

Worked: h(D) = 253; true road D→E→G→BUC = 80+97+101 = 278. 253 ≤ 278 ✓

⚠ Trap: h must never overestimate. Under is fine, and h = 0 is always admissible.

Minimax and alpha-beta

Minimax value of a tree
  1. Start at the leaves — their values are given.
  2. Work upward. At a MAX node take the largest child; at a MIN node the smallest.
  3. The root's value is the answer; the move is the child that produced it.

⚠ Trap: the root is usually MAX and the layers alternate. Count the layers before you start.

Alpha-beta pruning
  1. Walk the tree left to right, depth first.
  2. Carry two numbers down: α (best MAX can guarantee, only ever rises) and β (best MIN can guarantee, only ever falls). Start α = −∞, β = +∞.
  3. At a MAX node update α; at a MIN node update β.
  4. Prune the remaining children as soon as β ≤ α.

✓ Check: the value at the root must be identical to plain minimax. Pruning never changes the answer, only the work.

Solve a CSP by hand

Backtracking with the heuristics
  1. Pick the variable: fewest legal values left (MRV). If tied, most unassigned neighbours (degree).
  2. Pick the value: the one ruling out fewest options for neighbours (LCV).
  3. Assign it, then forward check: delete that value from every unassigned neighbour's domain.
  4. If any domain becomes empty, undo and try the next value.
  5. Repeat until every variable is assigned.

Worked: Australia, all regions start with 3 colours, so MRV ties 7 ways → degree picks SA (touches 5 others).

⚠ Trap: degree counts only unassigned neighbours, and it recounts as you go.

AC-3
  1. Put every arc (both directions of every constraint) in a queue.
  2. Take an arc X→Y. For each value in X's domain, is there some legal partner in Y? If not, delete it from X.
  3. If you deleted anything, put every arc pointing back into X onto the queue again.
  4. Repeat until the queue is empty. An empty domain means failure.

⚠ Trap: arcs are directional. X→Y and Y→X are two separate checks.

Planning

Apply an action
  1. Check every precondition is true in the current state. If not, the action is not applicable.
  2. Take the current state, remove the delete list, add the add list.
  3. Anything not mentioned stays as it was (and anything not listed is false — closed-world).
Build the RPG and read off h
  1. Fact layer f(0) = the initial state.
  2. Action layer a(i) = every action whose preconditions are all in f(i).
  3. Fact layer f(i+1) = f(i) plus every add effect of a(i). Ignore all delete effects.
  4. Stop when the goal is in a fact layer, or nothing new appears.
  5. Extract a relaxed plan backwards, then h = Σ |Oᵢ|, the number of actions in it.

⚠ Trap: fact layers only ever grow, because deletes are ignored. If a layer shrank, you used a delete effect.

One Bellman update

The core Week 4 calculation

Given: the grid, R, γ, the slip probabilities, and last sweep's U values.

  1. Pick a square. For each of the four actions:
    • list the three outcomes: intended (0.8) and the two perpendicular slips (0.1 each)
    • a blocked move leaves you on your own square — use your own value
    • multiply each probability by that square's previous U and add them up
  2. Take the largest of the four totals.
  3. Unew = R + γ × that largest total.

Worked — (3,3) at sweep 2, R = −0.04, γ = 1:

Right: 0.8×1 + 0.1×0.76 (slip up bounces off the edge) + 0.1×(−0.04) = 0.872
U = −0.04 + 1×0.872 = 0.832

⚠ Traps: use last sweep's numbers for every square, not ones you just recomputed. Terminals always contribute their raw ±1. A blocked slip still happens — it just leaves you where you were.

✓ Check: 0.8 + 0.1 + 0.1 = 1. If your outcomes do not sum to 1 you have missed one.

Extract the policy
  1. Wait until U has stopped changing.
  2. At each square do the same expected-value sum for all four actions.
  3. Write down the action that scored highest, not the number. That is π(s).

⚠ Trap: R and γ drop out here — they are the same for every action, so they cannot change which one wins.

Classification and regression metrics

From a confusion matrix
  1. Label the four cells: TP, FP, FN, TN.
  2. Then:
    accuracy  = (TP + TN) / everything
    precision = TP / (TP + FP)   ← of my yeses
    recall    = TP / (TP + FN)   ← of the real yeses
    F1        = 2PR / (P + R)

⚠ Trap: precision and recall share TP on top — the difference is what is on the bottom. Higher is better for all four.

MAE, MSE, RMSE
  1. Column of errors: e = ŷ − y for each point.
  2. Column of |e|, and column of e².
  3. MAE = sum of |e| ÷ n  ·  MSE = sum of e² ÷ n  ·  RMSE = √MSE.

✓ Check: RMSE ≥ MAE always. Lower is better for all three.

⚠ Trap: divide by n before the square root.

Diagnose under- or overfitting
  1. Is the training error high? → underfitting. Stop.
  2. Training low but validation much higher? → overfitting.
  3. Both low and close → fine.

⚠ Trap: with accuracy the direction flips — overfitting is high train, low validation.

Clustering

Distances

Subtract coordinate by coordinate first, once. Then:

L₁ = add the absolute values
d² = add the squares
L₂ = √ of that

Worked: (4,4) to (6,7) → differences −2, −3 → L₁ = 5, d² = 13, L₂ = 3.61.

✓ Check: L₂ ≤ L₁ always.

Within-cluster variance V(C)
  1. List every unordered pair in the cluster — n points give n(n−1)/2 pairs.
  2. For each pair compute d² (no square root).
  3. Add them all up.
  4. Divide by |C|, the number of points — not the number of pairs.

Worked: {(4,4),(6,7),(7,6)} → 13 + 13 + 2 = 28, then 28/3 = 9.33.

One K-means iteration
  1. Assign: each point goes to the nearest centre. Ties → lowest cluster index.
  2. Update: each centre becomes the mean of its points.
  3. Repeat. Stop when the assignments stop changing (not when the centres barely move).

⚠ Trap: you can compare d² instead of d when assigning — same winner, no square roots needed.

One hierarchical merge
  1. For every pair of clusters, list all cross distances (every point of one against every point of the other).
  2. Reduce each list to one number: single = min, complete = max, average = mean.
  3. Merge the two clusters with the smallest such number, and record that number as the merge height.
  4. Repeat until one cluster remains.

To read a dendogram: find the tallest vertical gap and cut just below it. The number of lines you cross is K.

Fit a line

Theorem 7.3 — five numbers
  1. Build columns: x, y, x², xy. Add each up.
  2. You now have n, Σx, Σy, Σx², Σxy.
  3. Denominator (same for both): nΣx² − (Σx)².
  4. β̂₁ = (nΣxy − ΣxΣy) / denominator
  5. β̂₀ = (Σx²Σy − ΣxΣxy) / denominator
  6. Predict with ŷ = β̂₀ + β̂₁x.

Worked: (−1,2), (0,0), (2,0) → n=3, Σx=1, Σy=2, Σx²=5, Σxy=−2, denom=14 → β₁ = −8/14 = −4/7, β₀ = 12/14 = 6/7.

✓ Check: the residuals must sum to zero. Ten seconds, catches almost everything.

Decision trees

Gini of one node
  1. Count the classes: a vector like [2, 0, 4], total n = 6.
  2. For each class, pᵢ = count / n.
  3. Gini = Σ pᵢ(1 − pᵢ).

Worked: [2,0,4], n=6 → (2/6)(4/6) + 0 + (4/6)(2/6) = 16/36 = 0.444.

✓ Check: 0 means pure; the biggest it can be is 1 − 1/k.

Gini-Split, and choosing the feature
  1. Split the rows by the feature — one group per value.
  2. Compute Gini for each group.
  3. Weight each by group size / total rows.
  4. Add them up — that is Gini-Split for that feature.
  5. Repeat for every feature and take the arg min.

Worked: HasJob → (6/15)(0) + (9/15)(0.494) = 0.296; OwnsHome → (6/15)(0.444) + (9/15)(0.494) = 0.474. HasJob wins.

⚠ Traps: the weights are where the marks are. And the answer is a feature name, not a number.

Reinforcement learning

Qt(a) from a history
  1. Look only at steps strictly before t.
  2. Pick out the ones where that arm was chosen.
  3. Average their rewards. No pulls at all → Q = 0.

Worked: A paid 0.5, then −0.3, then (B), then 1.0. At t = 5: Q(A) = (0.5 − 0.3 + 1.0)/3 = 0.4.

ε-greedy probability of an action
  1. Everyone gets ε/k from the random branch.
  2. Find the arm(s) with the highest Q. They share the remaining 1 − ε equally.
  3. Add the two parts for the arm you were asked about.

Worked: k = 2, ε = 0.5, and a₂ is greedy → 0.25 + 0.5 = 0.75. If a₂ is not greedy → just 0.25.

⚠ Trap: a non-greedy arm is never probability 0 — the random branch still reaches it.

One UCB step
  1. Note t, compute ln t.
  2. For each arm read off N (pulls before now) and Q.
  3. Bonus = c × √(ln t / N), or ∞ if N = 0.
  4. Total = Q + bonus. Pull the biggest; ties → lowest index.
  5. Take that arm's next reward, update its N and Q, move to t+1.

Worked — t = 8, c = 2, ln 8 = 2.079:

a₁: N=4, Q=4.75 → 4.75 + 2√(2.079/4) = 4.75 + 1.442 = 6.192
a₂: N=1, Q=3.5  → 3.50 + 2√(2.079/1) = 3.50 + 2.884 = 6.384 ← wins

⚠ Traps: it is ln, not log₁₀. c sits outside the root. N counts pulls before t.

Shortcut: if every arm has the same N, the bonus is identical, so just compare Q.
