Decision Trees

Gini, Gini-Split, and choosing what to ask first

Using a tree before building one

Figure 7.4 — the credit-risk classifier
A person has attributes HasJob and OwnsHome, each 0 (False) or 1 (True). The tree assigns them to one of C = {High, Low, Medium} — their credit risk.

Someone with HasJob = 0 is classified High, regardless of OwnsHome — the feature simply never gets consulted on that branch. That is a decision tree's whole appeal: the questions you get asked depend on your earlier answers.

Two conventions to state before you draw anything
  • For binary trees (two children at every non-leaf), the left branch is where the statement is True.
  • For a non-binary branch, label each arrow with the attribute value it stands for. Nothing forces a tree to be binary — a feature profession with values journalist / mathematician / historian gives three branches out of one node.

What the “class =” line in a node means
The most common class in that node — the simple majority — with ties broken by taking the class with lowest index. It is the label the tree would output if it had to stop right there, which is why every node carries one, not just the leaves.

The Gini index

What it measures
How ‘impure’ the set of points in a node is, with respect to the classes. The left node of the second row in Figure 7.5 has Gini 0: every point in it is Low, so there is no impurity at all.

That is the motivation in one line — we want to branch so that the children are as pure as possible.

The root of Figure 7.5, by hand — how do you get to 0.658?
For each class, multiply the chance of sampling it by the chance of not sampling it, then add over the classes:
(6/15)(9/15) + (5/15)(10/15) + (4/15)(11/15) ≈ 0.658   (7.8)

Exactly, that is (54 + 50 + 44)/225 = 148/225 = 0.6578…. The notes invite you to do the same for the right-hand node of the second row and get 0.494: (5/9)(4/9) + (4/9)(5/9) = 40/81 = 0.4938…

Definition 7.4 — Gini Index
Let v = (v₁, …, vk) ∈ ℕk be a k-dimensional vector of non-negative integers, and let n = Σᵢ vᵢ. Then
Gini(v) = Σi=1..k pᵢ(1 − pᵢ)   where  pᵢ = vᵢ/n   (7.9)

Note what the argument is: a vector of counts, not a set of points. Gini does not care which points are in the node, only how many of each class.

Three properties worth carrying into the exam
  • Gini = 0 exactly when the node is pure — one class has everything.
  • Maximum is 1 − 1/k, reached when all k classes are equally represented. For k = 2 that is ½ (Exercise 4); for k = 3 it is ⅔; for k = 4, ¾.
  • Equivalently Gini(v) = 1 − Σ pᵢ², since Σpᵢ = 1. Faster to compute under time pressure, and identical in value.

Gini-Split — choosing what to ask

Where 0.444, 0.494 and 0 come from

Each one is the Gini of one child group, from Definition 7.4 applied to that group's class counts. Nothing else.

splitgroupcounts [High, Low, Medium]Gini = Σ pᵢ(1 − pᵢ)
OwnsHome= No, 6 people[2, 0, 4] (2/6)(4/6) + 0 + (4/6)(2/6) = 16/36 = 0.444
= Yes, 9 people[4, 5, 0] (4/9)(5/9) + (5/9)(4/9) + 0 = 40/81 = 0.494
HasJob= No, 6 people[6, 0, 0] (6/6)(0/6) + 0 + 0 = 0 — pure
= Yes, 9 people[0, 5, 4] 0 + (5/9)(4/9) + (4/9)(5/9) = 40/81 = 0.494

And the 6/15 and 9/15 are simply what fraction of the 15 rows landed in each group. So:

OwnsHome: (6/15)(0.444) + (9/15)(0.494) = 0.178 + 0.296 = 0.474
HasJob:   (6/15)(0)      + (9/15)(0.494) = 0      + 0.296 = 0.296

That zero is the whole reason HasJob wins. Splitting on it hands you one group with nothing left to decide — all six are High.

Figure 7.6 — the same data split the other way
Splitting Table 7.3 by OwnsHome instead gives a tree that looks worse. Why?

Because splitting by ‘OwnsHome’ generates children with worse Gini values on average — well, weighted average. Weighting matters: a very impure child holding two points should not count as much as a slightly impure one holding nine.

The two calculations, side by side
Gini-Split(OwnsHome) = (6/15)·0.444 + (9/15)·0.494 ≈ 0.474
                         ↑ OwnsHome = False, Gini(2,0,4)    ↑ OwnsHome = True, Gini(4,5,0)

Gini-Split(HasJob)   = (6/15)·0     + (9/15)·0.494 ≈ 0.296
                         ↑ HasJob = False, Gini(6,0,0)      ↑ HasJob = True, Gini(0,5,4)

HasJob is less impure, so we split by it. Exactly: 64/135 ≈ 0.4741 against 8/27 ≈ 0.2963.

Definition 7.5 — Gini-Split Index
Assume categorical features only. Let S be a set of n data points with features A₁, …, Ak, and let Ai be an attribute with a possible values. Then
Gini-Split(Ai) = Σj=1..a (nj/n) · Gini(vj)   (7.10)

where vj counts the classes in the child node where Ai = j, and nj is the sum of its entries. To choose the attribute:

arg minA₁,…,Ak { Gini-Split(Ai) }   (7.11)

arg min, not min — the answer is which attribute, not the number. Write the attribute name.

Two extensions the definition already covers
  • More than two features: compute Gini-Split for all of them and pick the lowest.
  • More than two values: the sum simply runs over all the children. Nothing in (7.10) assumes a is 2.

Building the rest of the tree

The recursion, and the question people get wrong
Formula (7.11) applies at every node, not just the root. So: at each node, score every remaining attribute against the points that reached that node, take the arg min, split, and recurse. Stop when the node is pure — or when you run out of attributes.

Look at Figure 7.6: both children of the root are split by the same feature, HasJob, but only because there were only two features to choose from. In general, should we force different branches to split the same way?

No. Nothing stops us, but it makes more sense to allow different splits in different branches: when a new point arrives, its feature values are no secret to us, so we can simply traverse the tree taking the current best option at each node. Allowing branches to differ is what scikit-learn does.

Why re-splitting on a used feature is pointless, not just inelegant
Everything reaching a node below HasJob = Yes has HasJob = Yes. That feature now has one value across the whole node, so the split has a single child containing everything, and its Gini-Split equals the node's own Gini — no improvement, ever. The tool below marks such features useless here rather than scoring them.
What happens when you run out of features before you run out of impurity
Two rows with identical features but different classes can never be separated. The node becomes a leaf labelled with the majority class — impure, and accepting some training error. Table 7.4 in Exercise 5 does this on purpose: with 3 binary features there are only 8 possible feature vectors but 20 rows and 4 classes, so no tree on those features can be perfect.

Exam takeaways

What to have ready
  • Gini(v) = Σ pᵢ(1 − pᵢ), pᵢ = vᵢ/n. Zero ⟺ pure. Maximum 1 − 1/k at equal classes; ½ when k = 2.
  • Gini-Split(A) = Σⱼ (nⱼ/n)·Gini(vⱼ) — a weighted average over the children, and you pick the arg min.
  • Show the weights. Marks in these questions sit on the (nⱼ/n) factors as much as on the Gini values.
  • Node label = majority class, ties to the lowest index, and index order is the alphabetical class order.
  • Apply (7.11) at every node, on that node's points only, and let different branches split on different features.
  • Left = True in a binary tree; label the arrows in a non-binary one.
  • Decision Tree Regression is out of scope; continuous features are not.
  • Neural networks are out of scope.
