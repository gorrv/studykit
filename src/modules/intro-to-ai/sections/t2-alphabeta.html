Alpha-Beta Pruning

the same answer, fewer nodes

Two observations

At a MAX node → α

When some of the children of a MAX node have been evaluated, there is a lower bound α on how much MAX can get, even if the other children have not been evaluated yet.

≥ 3

At a MIN node → β

When some of the children of a MIN node have been evaluated, there is in turn an upper bound β on how much MIN can get, even if the other children have not been evaluated yet.

≤ 5
Why bounds, and why they only go one way
A MAX node that has already seen a child worth 3 can never end up below 3 — it can always just take that child. So its value is ≥ 3: a floor that only rises as more children are seen. Symmetrically, a MIN node that has seen a 5 can never end up above 5: a ceiling that only falls.

These are partial results computed before the node is finished — which is what makes them useful. If a floor from somewhere above already beats a ceiling here, nothing below this point can matter.

α, β, and the cut rule

Definitions
  • α is the minimum score the MAX player could get (the best MAX has secured so far anywhere on the path).
  • β is the maximum score the MIN player could get (the best MIN has secured so far anywhere on the path).

Two optimisations:

  • Skip the rest of a MIN node's children when β ≤ α.
  • Skip the rest of a MAX node's children when β ≤ α.
One rule, said in English
β ≤ α reads: "the best this branch can possibly offer MAX is already no better than something MAX can guarantee elsewhere." So MAX would never come here — and there is no point finishing the evaluation.

Notice the condition is the same at both node types. What differs is only which of the two values you were about to update. That is why it's one algorithm, not two.

What pruning does not do
Alpha-beta returns exactly the same value as plain minimax. It is not an approximation, not a heuristic, and it never changes the chosen move. The only thing it changes is how many terminal nodes get evaluated. If an exam question asks for "the minimax value with alpha-beta pruning", the value is the same number — the extra marks are for saying which nodes were skipped.

Why C got cut but D did not
C's first leaf was 2, which instantly capped C at ≤ 2 — below the 3 MAX already had. Dead branch, stop.

D's first leaf was 14, which caps D at ≤ 14 — still above 3, so D might yet beat B and must be explored. Then 5 caps it at ≤ 5, still above 3. Only the final 2 settles it. The order the leaves happen to appear in decides how much you save — which is the next section.

How much does pruning save?

It depends entirely on move ordering
  • Worst case — children arrive in the least helpful order and nothing is pruned: back to O(bd).
  • Best case — the best move is examined first at every node, and the cost drops to roughly O(bd/2).

Halving the exponent means you can search twice as deep in the same time — which, in a game, is the difference between a weak player and a strong one.

The intuition for "best move first"
Cuts happen when a bound gets tight early. Finding a strong move immediately raises α at once and makes every later sibling easy to dismiss; stumbling on it last means you carried a useless bound the whole way. Real engines therefore spend effort guessing a good move order before searching — which is why "try the move that was best last time" is such a common trick.
Summary
  • With more than one agent, we need different approaches.
  • Adversarial search like minimax lets us consider the best-worst outcomes and make decisions to guide towards them.
  • Alpha-beta pruning lets us trim and reduce the number of states we evaluate.

Exam-style takeaways

Key things to nail for Part 2
  1. The two observations — a partly-evaluated MAX node has a lower bound α; a partly-evaluated MIN node has an upper bound β.
  2. α = minimum score the MAX player could get. β = maximum score the MIN player could get. Learn these two sentences verbatim.
  3. The cut rule — skip the remaining children of a MIN node when β ≤ α, and skip the remaining children of a MAX node when β ≤ α. Same condition both times.
  4. Alpha-beta returns the identical value to minimax — it only changes how many nodes are evaluated.
  5. Be able to run the worked tree by hand — B = 3 sets α = 3; C's first leaf 2 gives β = 2 ≤ 3, so C's remaining two leaves are pruned; D needs all three because 14 and 5 don't settle it. Answer 3, 7 leaves evaluated instead of 9.
  6. Savings depend on move ordering — worst case O(bd), best case about O(bd/2), i.e. twice the depth for the same effort.
  7. Show your working — in a pruning question the marks are for the α/β values at each node and the crossed-out leaves, not just the final number.
