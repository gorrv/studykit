Solving a CSP

backtracking, heuristics, and inference

A CSP as a search problem

The four components
  • States — assignments of variables to values within domains.
  • Initial state — no variables assigned.
  • Action — assign a value to any unassigned variable, provided it does not violate a constraint. If no legal assignments, return failure.
  • Goal test — all variables are assigned values, satisfying all constraints.
The important word is "provided"
Compare Topic 01's search problem: there, actions were legal or not by the transition model, and the goal test happened at the end. Here the constraint check is folded into the action itself — you never even generate an inconsistent state. That's the first efficiency, and it's free.
The size of the naïve tree
  • The complete search tree is only of depth n (one layer per variable) — every solution is at the bottom, so depth is not the problem.
  • But with m possible values per variable, there are n! × mn paths through the tree.

The n! is pure waste: it counts the orders in which you could have made the same assignments.

Backtracking search

What it is
A variation of depth-first search with two ingredients:
  • Single-variable assignments — only one variable is assigned at each level of the search tree.
    • Commutativity: [WA = red, NT = green] = [NT = green, WA = red].
    • This reduces paths from n! × mn to mn.
  • For each assignment — check for failure; backtrack on failure to the next assignment; if all assignments fail, return failure.
function RECURSIVE-BACKTRACKING(assignment, csp)
    if assignment is complete then return assignment
    var ← SELECT-UNASSIGNED-VARIABLE(VARIABLES[csp], assignment, csp)
    for each value in ORDER-DOMAIN-VALUES(var, assignment, csp)
        if value is consistent with assignment given CONSTRAINTS[csp]
            add {var = value} to assignment
            result ← RECURSIVE-BACKTRACKING(assignment, csp)
            if result ≠ failure then return result
            remove {var = value} from assignment
    return failure
Where the improvements plug in
Look at the two capitalised helper functions — they are deliberately left abstract:
  • SELECT-UNASSIGNED-VARIABLE → the variable-ordering heuristics (MRV, degree).
  • ORDER-DOMAIN-VALUES → the value-ordering heuristic (LCV).

The extended version adds a third: an INFERENCE step after each assignment, which is where forward checking and arc consistency live. Everything in the rest of this topic is one of those three slots.

Still not good enough
  • It's inefficient — still exhaustively trying all combinations until failure at a given level; arbitrary selection of values.
  • Improving the algorithm: decide which variable we assign at each level; decide the order in which values are tried.
function BACKTRACK(assignment, csp) /* the version with inference */
    if assignment is complete then return assignment
    var ← SELECT-UNASSIGNED-VARIABLE(csp)
    for each value in ORDER-DOMAIN-VALUES(var, assignment, csp) do
        if value is consistent with assignment then
            add {var = value} to assignment
            inferences ← INFERENCE(csp, var, value)
            if inferences ≠ failure then
                add inferences to assignment
                result ← BACKTRACK(assignment, csp)
                if result ≠ failure then return result
            remove {var = value} and inferences from assignment
    return failure

Which variable to assign next?

Most constrained variable

  • Choose the variable with the fewest legal values.
  • Known as the minimum remaining values (MRV) heuristic.

Most constraining variable

  • Imposes the most constraints on the remaining values (for other variables).
  • In graph terms: highest degree.
"Fail first" — and why that's a good thing
Both heuristics aim to hit the dead end as early as possible. If a variable has only one legal value left, assigning it can't go wrong; if it has zero, you find out now instead of after ten more pointless assignments. Pruning near the root of a tree removes an exponential amount of work; pruning near a leaf saves almost nothing.

In practice they're used together: MRV first, degree as the tie-breaker — which is why on Australia the first variable picked is SA (every variable starts with 3 values, so MRV ties, and SA wins on degree 5).

Variable selected — what value to try?

Least constraining value (LCV)
Choose the value that rules out the fewest values in the remaining variables.
Why value ordering pulls the opposite way to variable ordering
This looks contradictory — variables "fail first", values "fail last" — but the asymmetry is real:
  • You must assign every variable, so you want the hopeless one exposed immediately.
  • You only need one value per variable to work, so you want the most promising one tried first.

Same goal both times: reach a solution, or a refutation, with the least search.

Detecting failure early: forward checking

Definition
  • Keep track of remaining legal values for unassigned variables.
  • Terminate search when any variable has no legal values.

Forward checking propagates information from assigned to unassigned variables.

The failure is detected at V = blue
SA borders WA (red), Q (green) and V (blue), so after the third assignment it has no legal values left and the search backtracks — without ever having tried to assign SA. That is forward checking earning its keep.
But it isn't enough
Forward checking only detects constraints early. Constraint propagation enforces constraints.
Spot the missed inference
Look at the row after Q = green: NT = {blue} and SA = {blue}. NT and SA are neighbours, and both are down to the same single value — the position is already dead. Forward checking cannot see it, because it only ever compares an assigned variable with its unassigned neighbours; it never compares two unassigned variables with each other. Fixing exactly that is arc consistency.

Constraint propagation: arc consistency

Definition
The simplest form of constraint propagation — keep pairs of variables consistent.
  • X → Y is consistent iff for each value of X there are allowed values of Y.
  • When checking X → Y, throw out any values of X for which there isn't an allowed value of Y.
  • If X loses a value, all pairs Z → X need to be rechecked.
Arcs are directed — this trips everyone up
X → Y and Y → X are two different arcs and are checked separately. Checking X → Y only ever deletes values from X, never from Y. That's why the third bullet exists: shrinking X can break arcs that point into X, so they all go back in the queue.

The headline result
Arc consistency detects failure earlier than forward checking — here with only two assignments instead of three. It can be run before or after each assignment is made.

AC-3

function AC-3(csp) returns the CSP, possibly with reduced domains
    inputs: csp, a binary CSP with variables {X₁, X₂, …, Xₙ}
    local variables: queue, a queue of arcs, initially all the arcs in csp

    while queue is not empty
        (Xᵢ, Xⱼ) ← REMOVE-FIRST(queue)
        if REMOVE-INCONSISTENT-VALUES(Xᵢ, Xⱼ) then
            for each X_k in NEIGHBORS[Xᵢ] do
                add (X_k, Xᵢ) to queue

function REMOVE-INCONSISTENT-VALUES(Xᵢ, Xⱼ) returns true iff succeeds
    removed ← false
    for each x in DOMAIN[Xᵢ]
        if no value y in DOMAIN[Xⱼ] allows (x, y) to satisfy the constraint Xᵢ ↔ Xⱼ
            then delete x from DOMAIN[Xᵢ]; removed ← true
    return removed
Reading AC-3 in three lines
1. Put every arc in a queue. 2. Pop one, prune the tail's domain against the head's. 3. If anything was pruned, push back every arc pointing at the tail, because they may have become stale.

It terminates because domains only ever shrink, and it costs O(n²d³) for n variables with domain size d. Failure = some domain becomes empty. Note it can also finish with all domains non-empty and still have no solution — arc consistency is a filter, not a solver.

The demonstration to run
With WA=red, Q=green, forward checking survives but AC-3 empties a domain — the exact claim that arc consistency detects failure earlier. Then try WA=red, Q=green, V=blue and watch forward checking finally catch up.
Which variable empties is not fixed — and that's fine
The usual trace ends with SA empty; the tool may report NT. Both are correct. After WA=red and Q=green, NT and SA are neighbours that have both been reduced to {blue}, so whichever arc — SA→NT or NT→SA — comes off the queue first is the one that wipes out.

AC-3 gives no guarantee about which domain empties, only that if the CSP is arc-inconsistent, some domain will. In an exam, name the variable your own trace produces and show the arc that did it.

Why constraint propagation pays off

The argument
  • Constraint propagation is often faster than traditional state-space search, because state-space search only cares if a state is the goal, not whether it is valid — and it is not immediately obvious what a good heuristic is for this kind of problem.
  • Constraint propagation eliminates areas of the state space that are no longer relevant: if we know this state isn't a valid solution, we can discard it and all further refinements of it.
The numbers
For {SA = blue}:
  • This state leaves 35 = 243 possible states for the neighbouring values — a lot of them invalid.
  • With constraint propagation: 25 = 32 possible states.
  • A reduction of 87%.

This enables dense or intractable problems to be searched through much faster.

Where 243 and 32 come from
SA has five neighbours (WA, NT, Q, NSW, V). Before propagation each has 3 colours: 3⁵ = 243. Setting SA = blue removes blue from every neighbour, leaving 2 each: 2⁵ = 32. And 32/243 ≈ 0.13, so 87% of that subtree is gone from a single assignment — which is the whole argument for inference in one line.
Summary
  • Problems of assignment are less concerned with the path taken than the solution.
  • CSPs let us define assignment problems with specific variables, domains and constraints.
  • Backtracking search is one approach towards solving a simple CSP.
  • We can improve variable selection through heuristics.
  • Forward checking and arc consistency help prevent wasted search.

Exam-style takeaways

Key things to nail for Part 4
  1. CSP as a search problem — states are assignments; initial state has nothing assigned; an action assigns a value provided it violates no constraint; the goal test is all variables assigned and all constraints satisfied.
  2. The tree is only depth n, but has n! × mn paths.
  3. Commutativity — [WA=red, NT=green] = [NT=green, WA=red] — lets single-variable assignment cut n! × mn down to mn. Know this reduction.
  4. Backtracking search is depth-first search with one variable assigned per level, checking for failure and backtracking.
  5. MRV = most constrained variable = fewest legal values. Degree = most constraining variable = imposes the most constraints on others. LCV = least constraining value = rules out the fewest values elsewhere.
  6. Forward checking — track remaining legal values for unassigned variables; terminate when any variable has none; it propagates from assigned to unassigned variables.
  7. Arc consistency — X → Y is consistent iff for each value of X there is an allowed value of Y; checking X → Y deletes values from X; if X loses a value, all arcs Z → X must be rechecked.
  8. Arc consistency detects failure earlier than forward checking, and can be run before or after each assignment.
  9. Be able to reproduce both worked runs — FC fails after WA=red, Q=green, V=blue (SA empties); AC fails after just WA=red, Q=green.
  10. AC-3 — a queue of all arcs; pop, run REMOVE-INCONSISTENT-VALUES, and if it removed anything, add every arc (X_k, Xᵢ) for neighbours X_k back to the queue.
  11. The 87% figure — {SA = blue} goes from 3⁵ = 243 to 2⁵ = 32 states for its five neighbours.
