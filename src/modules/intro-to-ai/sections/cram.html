A distilled summary of the whole module. Use Ctrl/Cmd+P to print it — the sidebar and tools are hidden in print. One card per topic, added as the content goes in.

W1 · What AI is

  • Two senses: a kind of intelligence (a property — no such thing as "an AI"), and a field of research.
  • McCarthy 1956: science and engineering of making intelligent machines — need not confine itself to biologically observable methods.
  • Four approaches: think / act × like humans / rationally. "Like humans" = cognitive models; "rationally" = laws of logic and probability.
  • Turing test 1950, Q&A. Total Turing test = a robot, physical behaviour too.

W1 · Agents

  • Agent: makes an intelligent decision when given the opportunity, using the knowledge and actions available at that time.
  • Autonomous agent: decides without human input.
  • Rational agent: always takes the best action.
  • The loop: Sensors → what the world is like now → what it'll be like if I do A → what action to do now → Effectors. Knowledge = how the world evolves, effects of my actions, goals.
  • Value alignment: aligning system goals with human ones; exactly specifying "good" is the hard part.

W1 · Model-based vs data-driven

  • Model-based = explicit knowledge = Symbolic / Classical AI: encode the world, encode how it changes, search for strategies. "Pretends to think."
  • Data-driven = tacit knowledge = ML: read coarse data, be told the problem, adjust the model. "Pretends to learn."
  • Dimensions: knowledge explicit/tacit, model-based/data-driven; perception perfect/imperfect; environment fully/partially observable, static/dynamic; actions instantaneous/durative, deterministic/stochastic.
  • Search assumes the easy end of every axis.

W1 · Search problems

  • Search = computing a sequence of actions that form a path to a goal.
  • Five parts: state space; initial state + goal test; actions; transition model; action costs.
  • Search tree: node = state, edge = action. Redundant paths ⇒ infinite tree.
  • Two fixes: check the path back to the root, or track visited states.
  • Notation: b branching factor, d depth of shallowest solution, m max depth.

W1 · The five algorithms

  • One algorithm, five f's. Best-first = priority queue on f(n).
  • BFS f = depth. Queue + reached. Complete ✓. Optimal ✓ only if equal costs. Time & space b + b² + … + b^d.
  • DFS f = −depth. Complete ✓ if redundant paths prevented. Optimal ✗ (left-most solution). Time b^m, space b·m.
  • UCS f = g. Complete ✓, optimal ✓. Time & space ∝ nodes cheaper than the goal. Minimum-cost, not minimum-action.
  • Greedy f = h. Fast, not optimal.
  • A* f = g + h. Optimal if h admissible.

W1 · Numbers to remember

  • BFS vs UCS from D: 2 actions cost 310 vs 3 actions cost 278.
  • Greedy ARAD → D → F → BUCHAREST = 140 + 99 + 211 = 450.
  • A* ARAD → D → E → G → BUCHAREST = 140 + 80 + 97 + 101 = 418.
  • First f-values from ARAD: A 447, B 449, D 393. Then C 671, E 413, F 415. Then G 417, H 526.
  • Goal offered via F at 450, via G at 418.

W1 · Heuristics

  • Heuristic = rule of thumb estimating cost from n to the goal. UCS looks backwards (g); h looks forwards.
  • Admissible = never over-estimates: actual cost ≥ h(n). Straight-line distance is admissible.
  • A* + admissible ⇒ optimal.
  • h ≡ 0 is admissible but turns A* into UCS.
  • Challenge: admissible and informative — obtained by relaxing problem constraints.
  • A* stops on expanding the goal, not on generating it.

W2 · Minimax

  • Game tree: nodes = states, edges = moves; Max, Min and Terminal nodes; only terminals have no children.
  • MINIMAX(n) = utility for MAX, assuming both play optimally.
  • MIN nodes take the min of their children; MAX nodes the max. Bottom-up.
  • Complexity: time O(bd), space O(b·d) — it's a DFS.
  • Complete if the tree is finite; optimal if the opponent is optimal.
  • Worked tree: 3,12,8 | 2,4,6 | 14,5,2 → B=3, C=2, D=2, A=3 via a₁.

W2 · Alpha-beta

  • α = minimum score the MAX player could get (a floor, only rises).
  • β = maximum score the MIN player could get (a ceiling, only falls).
  • Cut rule: skip the rest of the children when β ≤ α — same condition at MAX and MIN nodes.
  • Same value as minimax, always. Only the node count changes.
  • Worked tree: B=3 sets α=3; C's first leaf 2 gives β=2 ≤ 3 → prune C's other two. 7 of 9 leaves.
  • Ordering: worst case O(bd), best case O(bd/2) — twice the depth for the same effort.

W2 · CSPs

  • Three parts: variables X, domains D, constraints C. Each constraint = scope + relation.
  • Solution = instantiation of all of X from D satisfying all of C. Solvers search incomplete but consistent partial assignments.
  • Australia: X = {WA, NT, Q, NSW, V, SA, T}; D = {red, green, blue}; 9 constraints; SA degree 5, T degree 0.
  • n-Queens: X = {xij}, D = {0,1}, Σxij = N plus "not both 1" on rows, columns, both diagonals.
  • Tree depth n, but n! × mn paths; commutativity cuts it to mn.

W2 · Solving CSPs

  • Backtracking = DFS, one variable per level, backtrack on failure.
  • MRV — fewest legal values. Degree — most constraining. LCV — rules out fewest values elsewhere.
  • Forward checking — track legal values, stop when one empties; propagates assigned → unassigned only.
  • Arc consistency — X→Y consistent iff every value of X has a support in Y; deletes from X; if X shrinks, re-queue all Z→X.
  • AC detects failure earlier: AC fails after WA=red, Q=green; FC needs V=blue too.
  • {SA=blue}: 3⁵ = 243 → 2⁵ = 32, an 87% reduction.

W3 · Classical planning

  • Given I, G and A (actions with preconditions and effects); find a plan — a sequence taking I to G.
  • Planning is more powerful than CSP — CSPs can be modelled as planning problems.
  • An action has: parameters, preconditions (relations that must hold), effects (relations added or deleted).
  • Closed-world assumption — what is not listed in the initial state is assumed false.
  • Logistics: Move (at t from / connected → +at t to, −at t from) · Load (at t l, at c l → +on c t, −at c l) · Unload (mirror of Load).

W3 · PDDL

  • Language + algorithm — write any problem in PDDL, any planner solves it.
  • Versions: PDDL propositional · 2.1 numbers + time · 3 preferences · + continuous change, processes, events.
  • One domain file (predicates, actions) + many problem files (objects, init, goal).
  • Action syntax: :parameters, :precondition, :effect; (and …); deletes as (not (…)).
  • Fluents (2.1): :functions, comparisons in preconditions, increase/decrease in effects, (:metric minimize …).
  • Durative: :duration; conditions at start / over all / at end; effects at start / at end.

W3 · Forward chaining & RPG

  • Forward chaining: S′ = S − {deletes} + {adds}; a goal state contains the goal conditions.
  • Put X on Y from Z — pre: clear X, on X Z, clear Y; add: clear Z, on X Y; del: on X Z, clear Y.
  • RPG — plan from S to G ignoring delete effects; its length is h(S). FF, Hoffmann & Nebel 2001.
  • Build: f(0) = initial state; a(n+1) = actions with preconditions in f(n); f(n+1) = f(n) + adds. Layers only grow.
  • Extract: backwards from g(m) = goals; fact in f(n−1) drops down, else pick an action from a(n) and add its preconditions.
  • h(s) := Σ |Oi| — actions, not layers. Demo: m = 2 but h = 3.
  • Used as h in A*, rebuilt for every node added to the open list.

W4 · Uncertainty & MDPs

  • Search assumed the state is known (fully observable) and actions execute as intended (deterministic).
  • MDP = sequential decision making for a fully observable but stochastic environment.
  • Two principles: Markov property holds for action transitions; probability distributions are stationary.
  • Markov property: next state depends only on the current state, not the history.
  • Transition model T(s,a,s′) = P(s′|s,a). Grid: 0.8 intended, 0.1 each side, blocked ⇒ stay.
  • Plan → policy. A sequence breaks when an action slips; a policy covers every state.

W4 · Rewards & policies

  • Utility = sum of rewards of all states visited. Up,Up,Right,Right,Right ⇒ (5×−0.04)+1 = 0.8; that plan executes with probability 0.8⁵ ≈ 33%.
  • Negative reward incentivises optimality.
  • π must be complete · optimal · stationary · proper (guaranteed to reach a terminal).
  • Uπ(s) = E[Σ γtR(St)]; γ values current over future rewards.
  • Four regimes: R=−1.65 rush for any exit · −0.04 balanced · −0.01 take no risks (stall against the wall) · R>0 never terminate.
  • At (4,1) with R=−0.04 the policy points away from the goal — a 10% slip would hit the −1.

W4 · Expected utility

  • E[U] = Σc∈C P(c)U(c). Coin: 0.5×0 + 0.5×5 = 2.5.
  • P(a,b) joint — both true at once. P(a|b) conditional — a true given b known. P(a|b) ≥ P(a,b).
  • Bayes: P(a|b) = P(a,b) / P(b).
  • E[U|s,a] = Σs′∈nei(s) P(s′|s,a)U(s′) — sum over every state the action could reach.
  • It's an expectation because the action may not do what you asked; all you know is the probability of each outcome.

W4 · Value iteration

  • Bellman update: Ui+1(s) = R(s) + γ maxa Σs′ P(s′|s,a)Ui(s′).
  • Max over your actions, average over the world's outcomes.
  • Init: U = 0 everywhere except end states, where U(s) = R(s).
  • Stop when Ui+1 = Ui; formally δ < ε(1−γ)/γ.
  • One sweep by hand (R=−0.04, γ=1): all −0.04 except (3,3) = −0.04 + 0.8 = 0.76.
  • Converged U: 0.812 0.868 0.918 / 0.762 ▪ 0.660 / 0.705 0.655 0.611 0.388.
  • Policy: π(s) = arg maxa Σ P(s′|s,a)U(s′) — R and γ drop out.
  • Iterations blow up as γ → 1; distant states dip negative before climbing.

W5 · ML overview

  • Samuel 1959: "gives computers the ability to learn without being explicitly programmed".
  • Mohri et al. 2018 experience → performance · R&N 2022 observes data, builds a model that is both hypothesis and software · Murphy 2012 detect patterns, predict future data.
  • Supervised = trained on labelled examples. Unsupervised = unlabelled, discover patterns. Reinforcement = learns from reward/punishment, exploitation vs exploration.
  • Supervised problems: classification (labels), regression (numbers).
  • Unsupervised problems: clustering (discovers groups), dimensionality reduction (high-dim → low-dim, preserving desired properties).
  • Many ML algorithms have no proof they work — hence measurement replaces proof.

W5 · Classification metrics

  • Training set = used for learning, with labels. Test set = untouched, labels hidden, used after training.
  • Accuracy = correct / all = (TP+TN)/total.
  • The 99% trap: 1% prevalence, always answer "no" → 99% accuracy, catches nothing.
  • Precision = TP/(TP+FP) — of what I flagged, how much was real. Punishes false alarms.
  • Recall / sensitivity = TP/(TP+FN) — of what was real, how much I caught. Punishes misses.
  • F1 = 2/(recall⁻¹+precision⁻¹) = 2PR/(P+R), the harmonic mean — high only if both are high.
  • Recall exposes the always-"no" model; precision is 0/0 or a perfect 1.00. Neither uses TN.

W5 · Regression metrics

  • MAE = (1/n) Σ |ŷᵢ − yᵢ| — every unit of error equal.
  • MSE = (1/n) Σ (ŷᵢ − yᵢ)² — squares, so very sensitive to outliers.
  • RMSE = √MSE — same as MSE but back in the original units.
  • RMSE ≥ MAE always; equal only when all errors have the same size.

W5 · Under- and overfitting

  • Generalisation error = error on unseen data. Can't compute it, so minimise the empirical error — the one we control.
  • Underfitting = fails to capture the complexity of the training data. Too simple.
  • Overfitting = fits too much to the training data, fails to generalise. Too complex — it memorises the noise.
  • Training error only ever falls with complexity; validation error is U-shaped. Pick the bottom of the U.
  • The three fits: deg 1 → 1.89e−01 / 3.79e−01 · deg 4 → 6.91e−03 / 1.20e−02 · deg 29 → 3.22e−03 / 1.76e+15.
  • Diagnose from the gap: both high & close = under · both low & close = right · train ≈ 0 with validation climbing = over.
  • Validation not test: choosing with a set means fitting to it. Train / choose / report, on three sets.

W6 · K-means

  • Unsupervised = patterns without labels; clustering finds groups but cannot name them.
  • V(Ck) = (1/|Ck|) Σi,i′∈Ck d(pi,pi′)². Each pair once; divide by the number of points.
  • Better clustering = lower total within-cluster variance.
  • Algorithm: pick K data points as centres → assign each point to the nearest centre (ties to lowest index) → recompute centres as means → repeat until clusters stop changing.
  • Why not brute force: n = 20, K = 2 gives 2²⁰ − 1 = 1,048,575 assignments; exponential in n.
  • Local minima: initialisation decides. Fixes = many restarts (n_init) + smart seeding (k-means++).
  • Prop 6.3 (non-examinable): V(C) = 2 Σ d(p,µ)² — justifies "assign to nearest centre", and only for Euclidean.

W6 · Hierarchical

  • Start: n singleton clusters. Step: merge the closest pair. Stop: one cluster.
  • Two independent choices: linkage (cluster–cluster) and metric (point–point). Any combination.
  • L₁ = Σ|p₁ᵢ − p₂ᵢ| · L₂ = (Σ(p₁ᵢ − p₂ᵢ)²)½. L₂ ≤ L₁.
  • Single = min · Complete = max · Average = mean (divide by mn).
  • Single chains (straggly clusters); complete stays compact (bounds the diameter).
  • Ties: merge all clusters at the threshold — two pairs → two merges, a chain → one big cluster. Cost: some K unreachable.
  • Max steps = n − 1. Dendogram: join height = merge threshold; a long vertical gap = good place to cut.
  • Worked run (single, L₁): thresholds 4, 5, 7, 8, 12 — {1,5}, {2,3}, {2,3,6}, {2,3,4,6}, all.

W7 · Linear regression

  • Supervised = labelled data. Regression → a number; classification → a class.
  • Model: y = β₀ + β₁x + ε, ε ∼ N(0, σ²). Prediction ŷ = β₀ + β₁x; residual ε = y − ŷ.
  • N(µ, σ²) carries the variance. σ = 0.3 ⟹ N(µ, 0.09). µ ± σ ≈ 68%, ±2σ ≈ 95%, ±3σ ≈ 99.7%. P(one exact value) = 0.
  • Objective: minimise SSE = Σεᵢ². (Least Absolute Deviations minimises Σ|εᵢ| instead.)
  • By hand: collect SSE = nβ₀² + (Σx²)β₁² + (2Σx)β₀β₁ − (2Σy)β₀ − (2Σxy)β₁ + Σy², freeze one β, take the vertex at −b/2a, solve the pair.
  • Theorem 7.3: β̂₁ = (nΣxy − ΣxΣy)/(nΣx² − (Σx)²); β̂₀ = (Σx²Σy − ΣxΣxy)/(same denominator).
  • Notes' example (−1,2),(0,0),(2,0): β̂₀ = 6/7, β̂₁ = −4/7, SSE = 8/7. Ex 1: ŷ(5) = −2.
  • "Linear" is about the βs — polynomial regression is a special case of linear regression.
  • Normality is not used in the proof of Theorem 7.3, only for further properties like unbiasedness.
  • Free check: residuals sum to zero at the optimum; the line passes through (x̄, ȳ).

W7 · Decision trees

  • Gini(v) = Σ pᵢ(1 − pᵢ), pᵢ = vᵢ/n. Equivalently 1 − Σpᵢ².
  • 0 ⟺ pure. Maximum 1 − 1/k at equal classes: ½ (k=2), ⅔ (k=3), ¾ (k=4).
  • Gini-Split(A) = Σⱼ (nⱼ/n)·Gini(vⱼ) — a weighted average. Choose by arg min (7.11), at every node, not just the root.
  • Table 7.3: Gini(root) = 148/225 ≈ 0.658. Gini-Split(HasJob) = 8/27 ≈ 0.296 beats Gini-Split(OwnsHome) = 64/135 ≈ 0.474.
  • Node label = majority class, ties → lowest index; ordering is alphabetical.
  • ⚠ Figure 7.5 mislabels three nodes — [0,5,4] is Low not Medium, [0,0,4] is Medium, [0,5,0] is Low. Figures 7.4 and 7.6 are correct. Read labels off the vector.
  • Branches may split differently — that is what scikit-learn does, and re-using a feature on the same path is pointless (one child, no gain).
  • Left = True for binary nodes; label each arrow for non-binary ones.
  • Ex 4: max Gini for k=2 is ½. Ex 5: split by Feature1 — 0.67 vs 0.7313 vs 0.73.
  • Out of scope: Decision Tree Regression, neural networks. In scope: continuous features in a classification tree.

W8 · Bandits & action values

  • RL = learn by doing. k-armed bandit = k arms, each with its own reward distribution, maximise long-run average.
  • q⋆(a) = E[Rt | At = a] (8.2) — the true value, unknown. Stationary ⟹ drop the t (8.3).
  • Qt(a) (8.4) = average of rewards a paid on steps strictly before t. Q₁(a) = 0; 0 whenever N = 0.
  • 1predicate = 1 if true, 0 otherwise — it selects a's own steps in (8.4).
  • Incremental form: Q ← Q + (1/N)(R − Q). Same average, constant memory.
  • N(µ, σ²) is the variance. B ∼ N(11, 4) ⟹ σ = 2.
  • Exploit = take the current best. Explore = try something else in case an early sample was an outlier. No fixed definition of "too much".
  • Ex 1: q⋆(A)=10, q⋆(B)=11. Ex 2: Qt(A) = 0, 0.5, 0.1, 0.1, 0.4; Qt(B) = 0, 0, 0, 0.4, 0.4 (tie at t=5).

W8 · Selection methods

  • Random (8.4): Pr(At=ai) = 1/k, forever. Ex 4: k=50 → 0.02.
  • Greedy (8.5): At = arg maxa Qt(a), Q₁=0, ties randomised.
  • ε-greedy (8.6): random w.p. ε, greedy w.p. 1−ε. Ex 6: ε=0 → greedy, ε=1 → random.
  • Pr(greedy action) = 1 − ε + ε/k; Pr(specific other) = ε/k. Ties split the 1−ε.
  • Ex 5 (ε=0.5, k=2, optimal a₂): estimates point away 0.25 · tie 0.5 · point at it 0.75.
  • Fig 8.4: random ≈ 0 (arm values ~ N(0,1)); greedy stalls, stuck on the first positive arm; ε=0.1 leads at 500; ε=0.01 wins asymptotically by the law of large numbers — every arm sampled infinitely often for any ε>0, then the bigger ε just pays more to randomise.
  • Asymptote ≈ (1−ε)·q⋆(best) + ε·(mean arm); testbed q⋆(best) ≈ 1.54. Ex 7: ε=0.75 → ≈0.39 → between random and greedy.
  • % optimal ceiling for ε-greedy = 1 − ε + ε/k.

W8 · UCB

  • Why: ε-greedy explores uniformly — it wastes pulls on arms it already knows are bad.
  • (8.5)/(8.6): At = arg maxa [ Qt(a) + c√(ln t / Nt(a)) ].
  • Remark 8.8: N=0 ⟹ +∞ ⟹ maximising, so no Q₁ needed and the first k steps are a₁…ak in order. Ties → lowest index (greedy randomises — different rule!).
  • Terms: Q = exploitation · c = exploration parameter (a priori, data-independent) · c√(ln t/N) = exploration term ≈ uncertainty.
  • c ↑ ⟹ explore more. c = 0 ⟹ greedy. Common value √2; Ex 8 uses c = 2.
  • (8.7): √(ln t / t) → 0 — intervals shrink under repeated sampling. But ln t grows while N stays fixed, so a neglected arm's bound creeps back up.
  • Ex 8 (c=2): A₁…A₈ = a₁ a₂ a₃ a₃ a₁ a₁ a₁ a₂; UCB₈ = 6.1920 / 6.3841 / 5.0393. A₈ picks the worst Q because its interval is widest — Figure 8.5.
  • vs MDPs: the reward function is unknown (must be estimated), and there is only one state — richer RL needs q⋆(s, a).

W9 · Application & access

  • Five key questions: how applied / who has access / who benefits · what harms, who is harmed · how bias manifests and why · who is responsible · how to minimise. Use as headings.
  • Two columns: well-intentioned → “what are the hidden risks?”; fundamentally problematic → “should we even build this?”
  • Policing: breadth of surveillance · worse face recognition on minorities due to lack of data → wrongful arrests / stop-and-search · lack of accountability.
  • Military: targeting → bias into war, more deaths. Automated defense → dehumanization, loss of moral engagement, simplification of moral choices, easier escalation, arms races.
  • Political control: surveillance of opposition & minorities → authoritarianism, loss of privacy/speech/religious freedom · censorship & disinformation → polarisation, less informed citizens.
  • Phrenology: disproved pseudoscience predicting gender, intelligence, criminality, internal states from facial analysis. Revived by predicting gender/sexuality/race/emotion/criminality — but these are social constructs or unobservable; only the subjects can say.
  • Access: compute · GPUs · money to train and house · Big Tech monopoly → universities can't compete, poorer labs/countries excluded.

W9 · The seven harms

  • Order: human agency · accountability · safety and wellbeing · privacy · fairness and dignity · societal · environmental.
  • Agency: loss of control · loss of right to contest · over-delegation · loss of critical thinking.
  • Accountability: loss of accountability, or incorrect blaming of humans (warehouse workers blamed for robot mistakes).
  • Safety: physical safety · abuse & tech-facilitated violence · health · wellbeing.
  • Privacy by setting: intimate spaces · work & school · public spaces.
  • Fairness — allocative: opportunities · resources · quality-of-service. Representational: stereotyping · demeaning · erasing · alienating · loss of self-identification · essentialist categories.
  • Societal: information · cultural · civic and political · social relationships · deskilling. No identifiable individual victim — that's the test.
  • Environmental: energy & pollution · mineral mining for datacentres · AI for oil & gas.
  • Reparation (after): outcry · perpetrator communication (incl. denials) · investigation · legal action · legal repercussions · compensation · removal · discontinuation · design changes · law change.
  • Anticipation (before): quantitative measurement · ablation studies · qualitative (interviews, surveys, workshops, lit reviews, ethnography) · critique (speculation, argument).

W9 · Discrimination & bias

  • Direct = disparate treatment — disadvantaged because of a personal attribute.
  • Indirect = disparate impact — disadvantaged even though the attribute is not explicitly considered. Removing the attribute does not prevent it.
  • Bias, two senses: imbalance/tendency in data (input) · direct or indirect discrimination (output).
  • Five causes: world (world distribution) · representation (data collection) · measurement (wrong categorization/measurements) · algorithm (wrong algorithm) · evaluation (wrong metric or test set).
  • ★ Developer's fault: all except world bias.
  • Second branch (obvious risk, problematic task): ethics board doesn't flag · ★ developer doesn't oppose/report/whistleblow · management deploys.
  • ProPublica: more likely to mistakenly predict high-risk for Black than White defendants.
  • GPT-3 / DALL·E: “All white male” — representational (stereotyping, erasing).
  • Brandao 2019: age & gender bias in pedestrian detection miss rates.
  • Gender Shades (Buolamwini & Gebru 2018): Type VI error 46.5% (Face++), 46.8% (IBM), vs ~1–5% on Type I. Microsoft 0% (IV) → 25% (VI). Intersectional — one attribute at a time hides it.
  • Who finds these: women, Black scholars, LGBTQ → lived experience & diversity.

W9 · Mitigation & responsibility

  • Seven principles: human oversight & agency · safety & robustness · privacy · transparency · fairness · societal & environmental wellbeing · accountability. (Mirror the harms; transparency is the extra.)
  • Transparency = documentation/logging, explainability, informing when AI is used. Accountability = auditability, documenting how trade-offs were resolved, responsibility for harms.
  • Governance: regulations/standards/codes (safeguard present + constrain future) · internal AND external audit/verification/validation · “Trustworthy AI” = design AND governance.
  • Value alignment: technical (encode rules) and social (decide the values). Used in chatbots; important in game AI, credit scoring, Gen AI.
  • Bias mitigation: dataset curation (+ participatory design) · reweighting (weight more) · resampling (sample more often) · fairness functions (maximise minimum accuracy).
  • Privacy mitigation: anonymization (face blurring, text) · differential privacy — hides whether a person is in the dataset, by adding noise to computations.
  • Environmental: emission estimation (CodeCarbon) · smaller models.
  • Responsible: institution (allowing harms) · ethics board (passing it) · developers (best placed to anticipate, only ones able to test; also transparency, inefficiency, power).
  • Minimising: awareness · participatory design · team diversity · balanced datasets · testing with diverse groups · documentation · logging & explainability · ethics boards · whistleblowing (last — every other item assumes good faith).

Cross-cutting threads

  • "Search for good strategies" in the model-based bullet list is Parts 2–3. Classical AI = encode + search.
  • Optimal is always relative to something — fewest actions (BFS) vs cheapest (UCS) vs looks-closest (greedy).
  • Every trade is memory vs quality vs information — DFS buys memory with quality; A* buys expansions with a heuristic.
  • Relaxation is the general recipe for building heuristics: make the problem easier, use its cost as the estimate. Straight-line distance (W1) and the RPG's "ignore deletes" (W3) are the same trick twice.
  • Everything is still search. Minimax is a DFS. Backtracking is a DFS. Forward chaining is A*. Only the state and the successor rule change.
  • Fail first, cheaply. Alpha-beta's β ≤ α, forward checking's empty domain and the RPG's fixpoint are all the same move: prove a branch is dead before paying to explore it.
  • Heuristics cost something. W1's h was a lookup; W3's h is an entire sub-problem solved per node — worth it because the node saving is larger.
  • The reward function is the specification. Topic 01's value alignment problem, made numeric: R(s) = −1.65 quietly means "please die quickly".
  • When the world stops cooperating, the answer changes shape. Deterministic ⇒ a plan. Stochastic ⇒ a policy. Adversarial (W2) ⇒ a strategy that assumes the worst.
  • W1–4 are the model-based half; W5 is the data-driven half. Topics 1–4 all need you to write the world down first — that's what "without being explicitly programmed" rules out.
  • Guarantees give way to measurement. A*, alpha-beta, AC-3 and value iteration all come with proofs. Machine learning largely doesn't, so it substitutes held-out evaluation — which is why metrics and the train/validation/test split get two thirds of Topic 05.
  • Reinforcement learning is Topic 04 with the model taken away. Same rewards and policies; you're no longer given P(s′|s,a), so you must explore to find out.
