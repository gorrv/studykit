Topic 08 · Part 3 · Reinforcement Learning

Upper Confidence Bound

explore on purpose, not at random

What is wrong with ε-greedy

It explores stupidly

When ε-greedy decides to explore, it picks completely at random. Suppose you have three machines:

Q(a₁) = 1    Q(a₂) = 10    Q(a₃) = 100

You have pulled a₁ fifty times. You are certain it is bad. But when ε-greedy explores, a₁ is just as likely to be picked as anything else. That pull is wasted.

The fix, in one sentence
Explore the machines you are unsure about, not random ones.

To do that you need to track not just what you think a machine is worth, but how confident you are about it. And confidence has a simple proxy: how many times you have pulled it.

The figure

a₁ has the better estimate (Q = 6 against 4) but a narrow interval — we have pulled it a lot and we are confident. a₂ has been pulled barely at all, so its interval is wide and its upper end reaches 9. UCB picks a₂, because it might be much better than it currently looks.

Reading that picture

Each bar is a machine. The dot is its current average; the bar is how uncertain you are — wide means "barely tried it".

  • a₁ has the better average (6 vs 4), and a narrow bar. You have pulled it a lot and you trust the 6.
  • a₂ has a worse average but a very wide bar. You have barely tried it, so it could be much better than 4.

UCB judges by the right-hand end of the bar. a₂'s reaches 9, a₁'s only reaches 7 — so it takes a₂. Not because a₂ looks good, but because it might be good and you do not yet know.

And this cannot go on forever. Every time you pull a₂ its bar shrinks. Eventually it either proves itself, or its bar drops below a₁'s and you go back to a₁.

The rule

In words first
For each machine, add a bonus to its average. The bonus is big when you have not pulled it much. Then pull whichever total is highest.

That is the entire method. The formula just says how big the bonus is.

Definition 8.7
At = arg maxa [ Qt(a) + c √( ln t / Nt(a) ) ]
pieceis
Atthe machine you pull at step t. It is arg max, so the answer is a machine, not a number.
Qt(a)its average so far — the same running average from Part 1
Nt(a)how many times you pulled it before now
twhich step you are on overall
ca dial you set in advance — bigger c means more exploring

Because N is on the bottom of the fraction, a machine you have barely pulled gets a big bonus. Pull it more and the bonus shrinks.

Remark 8.8 — two rules you need before you can compute anything
  • If you have never pulled a machine, N = 0, and dividing by zero gives ∞. An infinite score always wins, so every machine gets tried once before any machine gets tried twice. A UCB trace therefore always starts a₁, a₂, a₃, … in order.
  • If two machines tie, take the lower-numbered one. a₁ beats a₂.

Careful: the greedy method breaks ties by randomising. UCB breaks them by lowest index. Two different rules in the same topic, and swapping them wrecks a whole trace.

One nice consequence: because N = 0 forces a pull, UCB needs no starting value for Q, unlike greedy.

The two halves

Computing ln t without a calculator

Most papers give you these or allow a calculator — but t is always small, so four numbers cover everything:

ln 2 = 0.693    ln 3 = 1.099    ln 5 = 1.609    ln 7 = 1.946

Everything else is those added together, because multiplying inside a log means adding outside it:

For the square root, bracket it. √1.386 sits between 1.1 (1.21) and 1.2 (1.44); try 1.18, whose square is 1.392. Two decimals is plenty.

And a shortcut that often saves the whole calculation: when every arm has the same N, the bonus is identical for all of them, so it cannot change the ranking — just compare the Q values. That is exactly what happens at t = 4 in Exercise 8.

One half is what you know, the other is what you don't
partnamewhat it is doing
Qt(a)exploitation termuse what you have learned
c √(ln t / Nt(a))exploration termreward machines you are unsure about
cexploration parameterhow much you care about being unsure

c is called a parameter because you choose it before you start and it never changes. Everything else in the formula is produced by playing.

c = 0 kills the bonus entirely, and UCB becomes the greedy method. A common choice is √2; Exercise 8 uses c = 2.

Why ln t is up there

The bonus has t on top and N on the bottom, so:

  • Pull a machine → N grows → its bonus shrinks. You are getting surer about it.
  • Ignore a machine → t keeps growing while its N stays fixed → its bonus slowly creeps up. Time passing makes old information less trustworthy.

That second point is why UCB can never abandon a machine forever. And because it is ln t rather than t, the creep is slow — otherwise UCB would just cycle through every machine in turn and never settle.

The notes also ask you to see that √(ln t / t) → 0: keep pulling the same machine and its bonus vanishes. A-level calculus is enough; no proof required.

How this relates to Topic 04

Two differences, and the lecture names both
Topic 04 · MDPsTopic 08 · Bandits
Rewardsgiven to you — you can compute the answer up frontunknown — you must estimate them by playing
Statesmany; where you are mattersonly one — after every pull you face the same choice again
You estimateU(s), a value per squareq⋆(a), a value per machine

Because there is only one state, some researchers hesitate to call bandits reinforcement learning at all. In a richer problem you would need q⋆(s, a) — a value for every state-and-action pair, not just every action. That single change is the bridge to everything beyond this course.

The chapter's own summary — each line is a complaint about the one before
  1. We have k actions and get rewards from our choices.
  2. Stick with whichever looks best.  → greedy
  3. But what if we were just unlucky with the others?  → ε-greedy
  4. But now we explore even the obviously bad ones.  → UCB
  5. And all of this has only one state.  → MDPs and beyond

Learn those five lines and you can rebuild the whole chapter.

Exam takeaways

What to have ready
  • Why UCB exists: ε-greedy explores at random, wasting pulls on machines it already knows are bad.
  • The rule: score = average + bonus; bonus is big when N is small; pull the highest score.
  • UCBt(a) = Qt(a) + c√(ln t / Nt(a)), and At is the arg max of it.
  • N = 0 gives ∞, so the first k steps are a₁ … ak in order, and no starting Q is needed.
  • Ties → lowest index. (Greedy randomises. Different rule.)
  • N counts pulls before now; ln t uses the current step. Mixing these up shifts every number.
  • c = 0 gives greedy. Bigger c explores more. Common value √2; Exercise 8 uses 2.
  • ln t on top means a neglected machine slowly becomes attractive again — UCB never abandons anything permanently.
  • vs MDPs: rewards unknown, and only one state, so we estimate q⋆(a) not q⋆(s, a).
  • Show a table — t, N, Q, bonus, total, arg max. Exercise 8 is marked on the working.
