Topic 01 · what security means

The two objects, as syntax

  • SKE = (KGen, Enc, Dec) over key space K, message space M, ciphertext space C.
  • sk ← KGen · c = Enc(sk, m) · m = Dec(sk, c). The arrow is there because key generation is random.
  • MAC = (KGen, Tag, Vf) with its own integrity key ik. τ = Tag(ik, m), and Vf returns 0 or 1.
  • Stating either triple says nothing about correctness or security. It is the shape, not the guarantee.

Correctness

  • c = Enc(sk, m) ⇒ m = Dec(sk, c). That is the whole obligation.
  • It is a statement about the scheme agreeing with itself, and is not a weak form of security.
  • The "do nothing" cipher is perfectly correct and perfectly useless.

The ladder, and what kills each rung

  • i key not recoverable → killed by the scheme that never uses the key.
  • ii messages not recoverable → killed by leaking the first letter.
  • iii partial messages not recoverable → killed by leaking statistics.
  • iv no further information inferable → the right intent, not yet formal.
  • v iv, even with chosen encryptions and decryptions → the one to aim at.

What a definition must say

  • What must not be possible — inferring further meaningful information about the messages.
  • Given what capabilities — observing only, or also encrypting and decrypting chosen inputs.
  • Change either half and it is a different claim. Nothing is "secure" without saying against whom.
  • This family of properties is confidentiality, or secrecy.

Breaking a shift cipher

  • A shift moves the letter counts along without changing them, so the counts identify the key.
  • Score each of the 26 shifts by χ² against English frequencies; the smallest wins.
  • Measured on a fixed passage: 10 letters → 83.7%, 20 → 98.6%, 30 → 100%.
  • Short messages are the only protection, and it runs out quickly.

The one-time pad

  • One uniform key letter per message letter, added letter by letter.
  • Perfect secrecy: for any message and any ciphertext there is exactly one key joining them, so every message stays exactly as likely as it was.
  • Not a computational claim — the information is absent, so no amount of work recovers it.
  • Costs: key as long as the message, never reusable, and no integrity at all.

Integrity

  • The assurance that what arrived is what was sent. A separate property from secrecy, achieved by separate means and a separate key.
  • The pad is the proof they are separate: Dec(k, c + d) = m + d. The attacker learns nothing and still chooses the message.
  • Engineering answers: indelible ink, no blank space, tamper-evident seals.
  • Cryptographic answer: a tag over the ciphertext under a second key, checked before decrypting.

Neither property covers these

  • Reordering, repeating, or reflecting valid ciphertexts and tags — each is genuine, so integrity is satisfied.
  • Delaying or denying delivery — generally network engineering rather than cryptography.
  • Every one of these needs its own sentence, with its own two halves.

The cast

  • Alice and Bob hold the keys.
  • Eve eavesdrops and nothing more — rung iv.
  • Charlie is active: chosen messages encrypted, chosen ciphertexts decrypted — rung v.
  • Eve is rarely a strong enough adversary to design against.

Topic 02 · games

Who may toss a coin

  • KGen randomised. Dec and Vf deterministic.
  • Enc and Tag potentially randomised — c ← Enc when they are, c = Enc when not.
  • Dec may output ⊥.
  • Randomness is just an extra input: c = Enc(sk, m; ρ), ρ ← R = {0,1}r.

Correctness, both objects

  • ∀ sk ∈ K, m ∈ M: Dec(sk, Enc(sk, m)) = m
  • ∀ ik ∈ K, m ∈ M: Vf(ik, m, Tag(ik, m)) = 1
  • Both satisfied by silly schemes — Enc(sk,m)=m, and a Vf that always says 1.

Canonical verification

  • Recompute τ′ = Tag(ik, m), output 1 iff τ = τ′.
  • Requires a deterministic Tag. With a randomised one a message has many valid tags, the verifier produces one, and rejects the rest — correctness fails.

Counting Enc

  • |M| = s, |C| = t, Encsk: M → C, Decsk: C → M ∪ {⊥}.
  • Functions: ts. Injective: C(t,s) · s!. If t = s: s! bijections.
  • Enc must be injective, so t ≥ s. Two messages sharing a ciphertext leave Dec one answer for two questions.

Kerckhoffs

  • Six requirements; the one that is quoted: the system must not require secrecy and may be stolen without causing trouble.
  • The key is the secret, not the design. Keys can be changed; designs cannot.
  • The forgotten four are about key handling, telegraphs, portability and ease of use.

The three IND games

  • All: C samples sk and a uniform b; A sends m0, m1 of equal length; A sees cb and names b′.
  • EAV no oracles · CPA adds OEnc · CCA adds ODec.
  • ODec returns ⊥ on cb only — otherwise the game is vacuous.
  • Equal lengths required because ciphertext length leaks message length.

EUF-CMA

  • OTag hands out tags and collects queries in Q.
  • A outputs (m′, τ′) and wins when Vf = 1 and m′ ∉ Q.
  • Existential: any new message counts. Ruling out the easiest forgery rules out the rest.

What secure means

  • IND-{EAV, CPA, CCA}: no efficient A wins noticeably more than one half. Half because you can always guess.
  • EUF-CMA: noticeably more than zero. Forging is creation, not a choice.
  • Efficient = PPT, probabilistic polynomial time. Noticeable = non-negligible, where negligible is eventually below every inverse polynomial.

What the games show

  • Deterministic Enc loses IND-CPA always: encrypt m0 at the oracle and compare.
  • A fresh key is not randomised Enc: a shift still sends aa to two equal letters.
  • Malleability loses IND-CCA: alter cb by one letter, have that decrypted, undo the change.
  • Why IND captures everything: any leak you can name distinguishes some pair, so no distinguishable pair means no leak.

Topic 03 · historical ciphers

Modular arithmetic

  • ℤ/nℤ = {0, …, n−1}. n = 26 historical, n = 2 modern.
  • Identity, inverses, commutative, associative.
  • ⊕ is addition mod 2, and a ⊕ a = 0.
  • Elementwise = schoolbook addition with no carries.

The three ciphers

  • Caesar one shift. |K| = 26. ci = mi + sk.
  • Substitution any permutation. |K| = 26! ≈ 288.4. Caesar's keys are a subset.
  • Vigenère repeating key of length j. |K| = 26 + … + 26n ≥ 26n. It is j Caesar ciphers interleaved.
  • Transposition rearranges rather than substitutes, so the letter frequencies are exactly the message's.

Why they all fail

  • Message-ciphertext pairs give the key.
  • Frequency analysis, directly or per column.
  • Enc is deterministic — the fundamental one, and the one a bigger key space does nothing about.
  • None of this is needed: pick m0, m1 of equal length and win IND-EAV. These attacks are the minimum any scheme must resist.

Brute force

  • Search K, keeping k with Dec(k, ci) = mi for all pairs.
  • Uses Dec, not Enc, because Enc may be randomised and re-encrypting need not reproduce c.
  • Needs known pairs, or enough context to recognise a plausible message.

Frequency analysis

  • e 12.7%, t 9.1%, a 8.2%, o 7.5%, i 7%.
  • Also first letters of words, and letter pairs.
  • Vigenère: find the key length first, split into c1c1+j…, attack each column as a Caesar cipher.
  • A longer key is not stronger — it just thins each column, so you need more ciphertext.

The trace

  • The gaps between consecutive letters: trace(hello) = (23, 7, 0, 3).
  • A shift moves both letters equally, so the trace is unchanged.
  • c decrypts to m iff trace(c) = trace(m). So hunt for the traces of likely words — no keys tried.

Perfect secrecy

  • The ciphertext carries no information except length. Every message of that length is equally likely.
  • For each message there is a unique key reaching a given ciphertext — and keys are uniform.
  • Binary version = the one-time pad (Miller–Vernam–Mauborgne), c = m ⊕ sk.

And what it costs

  • |K| ≥ |M|: key at least as long as the message.
  • Single use. Reuse gives c2 − c1 = m2 − m1 — the key cancels.
  • Key distribution is the hard problem, so you want small keys and large messages. This gives the opposite.
  • Real uses exist where a key can be hand-delivered and used once.

Topic 04 · block ciphers

The object

  • F : {0,1}n × {0,1}ℓ → {0,1}ℓ, n the key length, ℓ the block length.
  • Fsk(·) is a permutation for every key. That is the definition, not a consequence.
  • Goal (*): for uniform sk, behave like a uniform permutation.
  • Not an SKE and not a MAC — a building block for both.

Why the key cannot be the permutation

  • |Perm({0,1}ℓ)| = (2ℓ)!: 2, 24, 40320 for ℓ = 1, 2, 3; about 24.31×1040 at ℓ = 128.
  • Writing one down takes ℓ · 2ℓ bits.
  • So n stays small and the permutation is built from the key.

SPN

  • Per round: XOR the round key → S on each sub-block → P on the indices.
  • S : {0,1}ℓ′ → {0,1}ℓ′, P : {1..ℓ} → {1..ℓ}. Both public.
  • No S and no P in the final round — they are public, so after the last key they add nothing.
  • S and P must be permutations: inverting uses S−1 and P−1.
  • It is a permutation because a composition of permutations is one.

Feistel

  • Li = Ri−1, Ri = Li−1 ⊕ fi(ski, Ri−1).
  • Inverting: Ri−1 = Li, then Li−1 = Ri ⊕ fi(ski, Ri−1).
  • f need not be invertible — or injective, or anything. It is recomputed, never undone.
  • Decryption is the same circuit with the round keys reversed.

Confuse and diffuse

  • S confuses — mixes up a small sub-block.
  • P diffuses — spreads that mixing across the whole block.
  • Rounds buy diffusion: one round cannot move a flipped bit beyond the positions one P reaches.
  • Designing S and P, choosing r, and deriving round keys are all hard problems in their own right.

PRP security

  • Challenger samples uniform b and sk. b = 0 → oracle is F(sk, ·); b = 1 → a uniform permutation.
  • Secure if no efficient adversary names b noticeably better than one half.
  • The uniform permutation is lazily sampled — answers chosen as they are asked for.
  • Compared against a uniform permutation, not a uniform function.

DES

  • Feistel network, n = 56, ℓ = 64, r = 16. Refined from IBM's LUCIFER.
  • 56-bit key is brute-forceable, hence Triple DES in legacy systems.
  • Withdrawn January 2024 — all variants disallowed. AES replaces it.

What the monoalphabetic cipher got right

  • Its key is a permutation, and sk(a), sk(b) are almost independent.
  • Almost: knowing π(xi) = xj says nothing about π(xk) except that it is not xj.
  • What it got wrong: pairs leak the key, and Enc is deterministic so IND-CPA is impossible.
