Topic 03 · Historical Ciphers

Three Fixes, None of Them a Definition

modular arithmetic, Caesar to Vigenère, the attacks that caught them, and what perfect secrecy costs

Three ciphers, each invented to patch the flaw in the one before. All three fall, and the interesting part is how they were approached: find a weakness, add complexity, hope. No definition was ever targeted, so there was never a moment at which any of them could be said to have failed. The last section of the topic is the opposite of that — a scheme with a proof, and a bill to go with it.

Arithmetic that wraps around

Z/nZ
If ℤ = {…, −2, −1, 0, 1, 2, …} are the integers, then the integers modulo a positive n are 
ℤ/nℤ = {0, 1, …, n − 1}
Adding and subtracting work as they do in ℤ, except that they wrap. With n = 5: 1 − 4 = 2, 2 + 2 = 4, 3 + 4 = 2.
The four properties, and the two values of n that matter
identityx + 0 = 0 + x = x — a zero that does nothing
inversesx − x = 0 — adding and subtracting the same value cancel
commutativex + y = y + x — order does not matter
associative(x + y) + z = x + (y + z) — bracketing does not matter

n = 26 for historical ciphers, with a ↔ 0, b ↔ 1, …, z ↔ 25. n = 2 for contemporary ones, where addition has its own symbol: ⊕, with 0⊕0 = 1⊕1 = 0 and 1⊕0 = 0⊕1 = 1. The same four properties hold, and a ⊕ a = 0 is the one worth remembering.
Elementwise: schoolbook addition with no carries
  01000101          hello
⊕ 01110110        − abcde
  00110011          hdjik
Every position is its own little sum, and nothing moves between columns. That independence is why these ciphers are easy to describe — and, as the attacks below show, why they are easy to take apart one column at a time.

Caesar

The whole scheme
K = {0, 1, …, 25}, M = C = {a, …, z}*.
KGensample a uniform sk from K
Enc(sk, m)for each i, ci = mi + sk mod 26
Dec(sk, c)for each i, mi = ci − sk mod 26

Caesar's own favourite key is said to have been d ↔ 3. Sampling a uniform key from 26 possibilities is five coin flips — with a retry, since 32 does not divide evenly by 26.

Monoalphabetic substitution

An arbitrary permutation instead of a shift
K = Perm(α), M = C = α*. A permutation is a bijection from a set to itself; Enc applies it letter by letter and Dec applies its inverse — the same table read bottom to top. 
a  b  c  …  y  z
f  b  z  …  a  v
|K| = |α|! = 26! ≈ 288.4, against Caesar's 26. The keys of the Caesar cipher are themselves permutations, so Caesar's key space is a subset of this one.

Vigenère

A different shift per position, from a repeating key
K = α ∪ α2 ∪ … ∪ αn, M = C = α*. With a key of length j: ci = mi + ski mod j. 
   m₁   m₂   m₃   m₄   m₅   m₆   m₇
+  sk₁  sk₂  sk₃  sk₄  sk₁  sk₂  sk₃
   c₁   c₂   c₃   c₄   c₅   c₆   c₇
That is four distinct Caesar ciphers interleaved, and |K| = 26 + 262 + … + 26n ≥ 26n.

The pattern, and why it is the wrong pattern
Caesar's key space is tiny, so substitution makes it enormous. Substitution still leaks frequencies, so Vigenère spreads them over several alphabets. Each step fixes the flaw that was noticed and leaves the rest.

This is unprincipled: it finds a flaw, adds complexity, and relies on being cleverer than whoever is attacking. No security definition is targeted, so nothing is ever achieved — and nothing can be declared broken either, because there was no claim to break. What is wanted instead: if a well-defined problem is hard, then this object satisfies this definition of security. Then spend the effort on checking the proof and on measuring how hard the problem really is.
A different family: transposition
Instead of changing the letters, rearrange them — the key says how. The rail fence cipher writes the message in a zigzag across several lines and reads it off row by row. The letters are all still there, which is its own kind of weakness: the letter frequencies of the ciphertext are exactly those of the message.

Taking them apart

None of this is needed to call them insecure
Every cipher above falls immediately to the definitions of the previous topic: pick m0 and m1 of the same length that are distinguishable from cb; or note that a message-ciphertext pair reveals the key; or that access to Enc(sk, ·) recovers it outright; or simply that Enc is deterministic.

The attacks below matter for a different reason: any scheme must resist them as a bare minimum before IND-EAV, IND-CPA or IND-CCA is even worth discussing.
Brute force
input: message-ciphertext pairs {(mᵢ, cᵢ)}
for k in K:
    for i in 1..N:
        if Dec(k, cᵢ) ≠ mᵢ: try the next k
    return k
Two things to notice. It needs a way to recognise a wrong guess — either known pairs, or enough context to say that a candidate message is not plausible English. And it runs Dec on the ciphertexts, not Enc on the messages: Enc may be randomised, in which case re-encrypting a known message need not reproduce the ciphertext, and the right key would be thrown away.
Frequency analysis
Assume the messages are English and the cipher does not remove that structure from the ciphertext. Then e, t, a, o, i at roughly 12.7%, 9.1%, 8.2%, 7.5%, 7% give you a handle; so do first letters of words, and pairs of letters. It needs enough ciphertext — and surprisingly little.

Direct against Caesar and against substitution. Against Vigenère you must first find the key length j, split the ciphertext into c1c1+jc1+2j… and so on, and attack each of those as its own Caesar cipher.

The trace: Caesar's extra weakness

The gaps survive
Take the differences between consecutive letters of a word. 
hello:  h→e = −3 = 23,  e→l = 7,  l→l = 0,  l→o = 3
trace(hello) = (23, 7, 0, 3)
A shift moves every letter by the same amount, so every difference is unchanged. Enc(1, hello) = ifmmp, and trace(ifmmp) = (23, 7, 0, 3) too.

A ciphertext can decrypt to a message exactly when the two share a trace. So you can hunt for the trace of a likely word — the, hello, attack — without trying a single key.

Perfect secrecy, and the bill

The scheme
K = {0, …, 25}n and M = C = {a, …, z}≤n. Sample a uniform sk; add it letter by letter; subtract it to decrypt. No element of sk may ever be used twice, so the key is at least as long as the message.

The binary version, modulo 2, is the one-time pad (Miller–Vernam–Mauborgne): K = {0,1}n, c = m ⊕ sk.
What the claim actually says
The ciphertext carries no information about the message except its length. Any message of that length could have produced it, and each is equally likely. Take c = aaaaaaa: leopard could have produced it, and so could caracal, lioness, cheetah and panther — each under exactly one key, each sampled with the same probability.

Two messages, one key
c₂ − c₁ = (m₂ + sk) − (m₁ + sk) = m₂ − m₁
The key cancels. Anyone watching now has the difference of two secret messages without having either, and guessing one gives the other outright. This is not a weakening of the one-time pad; it is a different scheme, and that one has no argument behind it at all.

Where this leaves us
Perfect secrecy is achievable and brittle. It has real uses where the key can be delivered by hand and used once — the Washington–Moscow hotline being the standard example — and a long history of catastrophic failure wherever the single-use rule was bent.

The deeper problem is the shape of the bill. Key distribution is hard, so what is wanted is a small key and large messages. Perfect secrecy requires the exact opposite, and no cleverness will change that: it follows from |K| ≥ |M|, which follows from the uniqueness that made it perfect.

Takeaways

If you remember seven things
  1. Z/nZ with n = 26 for historical, n = 2 for modern. Identity, inverses, commutative, associative. a ⊕ a = 0.
  2. Caesar: one shift. |K| = 26. Substitution: any permutation, |K| = 26! ≈ 288.4. Vigenère: a repeating key, |K| ≥ 26n.
  3. Every one of them is deterministic, which is the fundamental failure — and the one a bigger key space does not touch.
  4. Brute force uses Dec, not Enc, because Enc may be randomised.
  5. Vigenère is broken per column: find the key length, split the ciphertext, attack each part as a Caesar cipher.
  6. The trace is the gaps between letters, and a shift leaves it alone. c decrypts to m iff they share a trace.
  7. Perfect secrecy forces |K| ≥ |M|, a single-use key, and a key at least as long as the message. Reuse leaks m2 − m1.
Things that catch people out
  • Thinking 26! is a large enough key space to matter. It is, against brute force alone — and the cipher still falls to frequency counting, which never touches the key space.
  • Calling Vigenère "polyalphabetic and therefore strong". It is j Caesar ciphers, and finding j is the only extra work.
  • Believing a longer Vigenère key is fundamentally stronger. It only thins out each column, so you need proportionally more ciphertext.
  • Writing brute force with Enc. Fine for these ciphers, wrong in general.
  • Thinking the one-time pad's problem is that it is slow. It is perfectly secret and provably so; the problems are key length, single use, and no integrity.
  • Treating key reuse as "a bit less secure". It leaks the difference of the messages exactly, to anyone watching.
