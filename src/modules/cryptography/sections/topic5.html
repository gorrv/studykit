Topic 05 · Modes of Operation

Using the Thing You Built

ECB, CBC and counter mode, CBC-MAC, Encrypt-then-MAC, and AES

A block cipher encrypts one block. Messages are not one block. The ways of bridging that gap are the modes of operation, and the gap is where the security goes: a perfect block cipher used in the wrong mode gives a scheme that loses IND-CPA every single time. The last part of the topic puts an SKE and a MAC together in the one order that works, and names the cipher everything actually uses.

Suppose F were perfect

What perfect would mean
  • Inverting F costs about 2n — brute force is the best attack there is.
  • On a uniform sk, Fsk cannot be told from a uniform permutation. That is PRP security, and it is the one we take as the definition.

Given that, we can build secure SKE and secure MAC. The whole of this topic is how — and every security claim in it will reduce to "is F a good block cipher, with a large enough ℓ".
Follow your nose, and see where it goes wrong
The obvious attempt: Enc(sk, m) = Fsk(m), Dec(sk, c) = Fsk−1(c). That handles exactly one block. For longer messages: pad unambiguously to a multiple of ℓ, then encrypt block by block.

That second step is a mode of operation — the simplest one, and the one that does not work.

Electronic Code Book

ECB
M = C = ⋃j {0,1}jℓ, K = {0,1}n. Parse m = m1 … mt into blocks, and for each i: 
cᵢ = F(sk, mᵢ)          mᵢ = F⁻¹(sk, cᵢ)
Correct, parallel, simple, and completely insecure.
Two attacks, and the second needs no oracle
With the encryption oracle. Pick distinct m0, m1 of equal length. Learn c0 = Enc(sk, m0) and c1 = Enc(sk, m1). They are distinct, and the challenge cb equals one of them. Done.

Without one. Let m0 be a block repeated twice and m1 be two different blocks. Equal plaintext blocks give equal ciphertext blocks, so look.

The fundamental problem: Enc(sk, ·) cannot be allowed to be deterministic.

Probabilistic encryption

Randomness as an input, and what it costs
A function f : X → Y has no notion of randomness, so it is supplied: R = {0,1}p, f : X × R → Y, and the random coins ρ are sampled uniformly for each call.

Two consequences:
  • encrypting the same message twice should give different ciphertexts;
  • therefore, to still be decryptable, |C| > |M| — ciphertexts are necessarily longer than messages.

Cipher Block Chaining

CBC
The first thing Enc does is sample a uniform IV. 
c₀ = IV                  mᵢ = cᵢ₋₁ ⊕ F⁻¹(sk, cᵢ)
cᵢ = F(sk, cᵢ₋₁ ⊕ mᵢ)
and the ciphertext is c0 c1 … ct — one block longer than the message.

Encryption is sequential: each block needs the previous ciphertext. Decryption is parallel, and needs the IV.

Secure: if F is a good block cipher and ℓ is large enough, CBC is IND-CPA secure (Bellare–Desai–Jokipii–Rogaway, FOCS 1997).

Counter mode

Count, do not chain
Sample a uniform IV of 3ℓ/4 bits. 
c₀ = IV                  mᵢ = cᵢ ⊕ F(sk, IV‖i)
cᵢ = F(sk, IV‖i) ⊕ mᵢ
IV∥i is the IV with the counter appended. With ℓ = 8 and IV = 110111: IV∥1 = 11011101 and IV∥2 = 11011110.

Both directions are parallel, and — the striking part — F is never inverted, so it does not have to be a permutation at all.

Secure on the same condition, plus one more: no F(sk, IV∥i) may ever repeat. For large ℓ and messages of fewer than 2ℓ/4 blocks, a repeat has exponentially small probability.

CBC-MAC

A MAC from the same block cipher
M = {0,1}tℓ, T = {0,1}ℓ, K = {0,1}n. 
τ₀ = 0^ℓ
τᵢ = F(ik, τᵢ₋₁ ⊕ mᵢ)
τ  = τ_t          ← the last one only
Verification is canonical: recompute and compare. Both Tag and Vf are necessarily sequential, and like counter mode this never inverts F.

Secure: EUF-CMA for fixed-length messages (Bellare–Kilian–Rogaway, 2000).
Compare with CBC, because the differences are the security
  • No IV — or rather, the IV is fixed at 0ℓ.
  • No intermediate tags. Only τt is output.
  • Fixed-length messages only.

Relax any one of those three and CBC-MAC is not EUF-CMA secure. The tool below does each in turn.

Putting them together

Encrypt-then-MAC
Given an IND-CPA secure SKE, an EUF-CMA secure MAC, and CSKE ⊆ MMAC:
KGen′sk ← KGenSKE, ik ← KGenMAC, return (sk, ik)
Enc′c ← Enc(sk, m), τ = Tag(ik, c), return (c, τ)
Dec′if Vf(ik, c, τ) = 0 return ⊥, else return Dec(sk, c)

Theorem (Katz–Lindell 5.7). The result is IND-CCA secure. The tag is on the ciphertext — the thing that actually travels — and it is checked before anything is decrypted.

The other two orders, Encrypt-and-MAC and MAC-then-Encrypt, do not generically give IND-CCA.

The Advanced Encryption Standard

Where it came from
NIST announced an open competition in January 1997 to replace DES. Fifteen algorithms were submitted by international teams across academia and industry; three workshops were held in 1998, 1999 and 2000, and after the second the field was cut to five finalists. Rijndael, by Vincent Rijmen and Joan Daemen, was selected — secure and fast.
The parameters
AES is a substitution-permutation network.
block lengthℓ = 128 for all three variants
sub-blockℓ′ = 8 — the S-box acts on bytes
key lengthn ∈ {128, 192, 256}, giving AES-128, AES-192, AES-256
roundsr ∈ {10, 12, 14} respectively — the rounds are otherwise identical, and only the key schedule differs
the state128 bits = 16 bytes, held as a 4×4 square

P is two steps: ShiftRows acts on the rows of the square, then MixColumns multiplies the columns by a fixed matrix. Together they are the permutation; AddRoundKey lays the round key out as a square and XORs it; SubBytes is S.
So what
AES-128 is usually the answer to "which block cipher should I use?". The best known brute force costs about 2126 even allowing 256 memory, and TLS 1.3 — the backbone of the internet — permits almost exclusively AES modes for authenticated encryption. The full specification is NIST's FIPS-197.

Takeaways

If you remember eight things
  1. ECB: ci = F(sk, mi). Deterministic, so it loses IND-CPA — and loses IND-EAV too, because equal blocks give equal ciphertext.
  2. Enc must be probabilistic, with randomness as an explicit input, and therefore |C| > |M|.
  3. CBC: c0 = IV, ci = F(sk, ci−1 ⊕ mi). Sequential to encrypt, parallel to decrypt, needs F−1.
  4. Counter: ci = F(sk, IV∥i) ⊕ mi. Parallel both ways, and never inverts F — the IV is 3ℓ/4 bits and messages must be under 2ℓ/4 blocks.
  5. CBC-MAC: τ0 = 0ℓ, chain, output only τt. Secure for fixed-length messages only.
  6. Its three rules are load-bearing: no IV, no intermediate tags, fixed length. Relax any one and there is a one-query forgery.
  7. Encrypt-then-MAC gives IND-CCA from an IND-CPA SKE and an EUF-CMA MAC. The other two orders do not, generically.
  8. AES: an SPN with ℓ = 128, ℓ′ = 8, n ∈ {128,192,256}, r ∈ {10,12,14}. GCM is the mode everything uses.
Things that catch people out
  • Blaming ECB's failure on the block cipher. F could be a perfect PRP and ECB would still lose every round. The mode is the fault.
  • Forgetting the IV is part of the ciphertext and must be sent. It is not secret, but it is required.
  • Thinking counter mode needs an invertible F. It never inverts anything — nor does CBC-MAC.
  • Treating counter mode's block limit as a formality. Past 2ℓ/4 blocks the keystream repeats, and a repeated pad leaks the difference of the messages.
  • Using CBC-MAC on variable-length messages. One query forges, and the fix is to bind the length in.
  • Assuming the composition order is a matter of style. Encrypt-and-MAC loses IND-CPA — a property both components had separately.
  • Saying DES and AES are both SPNs. DES is a Feistel network; AES is the SPN.
