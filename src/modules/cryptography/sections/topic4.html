Topic 04 · Block Ciphers

Building a Permutation You Can Afford

substitution-permutation networks, Feistel networks, and what PRP security asks for

The historical ciphers failed for want of a definition. But one of them had a good idea buried in it, and this topic digs it out: the monoalphabetic cipher's key is a permutation, and that is the right shape. The problem is the bill — writing a permutation down costs more than any key can carry — so the rest of the topic is two ways of building a big permutation out of a small key.

What went wrong, and what went right

Wrong
The historical ciphers were ad hoc, with no definition to satisfy: one message-ciphertext pair is often devastating, meaningful information about messages is easy to infer, and the whole enterprise was an arms race of adding complexity.
Right
Recall the monoalphabetic cipher: K = Perm(α), and Enc applies the permutation letter by letter. It has a genuinely good property — sk(a) and sk(b) are almost independent.

Almost: knowing π(xi) = xj tells you nothing about π(xk) for k ≠ i — except that it is not xj, since a permutation cannot send two things to the same place.
Its two weaknesses, and which one matters more
  • Message-ciphertext pairs say far too much about sk. Learn that sk(a) = f and the key space drops by a factor of 26.
  • Enc is deterministic, so IND-CPA security is impossible — no amount of improvement to the permutation changes that.

Which suggests the plan for everything that follows: use a well-designed permutation as a subroutine inside a randomised procedure.

Permutations, and why a key cannot be one

Counting them
For a finite set X with t elements, a permutation is a bijection π : X → X, and |Perm(X)| = t! = t × (t−1) × … × 1.

Now take X = {0,1}ℓ, so t = 2ℓ: 
|Perm({0,1}^ℓ)| = (2^ℓ)!

ℓ = 1 → 2      ℓ = 2 → 24      ℓ = 3 → 40320      ℓ = 128 → ≈ 2^(4.31×10⁴⁰)
Writing one down takes about ℓ · 2ℓ bits.

Block cipher
A block cipher is a function 
F : {0,1}ⁿ × {0,1}^ℓ → {0,1}^ℓ
with n the key length and ℓ the block length, such that for every key sk the function Fsk(·) = F(sk, ·) is a permutation of {0,1}ℓ.

What is wanted, written (*): for a uniform sk, Fsk should behave like a uniform permutation. Not be one — behave like one, to anyone who cannot afford to look at all of it.

Why not just let sk name a permutation? Because n ≈ ℓ · 2ℓ, which the tool above puts a number on.

Substitution-permutation networks

Shannon's idea: many small permutations, repeated
  • Split the block of length ℓ into sub-blocks of length ℓ′ and apply a permutation of binary strings to each — the substitution, S : {0,1}ℓ′ → {0,1}ℓ′.
  • Apply a permutation of the indices across the whole block — the permutation, P : {1, …, ℓ} → {1, …, ℓ}.
  • Repeat for r rounds.

Shannon's name for it: confuse and diffuse. S mixes up a small block; P spreads that mixing across the whole thing.
A worked round, with ℓ = 8 and ℓ′ = 4
With m = 0110 0111 and the tables 
S:  0000 0001  …  0110 0111  …
    0100 0011  …  0101 1110  …

P:  1 2 3 4 5 6 7 8
    2 6 5 1 3 4 7 8
Apply S to each half: S(m) = S(0110) ∥ S(0111) = 0101 1110. Then move the bit at index i to index P(i): P(S(m)) = 1011 0110.
Where the key goes
S and P are public. The key enters by being XORed in, one round key per round: 
m⁽⁰⁾ = m
m⁽¹⁾ = P(S(sk₁ ⊕ m⁽⁰⁾))
m⁽²⁾ = P(S(sk₂ ⊕ m⁽¹⁾))
   …
m⁽ʳ⁾ = sk_r ⊕ m⁽ʳ⁻¹⁾        ← no S and no P in the final round
How the round keys sk1, …, skr are derived from sk is the key schedule.

The final round skips S and P because they are public: applying them after the last key adds nothing an adversary could not simply undo.
It is a permutation for every key, two ways to see it
  • XOR with a fixed string is a permutation; S is a permutation; P is a permutation. A composition of permutations is a permutation, so each round is one, so any number of rounds is one.
  • Or: F(sk, ·) is an invertible function whose domain and codomain are the same finite set, which is the same thing.

The hard parts, which are genuinely hard
How should S and P be designed? How many rounds r? How should the round keys be derived? These need finite fields, discrete probability, linear and differential cryptanalysis, and lower bounds on round counts. The constructions are simple; choosing their parts is not.

Feistel networks

A different way to the same goal
Due to Horst Feistel at IBM. Split the block in half, m = L0 ∥ R0, and take round functions fi : {0,1}n′ × {0,1}ℓ/2 → {0,1}ℓ/2. Then each round is 
Lᵢ = Rᵢ₋₁
Rᵢ = Lᵢ₋₁ ⊕ fᵢ(skᵢ, Rᵢ₋₁)
and the output is Fsk(m) = m(r).
Inverting it — follow your nose
Given ski and m(i) = Li ∥ Ri: 
Rᵢ₋₁ = Lᵢ                        ← it was copied across untouched
Lᵢ₋₁ = Rᵢ ⊕ fᵢ(skᵢ, Rᵢ₋₁)        ← recompute f and XOR it away
Nowhere is fi⁻¹ needed. Unlike an SPN, the round functions do not have to be permutations — they do not even have to be injective. Inverting a round is the same operation as performing one, with the index decremented.

DES
The Data Encryption Standard is a Feistel network with n = 56, ℓ = 64, r = 16, refined from IBM's earlier LUCIFER. A 56-bit key is now brute-forceable, which is why Triple DES appears in legacy systems.

All DES variants were withdrawn from the standard in January 2024 and are disallowed. The replacement, AES, is the subject of the next topic.

What security are we actually asking for?

A block cipher is not an SKE and not a MAC
It is a building block for both. The IND-CPA security of an SKE built from one, or the EUF-CMA security of a MAC built from one, will depend in part on the security of the block cipher — but the block cipher has its own definition, and this is it.
PRP — pseudorandom permutation
The challenger samples a uniform bit b and a uniform sk.
  • b = 0: the adversary gets oracle access to F(sk, ·).
  • b = 1: it gets a uniform permutation π : {0,1}ℓ → {0,1}ℓ.
The adversary queries whatever it likes and outputs b′. F is PRP secure if no efficient adversary guesses b with probability noticeably different from one half.

The uniform permutation is realised by lazy sampling: an answer is chosen uniformly the first time each input is asked about, and remembered after that. Nobody writes out a table of size 2ℓ.

Takeaways

If you remember seven things
  1. A block cipher is F : {0,1}n × {0,1}ℓ → {0,1}ℓ with Fsk a permutation for every key. n is the key length, ℓ the block length.
  2. |Perm({0,1}ℓ)| = (2ℓ)! and writing one down takes ℓ · 2ℓ bits, which is why the key names a construction and not a permutation.
  3. SPN: per round, XOR the round key, apply S to each sub-block, apply P to the indices. No S or P in the final round.
  4. An SPN needs S and P to be permutations, because inverting uses S⁻¹ and P⁻¹.
  5. Feistel: Li = Ri−1, Ri = Li−1 ⊕ fi(ski, Ri−1) — and f need not be invertible, because inverting recomputes it rather than undoing it.
  6. Confuse and diffuse. S mixes a small block, P spreads it. Rounds buy diffusion.
  7. PRP security: no efficient adversary tells F(sk, ·) from a uniform permutation with probability noticeably different from one half.
Things that catch people out
  • Thinking a block cipher is an encryption scheme. It is deterministic and keyless-looking from the outside; building an IND-CPA secure SKE from one takes more work, and is the next topic's problem.
  • Applying S and P in the final SPN round. They are public, so they add nothing after the last key.
  • Assuming Feistel round functions must be invertible. They need not even be injective — the structure provides the invertibility.
  • Confusing P, a permutation of indices across the block, with S, a permutation of values within a sub-block.
  • Reading PRP as "the output looks random". It is a statement about indistinguishability from a uniform permutation — which is itself far from a uniform function, since permutations never collide.
  • Forgetting that n and ℓ are independent. DES has n = 56 and ℓ = 64.
