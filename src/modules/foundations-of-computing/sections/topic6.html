Halfway, and What Holds It Together

no new material — the through-line, an audit, and a drill

Week 6 is the revision week, so there is no sixth lecture and nothing new below. What there is instead: the argument that runs through the first five topics, said once as a whole; a tool that re-checks each topic's central claim on freshly generated instances; and a drill that mixes questions from all of them and keeps a separate score per area, so that “revise” turns into a list rather than a mood.

The argument so far

Read as five separate topics it is a lot of definitions. Read as one argument it is short. Topic 1 asks what a machine can decide at all, and finds a ceiling: finite automata cannot count, and Turing machines cannot decide halting. Topic 2 keeps only the problems that are decidable and asks what they cost, which produces P, NP, and the reduction as the tool for comparing two problems' difficulty without solving either. Topic 3 takes the problems that are cheap and gets better at them — divide and conquer, and the Master Theorem as a way of reading a recurrence's answer off its shape. Topic 4 is that machinery applied to graphs, where the algorithms are the ones you will actually use. Topic 5 goes back to the hardest problem in Topic 2, SAT, and asks what to do when a problem is NP-complete but you need an answer anyway — which is where the module stops being about classification and starts being about tactics.

The one-line version of each topic
01What can be decided Some languages need unbounded memory; some need more than any machine has.
02What it costs P, NP, and reductions — comparing difficulty without solving anything.
03Doing the cheap ones faster Divide and conquer, recurrences, and reading the answer off a/b/f.
04The same, on graphs Search, spanning trees, topological order, strong connectivity.
05Coping with the hard ones DPLL, and the tractable islands: 2SAT and Horn clauses.
The joins, which is where the marks are
Almost every hard exam question in this module lives on a boundary between two topics, not inside one.

1 → 2. A decision problem is a language; a machine deciding it in polynomial time is what P means. The two topics use the same objects.
2 → 3. Cook–Levin says SAT is NP-complete, which is what makes every later reduction possible — you reduce from SAT because SAT is the one already known to be hard.
2 → 5. SAT ≤ₚ CLIQUE and SAT ≤ₚ 3SAT are the same technique in two directions: rewrite the instance, preserve the answer, keep it polynomial.
4 → 5. 2SAT is in P because of Topic 4: build the implication graph and run strongly connected components on it. A formula is unsatisfiable exactly when some P and ¬P land in the same component. The 2SAT tool in this module literally calls Topic 4's sccFind.
3 → 4. The complexity of BFS, DFS, Kruskal and Prim is stated as T(|V|, |E|), and reading those bounds is Topic 3's skill applied to Topic 4's algorithms.

Does it all still hold?

Every claim below is checked by two engines that share no reasoning — a construction against exhaustive testing, an algorithm against brute force, a theorem against the thing it is a theorem about. Instances are generated fresh each time you press the button, so a claim that survives twenty rounds has survived twenty inputs nobody chose.

What a green row does and does not mean
It means the claim held on some small random instances, decided twice. It is evidence, not a proof, and the difference matters in this module more than most: Topic 7's whole point is that an approximation ratio holds only if it holds for every input, so no number of agreeing examples establishes one. Examples are good for the opposite job — a single disagreement refutes. Use the audit to catch things that are broken, never to conclude that something is right.

A way to spend the week

The definitions that must be automatic
These are the ones that appear as bookwork marks, where there is no partial credit for the gist: the five-tuple for a DFA, an NFA and a Turing machine; the definition of P and of NP; what it means for A ≤ₚ B; NP-hard versus NP-complete; the three cases of the Master Theorem; the definition of a strongly connected component; and what unit propagation and pure literal elimination each do. Write them from memory, then check them against the cram sheet — not the other way round, which only ever produces the feeling of knowing them.
The mistakes this module's tools were built to catch
  • Using the pumping lemma to prove a language is regular. It cannot; it only refutes.
  • Getting a reduction backwards. To show B is hard you reduce a known-hard A to B, not B to A.
  • Applying the Master Theorem when f is not polynomially separated from nlog_b a — Case 2 has conditions, and there is a gap where no case applies.
  • Claiming a DFS finishing order is a topological sort of a graph that has a cycle. It is a finishing order; the sort only exists for a DAG.
  • Believing a satisfying assignment because the algorithm returned one. Check it against the clauses — a 2SAT bug can produce a well-formed assignment that satisfies nothing.
  • Saying NP-complete where the argument only gives NP-hard.
If you have three sessions
One. Write the definitions out cold, then run the drill above until every bar has something in it. You are looking for which bar is shortest, not for a good score.

Two. Take the worst area and do it by hand — not by re-reading. Run the relevant tool, copy the instance it gives you, work it on paper, then compare. The tools show every intermediate step precisely so that you can find the step where you and they part company.

Three. Do the joins: state Cook–Levin, do a SAT ≤ₚ CLIQUE reduction on a small formula by hand, and build one implication graph for a 2SAT instance. Those three cover the boundaries where the harder questions live.
