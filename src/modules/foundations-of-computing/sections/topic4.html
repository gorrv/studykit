Topic 04 · Graph Algorithms

Searching, Spanning, Sorting, Condensing

four algorithms on graphs, and what each one is really counting

Everything in this topic runs on a graph, so the cost is written in two variables rather than one: T(|V|, |E|), the number of primitive operations on a graph with |V| vertices and |E| edges. A primitive operation is anything doable in O(1). The reason for two variables is that graphs vary in density — a graph on n vertices can have n−1 edges or n(n−1)/2 of them, and an algorithm that touches every edge behaves very differently in the two cases.

The four algorithms, and the one idea each rests on
BFS and DFS differ by one data structure — a queue or a stack — and nothing else.
Kruskal and Prim are both greedy, and both correct, and on the example graph they return different trees.
Topological sort exists exactly when the graph has no cycle.
SCC uses depth-first search twice, the second time on the reversed graph.

Breadth-first and depth-first search

The two searches are the same five lines. Only the container changes.

BREADTH-FIRST-SEARCH
1. Select root vertex and add to a queue
2. While queue is not empty:
  3. Inspect the first element u on the queue.
  4. Add any unvisited neighbours of u to the queue.
  5. Remove u from the queue.
DEPTH-FIRST-SEARCH
1. Select root vertex and add to a stack
2. While stack is not empty:
  3. Inspect the top element u on the stack.
  4. Add any unvisited neighbours of u to the stack.
  5. Remove u from the stack.
The termination time, and its proof
Theorem. BFS and DFS both terminate in O(|V| + |E|).

Proof. Every vertex is enqueued and dequeued at most once, so steps 3–5 run once per u ∈ V. Inspecting and removing are O(1) each. Step 4 costs O(|Adj(u)|), because it looks at every neighbour of u. Summing:

∑u∈V ( O(1) + O(|Adj(u)|) ) = O(|V|) + O(|E|)
because ∑u |Adj(u)| counts each edge once (twice if undirected), which is O(|E|). The DFS proof is identical with “stack” for “queue”. ∎

The sum is the only step worth pausing on. It is tempting to say “step 4 is O(|E|) and it runs |V| times, so O(|V|·|E|)” — but that double-counts badly. Each vertex only pays for its own neighbours, and adding those up across all vertices totals the edge count once. This telescoping is why graph searches are linear rather than quadratic.

What the two searches actually give you
BFS visits everything at distance 1, then everything at distance 2, and so on, so the order it dequeues vertices in is increasing distance from the root. That makes BFS a shortest-path algorithm for free, on unweighted graphs.

DFS gives no such ordering — it plunges. What it gives instead is the timestamp structure: when a vertex is entered and when it is finished. That structure is what Topic 4 uses twice more, for topological sorting and for SCC.

A discrepancy worth knowing about
Depth-first search is often presented in two forms that explore neighbours in opposite orders. Pushing neighbours onto a stack means they come off in reverse: A’s neighbours are B, E, G and the search leaves for G. Walking them in listed order instead, so F leaves for E, not H. Both are genuine depth-first searches and both are correct — but they produce different traces, which is worth knowing before you assume you have made an arithmetic error. The tool above has a control for it.

Minimum spanning trees

Write these out exactly
A spanning tree for a weighted graph G = (V, E, w) is a tree T = (V, E′) in which every vertex is connected and E′ ⊆ E.

A minimum spanning tree is a spanning tree whose total weight is minimal out of all possible spanning trees.

Note what is being minimised: the sum of the edge weights, not the number of edges. Every spanning tree of a graph on |V| vertices has exactly |V| − 1 edges, so there is nothing to choose there.

Two greedy algorithms find one. Kruskal sorts all the edges once and takes them cheapest-first, skipping any that would close a cycle. Prim grows a single tree outwards from a root, always taking the cheapest edge that leaves it.

KRUSKAL-MST(G)
1. Sort the edge list E by weight (shortest first)
2. Initialise the set T = ∅
3. While sorted list E is not empty:
  4. Dequeue shortest edge (u, v) from E
  5. If T ∪ {(u,v)} is acyclic:
    6. T ← T ∪ {(u,v)}
7. Return tree T
PRIM-MST(G)
1. Select a root r ∈ V, all its edges to a priority queue Q
2. Initialise the set T = ∅
3. While queue Q is not empty:
  4. Dequeue shortest edge (u, v) from Q
  5. If T ∪ {(u,v)} is acyclic:
    6. T ← T ∪ {(u,v)}
    7. Add to Q any new edges adjacent to u or v
8. Return tree T
The two termination times
Kruskal: O(|E| log |E|), and the sort is the whole story —
  sorting E by weight = O(|E| log |E|)
  steps 4 and 6, once per edge = O(|E|)
  the cycle test, done by asking whether u and v are already connected = O((|V| + |E|) α(|V|))
where α is the inverse Ackermann function, which grows so slowly it is under 5 for any input that fits in the universe. The sort dominates.

Prim: O(|E| + |V| log |V|), using a Fibonacci heap for the priority queue. The bound is a property of the data structure, not of the algorithm — with a simpler heap you get O(|E| log |V|).

Step 5 is the interesting one in both. “Is T ∪ {(u,v)} acyclic?” sounds like it needs a search, but it does not: T is always a forest, so adding (u,v) creates a cycle exactly when u and v are already in the same component. That turns a graph search into a lookup, and it is why the disjoint-set structure appears in the complexity bound.

On the example graph, Kruskal returns a tree containing A–H and Prim returns one containing B–C. Both weigh 8. Both totals come to 37. Brute force over all 662 spanning trees confirms 37 is the minimum and that exactly two trees achieve it — so both algorithms are right, and they have simply landed on different members of a tie. If an exam answer differs from the mark scheme only in which of two equal-weight edges it took, check the total before assuming you are wrong.

Directed acyclic graphs and topological sorting

Write these out exactly
A graph G = (V, E) is a directed acyclic graph if it is irreflexive and contains no cycles of length ≥ 2 — equivalently, if there is a path u ⇝ v then there is no path v ⇝ u.

A topological sorting of a DAG is an ordered list L = ⟨v1, …, vn⟩ such that if vi ⇝ vj then i < j — every arrow points downstream.
TOPOLOGICAL-SORT(G)
1. While vertices remain unsorted:
  2. Select any unsorted vertex and add to a stack
  3. While stack is not empty:
    4. Inspect the top element u on the stack.
    5. If u has no unsorted neighbours:
      6. Pop u and add to the front of list L.
    7. Else:
      8. Add any unsorted neighbours of u to the stack.
9. Return sorted list L

A vertex is added to L only once everything downstream of it is already there — so it lands in front of all its descendants. That is the invariant, and it is the whole proof of correctness. The outer loop exists because a DAG need not be connected: dressing involves a watch that nothing depends on and that depends on nothing.

Two things that catch people out
The order is not unique. Step 2 says “select any unsorted vertex”. Socks and a watch can go in either order, so there are many correct answers and the mark scheme has one of them. Check your answer against the definition — every arrow forwards — rather than against a remembered list.

Sorting and acyclicity are the same question. A topological order exists exactly when there is no cycle, because three vertices on a cycle would each have to come before the next and after it. So “give a topological sort” and “show this is a DAG” are answered by the same piece of work.

Strongly connected components

Write these out exactly
Define a relation ∼ ⊆ V × V by
u ∼ v  ⇔  u = v, or there is a path u ⇝ v and a path v ⇝ u
A strongly connected component is a maximal subset C ⊆ V with u ∼ v for all u, v ∈ C. Equivalently, the components are the equivalence classes [u]∼ = { v ∈ V : v ∼ u }.

The component graph GSCC = (VSCC, ESCC) has one vertex per component, and (A, B) ∈ ESCC iff (a, b) ∈ E for some a ∈ A, b ∈ B with A ≠ B.

The word doing the work is maximal. Any single vertex is trivially strongly connected with itself, so “a set where everything reaches everything” is not enough — the set must not be extendable. Leaving out a vertex that belongs is the commonest way to lose marks here, and it is why the tool below checks maximality separately.

Theorem: GSCC is always a DAG
Proof. Suppose for contradiction that the component graph contains a cycle ⟨C1, C2, …, Cn, C1⟩.
Choose any a ∈ Ci and b ∈ Cj with Ci ≠ Cj.
Following the cycle forwards gives a path a ⇝ b; continuing round it gives b ⇝ a.
So a ∼ b, and Ci and Cj were never maximal — they should have been one component. Contradiction, so GSCC has no cycles. ∎

This is a genuinely useful theorem rather than a curiosity: it says any directed graph, however tangled, becomes a DAG once you collapse its cycles. Everything you know about DAGs — topological order, downstream reasoning, dependency resolution — then applies to the condensed graph.

SCC(G)
1. Call TOPOLOGICAL-SORT(G) to generate ordered list L
2. While L is not empty:
  3. Inspect the first element u in the list.
  4. Perform DFS on the transpose graph GT from u
  5. Add all visited vertices to a new component S
  6. Remove these vertices from the list L.
7. Return all components identified
Step 1 looks like a mistake, and is not
A graph with cycles has no topological order, so calling TOPOLOGICAL-SORT on one sounds wrong. What the routine actually computes is the reverse finishing order of a depth-first search. On an acyclic graph that happens to be a topological order — which is why it has that name — and on a cyclic one it is still perfectly well defined, and is exactly the order the second pass needs.

Why the transpose? Pass one, on G, finds everything u can reach. Pass two, on GT, finds everything that can reach u. A vertex in both sits on a round trip through u — which is the definition of u ∼ v. The finishing order is what stops the second search spilling out of the component and swallowing the next one.

Practice tool

Find the components — then check them against the definition

The components are found by the standard two-pass algorithm, and then checked by plain reachability that has never heard of it: every pair inside a component must reach each other both ways, and no outside vertex may belong. The component graph is built and tested for acyclicity, so the theorem is confirmed rather than quoted.

Try the DAG preset. Every component is a single vertex, because a DAG has no cycles and so nothing is mutually reachable with anything else — and the component graph comes back as a copy of the original. That is the degenerate case of the theorem, and a good sanity check that you have the definition the right way round.

Exam takeaways

Six one-liners
  • BFS and DFS are the same algorithm with a queue and a stack. Both O(|V| + |E|).
  • The linear bound comes from ∑u|Adj(u)| = O(|E|) — each vertex pays only for its own neighbours.
  • BFS gives shortest paths on unweighted graphs; DFS gives timestamps and back edges.
  • Kruskal O(|E| log |E|), dominated by the sort. Prim O(|E| + |V| log |V|) with a Fibonacci heap.
  • “Would this edge make a cycle?” = “are u and v already connected?”
  • GSCC is always a DAG, because a cycle among components would merge them.
Traps
  • O(|V|·|E|) for a search, from multiplying step 4 by the loop instead of summing it.
  • Assuming the MST is unique. It usually is not, and Kruskal and Prim can return different trees of equal weight.
  • Assuming the topological order is unique. Step 2 says any unsorted vertex.
  • Forgetting maximal in the SCC definition — {A} on its own is always “strongly connected”.
  • Doing the second SCC pass on G instead of GT. On G it just re-finds what u reaches, which you already had.
  • Calling a graph a DAG without checking irreflexivity. A self-loop is a cycle of length 1.
  • Reporting “no topological order” without naming the cycle that prevents it.
