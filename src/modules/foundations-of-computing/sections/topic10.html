Topic 10 · The Limits of Computation

Problems No Machine Can Solve

countability, the universal machine, halting, and the Entscheidungsproblem

Every previous topic asked how expensive a problem is. This one asks whether it can be solved at all, and the answer for some perfectly well-posed questions is no — not “not yet”, not “not efficiently”, but never, by any machine, however long you wait. The argument is short, and it turns on a single move: a machine is a finite object, so a machine can be handed a description of itself.

Decidable and undecidable

Write these out exactly
The Church–Turing thesis. Any language that can be effectively computed by some finite process can be recognised by a Turing machine.

Notation. M(w) = 1 if M accepts w, 0 if M rejects w, and ↑ if M does not halt on w.

Decidable. L is decidable if some machine M is
  sound: M(w) = 1 ⇒ w ∈ L
  complete: w ∈ L ⇒ M(w) = 1
  terminating: TM(w) < ∞ for all w ∈ Σ*
Drop the third condition and you get something weaker but useful
Sound and complete but not necessarily terminating is called recognisable (or semi-decidable): the machine accepts every word of L, and on words outside L it may simply run forever. You can confirm a “yes” by waiting; you can never confirm a “no”, because waiting longer always remains an option.

The halting problem sits exactly here. It is recognisable — simulate, and accept if the machine stops — and it is not decidable, which is what the rest of this topic proves. It is usually defined decidable and stops; the distinction is where most of the interest lives.
Is every language decidable?
No, and the reason is a counting argument before it is anything else. There are only countably many Turing machines, because a machine is a finite string over a finite alphabet and those can be listed. But there are uncountably many languages, since a language is an arbitrary subset of the countable set Σ*. So machines run out long before languages do — most languages have no machine at all, for the same reason most real numbers have no name.

That argument shows undecidable languages exist. It does not hand you one, and it says nothing about whether the ones we care about are among them. The diagonal construction below does hand you one, and the halting problem is one we care about.

Encoding machines as strings

The encodings
Tuples. ⟨w₀, w₁, …, wₙ⟩ := # w₀ # w₁ # … # wₙ #
Finite functions. ⟨f⟩ := ⟨ ⟨a₁, f(a₁)⟩, ⟨a₂, f(a₂)⟩, …, ⟨aₙ, f(aₙ)⟩ ⟩ — effectively a 2 × n matrix.
Machines. code(M) := ⟨ qinit, qaccept, qreject, ⟨δ⟩ ⟩

A binary alternative is also offered: transcribe each character as 0 ↦ 00, 1 ↦ 01, # ↦ 11.
Neither encoding, as printed, can be decoded
The tuple format is described as built from strings over the expanded alphabet Σ ∪ {#}, so a component may itself contain a separator. Then #0#1# is both the pair ⟨0, 1⟩ and the one-element tuple containing the string 0#1. Reading it back, nothing distinguishes them.

This is not hypothetical: code(M) nests tuples inside tuples — δ is encoded as a tuple of pairs — so its components contain separators by construction.

The binary code is offered as the alternative, and it does not fix the problem: it gives the data character # and the separator the same pattern, 11, so the two encodings above are still identical bit for bit. What fixes it is reserving a pattern the data can never produce — code # as 10 and keep 11 for the separator alone. The tool shows all three side by side and checks the repaired code is injective by exhaustion.

The universal machine
A universal Turing machine Mu takes as input a pair ⟨code(M), w⟩ and satisfies

Mu( ⟨code(M), w⟩ ) = M(w)

— it accepts if M accepts, rejects if M rejects, and fails to halt if M fails to halt. It is an interpreter: it reads the software code(M) and simulates M on w.

A language no machine recognises

Theorem: there is an undecidable language
Step 1. Enumerate every word over the alphabet: w₀, w₁, w₂, ….
Step 2. Enumerate every Turing machine: M₀, M₁, M₂, … — possible because there are only as many machines as there are codes for machines.
Step 3. Let L = { wi ∈ Σ* : Mi does not accept wi }, so wi ∈ L ⟺ Mi does not accept wi.
Step 4. If L were decidable it would be the language of some machine Mj on the list. But then wj ∈ Language(Mj) ⟺ wj ∉ L, so Language(Mj) ≠ L. Contradiction. ∎

The construction is worth seeing as a table. Machines down the side, words along the top, a tick where the machine accepts the word. L is built by walking the diagonal and flipping every entry, which guarantees that L disagrees with row i at column i — and so with every row somewhere.

The halting problem

Write this out exactly
HALTTM
Input) An encoding code(M) of a machine, and an input word w ∈ Σ*.
Output) True if and only if M terminates on input w.

HALTTM = { ⟨code(M), w⟩ : M terminates on input w }
Theorem: HALTTM is undecidable
Step 1. Suppose there is a sound, complete, terminating algorithm halt with halt(⟨code(M), w⟩) = 1 if M(w) ∈ {0, 1} and 0 if M(w) = ↑.
Step 2. Build a computable clone taking w to ⟨w, w⟩.
Step 3. Build M* so that M*(w) = 1 ⟺ halt(clone(w)) = 0 — accept when halt says “does not halt”, and otherwise loop forever.
Step 4. Feed M* its own code: M*(code(M*)) = 1 ⟺ halt(⟨code(M*), code(M*)⟩) = 0 ⟺ M*(code(M*)) = ↑.
Step 5. M* halts exactly when it does not halt. Contradiction, so halt does not exist. ∎
What this does and does not say
It does not say halting is hard, or that we have not found the algorithm yet, or that it needs too much time. There is no such algorithm. Any program claiming to decide halting for all inputs is wrong on at least one, and the proof tells you how to construct that input.

It also does not say you can never tell whether a particular program halts. Plenty of individual cases are easy. What fails is the general procedure, and that is a strictly stronger claim than any statement about any one program.

The Entscheidungsproblem

Write this out exactly
The Entscheidungsproblem (the decision problem)
Input) A predicate formula F.
Output) True if and only if F is a tautology.

Theorem. The Entscheidungsproblem is undecidable.
The proof, and why it needs predicate logic
Step 1. Cook–Levin built, for a machine M and word w, a propositional formula FM,w satisfiable exactly when M accepts w within a polynomial number of steps.
Step 2. That bound is the obstacle. Expressing “M will eventually accept” propositionally would need an infinite disjunction Sq,₀ ∨ Sq,₁ ∨ Sq,₂ ∨ … , which is not a formula.
Step 3. With predicate symbols carrying the time as an argument — Ca(i, t) for “cell i holds a at time t”, H(i, t) for the head position, Sq(t) for the state — that infinite disjunction becomes ∃t Sq(t).
Step 4. So there is a predicate formula FM,w satisfiable exactly when M eventually accepts w. That reduces the Accepting problem to the complement of validity, and since ATM is undecidable, so is the Entscheidungsproblem. ∎
Two details worth getting right
Satisfiability and validity are complements, not the same thing. F is satisfiable exactly when ¬F is not a tautology. The reduction therefore lands on the complement of the Entscheidungsproblem — which is easy to skate past. Undecidability transfers to complements anyway, since a decider for a language gives one for its complement by swapping the answers.

The reduction only needs to be computable, not polynomial. It is often called a polynomial reduction. It is one, but the extra strength is not used: for an undecidability argument all that matters is that the translation is something a machine can carry out. Saying “polynomial” suggests a complexity result where this is a computability one.
Where this came from
Hilbert posed the Entscheidungsproblem in 1928 as a challenge: find a procedure deciding the validity of any statement of first-order logic. Turing’s 1936 paper “On Computable Numbers, with an Application to the Entscheidungsproblem” answered it in the negative — and the machines were invented as a means to that end, not the other way round. The whole apparatus of this course exists because someone needed a precise definition of “procedure” in order to prove that a particular procedure does not exist.

Exam takeaways

What is most likely to be asked
Define decidable. Sound, complete, terminating — all three, and know that dropping the third gives recognisable.

State the Church–Turing thesis, and know it is a thesis, not a theorem: it identifies an informal notion with a formal one, so it cannot be proved.

Run the diagonal argument. Enumerate words, enumerate machines, define L by flipping the diagonal, and show no row can equal it.

Prove HALTTM undecidable. Assume halt, clone the input, build M* to do the opposite, feed it its own code.

Name the other undecidable problems and, for each, the reduction: A, R, E, EQ, REGULAR, and the Entscheidungsproblem.

Get the direction of a reduction right. Reduce a known-undecidable problem to the one you are asking about. The hardness travels along the arrow.
Traps
  • Saying halting is “too hard to compute”. It is not hard; it is impossible.
  • Reducing the wrong way and concluding nothing.
  • Confusing undecidable with NP-hard. Different axis entirely: NP-hard problems are all decidable.
  • Claiming the counting argument identifies a specific undecidable language. It only shows one exists.
  • Forgetting that undecidable languages can still be recognisable, and that HALT is.
  • Treating the Church–Turing thesis as something that was proved.
The one-sentence version
A machine is a finite string, so a machine can be handed its own description and asked to predict itself — and any machine that could always answer correctly could be rewired to do the opposite of its own prediction, which nothing can do.
