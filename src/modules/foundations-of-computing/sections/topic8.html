Topic 08 · Linear Programming

Optimising Under Constraint

feasible regions, the simplex method, and what integrality costs

Topic 7 took an optimisation problem that was hopeless and settled for a guaranteed-good answer. This topic takes a class of optimisation problems that are not hopeless — you can have the exact optimum, in polynomial time — and then shows how little it takes to destroy that. Add three letters to the problem statement, x ∈ ℤ, and a problem in P becomes NP-hard.

What a linear program is

Write these out exactly
Linear objective function — the quantity to be maximised or minimised.
Linear constraints — a set of linear inequalities restricting the feasible solutions.

LP
Input) A set of linear constraints Ax ≤ b, and a linear objective function f : ℝn → ℝ.
Output) A solution x ∈ (ℝ≥0)n such that (i) x satisfies Ax ≤ b and (ii) f(x) is maximal.

Feasible region R = { x ∈ ℝn : x is a solution }.
Optimal solutions { x ∈ R : ∀y ∈ R ( f(x) ≥ f(y) ) } ⊆ R.

Two details in that definition earn their place. The output is drawn from (ℝ≥0)n, so every variable is implicitly non-negative — x ≥ 0 and y ≥ 0 are constraints you never have to write and must never forget, because they are two of the edges of the region below. And the inequalities are non-strict. That is not decoration: maximise x subject to x < 1 has no solution at all, because the region is not closed and the supremum is never attained.

Matrix form
The constraints 3x + 2y ≤ 15, 2y − x ≤ 5, x + 2y ≤ 7 are written more compactly by stacking the coefficients into a matrix and the right-hand sides into a vector:

A = [ [3, 2], [−1, 2], [1, 2] ]    b = (15, 5, 7)    giving   Ax ≤ b.

Watch the sign: 2y − x becomes the row (−1, 2), not (1, 2). Rows are in the order the constraints are listed, and the columns in the order the variables are.

Because the constraints are linear, the region they cut out is a convex polytope, and because the objective is linear its contours are parallel straight lines. Slide a line across a convex polygon and the last point it touches is a corner. That is the whole geometric content of the topic, and every algorithm below is a different way of finding the right corner without visiting all of them.

Three outcomes, and the slide says so
A linear program has a unique solution, infinitely many, or none. Infinitely many happens when the objective contour is parallel to an edge, so two adjacent vertices tie and every point between them is optimal too. None happens two quite different ways: the region can be empty, or it can be unbounded in a direction that improves the objective. Both presets above are worth running, because the exam answer “no solution” is only half a mark.

The simplex method

Dantzig, 1946–47, out of operations research for the US Air Force; named after the simplex, the n-dimensional analogue of a triangle, after the shape of the feasible region. The idea is to start at a corner and walk to a neighbouring corner that improves the objective, repeating until no neighbour is better — at which point convexity guarantees you are at the global optimum, not merely a local one.

Slack form
A slack variable turns each inequality into an equation, by naming exactly how much room is left in that constraint:

3x + 2y ≤ 15  ⟹  3x + 2y + s₁ = 15  ⟹  s₁ = 15 − 3x − 2y
2y − x ≤ 5  ⟹  −x + 2y + s₂ = 5  ⟹  s₂ = 5 + x − 2y
x + 2y ≤ 7  ⟹  x + 2y + s₃ = 7  ⟹  s₃ = 7 − x − 2y

x and y are the independent variables; s₁, s₂, s₃ are dependent — pick the first two and the rest follow. The constraint is satisfied exactly when its slack is ≥ 0, so a slack of zero means that constraint is tight, which is the same as saying you are sitting on that edge. The objective becomes one more dependent variable, the cost: C = 2x + 3y.
The seven steps
1) Build the initial tableau from the slack form plus the cost equation, the cost row written with the objective coefficients negated (because it is stored as C − 2x − 3y = 0).
2) Pivot column: the most negative coefficient in the final row.
3) Row quotients: right-hand side ÷ the entry in the pivot column.
4) Pivot row: the smallest quotient with a positive denominator.
5) Pivot value = the entry in both. Scale the pivot row by 1/pivot, then subtract multiples of it from every other row to clear the column.
6) Repeat until no negative coefficients remain in the final row.
7) Read off: a variable whose column is all zeros bar a single 1 takes that row's right-hand side; every other variable is 0.

Step 2 is doing something specific: a negative entry in the cost row means increasing that variable would raise C, so a row with no negative entries left means nothing can be improved. Step 4 is asking how far the entering variable can grow before some slack hits zero — the first constraint to become tight is the one you run into, and its row is the pivot.

The final tableau on the slide has an arithmetic slip
Rounds 1 and 2 in the tool reproduce the lecture's tableaux entry for entry. Round 3 does not: the slide's last row reads 0.25s₁ + 2.25s₃ + C = 12.5, and the s₃ coefficient should be 1.25.

You can check it without doing the pivot at all. The final cost row is an identity in x and y, so substitute the slack definitions into C = 12.5 − 0.25s₁ − λs₃ and match coefficients: s₁ = 15 − 3x − 2y and s₃ = 7 − x − 2y give a coefficient of x of 0.75 + λ, which must equal 2, so λ = 1.25; the y coefficient 0.5 + 2λ = 3 agrees, and the constant 12.5 − 3.75 − 7(1.25) = 0 as it must.

The reported answer — x = 4, y = 1.5, C = 12.5 — is unaffected, and so is everything built on it later. Also worth noting: the round 2 row operations on the slide are written R₂ ← (R₃ − …R₃) where they mean R₂, and round 3 divides by 2 where the pivot value is 1. The tool prints the operations it actually performed.
Step 4 as stated is wrong on degenerate problems
The slide asks for the smallest quotient where both the numerator and denominator are positive. The standard rule asks for a numerator that is non-negative, and the difference is exactly a right-hand side of zero.

Run the Degenerate preset both ways. On max 3x + 2y subject to x + y ≤ 4, x − y ≤ 0, x ≤ 3, the second row has a right-hand side of 0, so its quotient is 0 — the smallest there is. The slide's rule skips it as "not positive" and pivots elsewhere; the next tableau has a negative right-hand side, which means it is describing a corner outside the region, and the method finishes by reporting x = 3, y = 1 with C = 11. That point breaks x − y ≤ 0, and the true optimum is x = y = 2 with C = 10. An answer that is both infeasible and larger than the optimum is the worst kind of wrong, because nothing about it looks suspicious.

A related gap: with degenerate pivots the method can also cycle, returning to a tableau it has already seen. Bland's rule — always take the lowest-indexed eligible column and row — is the standard cure. It is slower, and it is what the phase-one solver in this module uses, precisely because nobody is watching that one run.
And it cannot start on the lecture's own energy example
The tableau begins at the corner where every variable is zero and every slack holds its whole constraint. That is a real corner only if every right-hand side is non-negative once the constraint is written as ≤. The energy program's G + C + S + W + N ≥ demand becomes a ≤ row with a negative right-hand side, so setting everything to zero breaks it, and there is no starting corner to walk from.

The fix is a phase-one method: add an artificial variable to each awkward row, minimise the sum of the artificials — a program that does have an obvious starting corner — and if you can drive them all to zero you have found a genuine corner to begin the real objective from. If you cannot, the region is empty. The slides never mention this, and the tool falls back to it and says so. It matters again in the next section, because branching adds y ≥ 2.
Two theorems to quote
Klee–Minty (1972). The worst-case running time of the simplex method is exponential. Their program is a cube distorted so that the most-negative-coefficient rule walks every one of its 2n+1 corners.

Khachiyan (1979). Linear programming is solvable in polynomial time — by the ellipsoid method, not by simplex.

These do not conflict. Klee–Minty is about one algorithm; Khachiyan is about the problem. In practice simplex is the one people run, because its bad cases are contrived and its typical behaviour is excellent — the reverse of the usual situation, where the proof is comforting and the practice is not.

Integer programming

Write this out exactly
IP
Input) A set of linear constraints Ax ≤ b, and a linear objective function f : ℝn → ℝ.
Output) A solution x ∈ (ℤ≥0)n such that (i) x satisfies the constraints and (ii) f(x) is maximal.

Word for word the LP definition, with ℝ replaced by ℤ in one place. That is the entire difference, and it is the difference between P and NP-hard.

Variants. Mixed integer linear programming (MILP): some variables must be integers, others may not be. Zero-one integer programming: every variable is 0 or 1.
Modelling: assignment as an integer program
Workers with capacities, tasks with requirements, an edge wherever a worker can do a task.
1) A variable xi,j per edge, with xi,j ≤ 1.   2) Per worker: Σj xi,j ≤ capacity of i.   3) Per task: Σi xi,j ≥ requirement of j.   4) Maximise Σi,j xi,j.

Two slips to be aware of on the slide. Step 5 restates the task constraint as “Σj xi,j ≥ requirements of j”, summing over the wrong index — it must be over the workers i, as step 3 correctly has it, otherwise the constraint does not mention task j at all. And the result is called a maximal matching, where what the program finds is a maximum one; with capacities above 1 it is not a matching in the usual sense either, but a degree-constrained subgraph.
Linear relaxation and BRANCH-AND-BOUND
The linear relaxation of an integer program is the same program with the integrality requirement dropped. It can be solved quickly, and its optimum is always at least as good as the integer optimum — so it is an upper bound.

BRANCH-AND-BOUND (LP):
1. Find a solution a to the linear relaxation of LP
2. If a ∈ ℤn, return a
3. Else:
4.   Choose a non-integer xi = ai to branch on
5.   aL = BRANCH-AND-BOUND (LP ∪ { xi ≤ ⌊ai⌋ })
6.   aR = BRANCH-AND-BOUND (LP ∪ { xi ≥ ⌈ai⌉ })
7.   Return whichever of them maximises f.

The two branches are exhaustive and disjoint: no integer point has ⌊ai⌋ < xi < ⌈ai⌉, so nothing is lost by cutting the fractional value out, and every integer point still lies in one side or the other.
The pseudocode has no bounding step in it
Read lines 5 and 6 again: both children are always explored, whatever has already been found. Nothing in the algorithm ever uses a bound to avoid work, which makes the name half false — as written it is branch-and-branch, a complete enumeration of the tree.

The missing line is the one that earns the name: if a node's relaxation is already no better than the best integer solution found so far, then nothing below that node can beat it either, because the relaxation bounds everything beneath it — so prune it unexplored. The tool runs with and without, and reports what the difference costs. On the lecture's five-node example it costs nothing, which is exactly why the omission passes unnoticed.

Two smaller gaps: there is no case for a subproblem being infeasible (adding y ≥ 2 can empty the region), and no case for it being unbounded, in which case the recursion never terminates.

The lecture's tree, and one number in it
The relaxation gives x = 4, y = 1.5 with C = 12.5. Branching on y:
y ≤ 1 gives x = 13/3, y = 1, C = 35/3 — still fractional, so branch again on x, giving (4, 1) with C = 11 and (5, 0) with C = 10.

The slide writes the y ≤ 1 node as x = 4.3, C = 11.6. It is 13/3 = 4.333… and 35/3 = 11.667, so 11.6 is the truncation of a recurring decimal rather than a rounding of it. Nothing depends on it — the node is discarded either way — but write the fraction in an exam and you cannot be marked down for it. The slide's final comparison also pairs C = 11 with the point (5, 0), and (5, 0) gives 10; the 11 belongs to (4, 1).
Theorem: integer programming is NP-hard
By reduction SAT ≤p IP. Given a CNF formula F:
1) For each propositional variable P, introduce two numerical variables xP and x¬P.
2) Each clause becomes a constraint that at least one of its literals is chosen: (P ∨ Q ∨ ¬R) becomes (xP + xQ + x¬R) ≥ 1.
3) For each variable add both (xP + x¬P) ≤ 1 and (xP + x¬P) ≥ 1.
4) Then F is satisfiable ⟺ IPF has an integer solution.

Step 3 is the clever part. The two inequalities together force xP + x¬P = 1, and since both are non-negative integers, exactly one of them is 1 — so a pair of linear inequalities has encoded a Boolean choice. The construction is clearly polynomial: two variables and two constraints per propositional variable, one constraint per clause.

Note the theorem says NP-hard, not NP-complete. Hardness is all the reduction gives you; membership of NP needs the separate argument that an optimal solution can be written down in polynomial space.
Two things the reduction does not actually need
Worth knowing if you are asked to justify each part rather than recite it.

The objective does no work. The claim is “F is satisfiable ⟺ IPF has an integer solution” — a question about feasibility, not optimality. Any objective at all will do, which is why the slide never says what to maximise.

Only half of the pairing constraint is load-bearing. Drop xP + x¬P ≥ 1 and keep only ≤ 1, and the equivalence still holds: a solution may now leave both at 0, so P is assigned nothing, but every clause still has a literal set to 1 and that partial assignment extends to a satisfying one. Checked here over 500 random formulas, 116 of them unsatisfiable, with no mismatch either way. The ≤ 1 half is the one you cannot lose — without it xP = x¬P = 1 satisfies every clause of every formula. The ≥ 1 half is there to make the recovered assignment total, which is worth having and is not the same as being necessary.
Where the integrality actually bites
Drop the integrality from that reduction and it collapses immediately: xP = x¬P = ½ satisfies every constraint of every formula, satisfiable or not. The linear relaxation of an encoded SAT instance is trivially solvable and tells you nothing. That is the cleanest statement of what the extra three letters buy — and of why branch-and-bound has to exist at all.

Exam takeaways

What is most likely to be asked
Build a program from a word problem. A variable per decision, a constraint per limit, the objective last. Say which direction you are optimising and remember that non-negativity is free.

Convert to slack form and build the initial tableau. Negate the objective coefficients in the cost row. Get the sign of a term like 2y − x right.

Do two rounds of simplex by hand. Most negative in the last row picks the column; smallest non-negative quotient picks the row; scale, then clear. Keep fractions.

Read off a solution from a final tableau. Unit column ⟹ basic ⟹ takes that row's right-hand side. Everything else is zero. A zero slack means that constraint is tight.

Branch and bound, one level. Solve the relaxation, pick a fractional variable, write down both subproblems with their floor and ceiling bounds, and say which child wins.

State and use the reduction. Two variables per propositional variable, one ≥ 1 constraint per clause, the ≤ 1 and ≥ 1 pair per variable, and the sentence about why that pair forces a 0/1 choice.

Name the theorems. Klee–Minty 1972: simplex is exponential in the worst case. Khachiyan 1979: LP is in P. IP is NP-hard by SAT ≤p IP.
The one-sentence version
A linear program is a convex region and a straight objective, so the answer sits at a corner and can be found in polynomial time; requiring the corner to have whole-number coordinates removes the geometry that made it easy, and the best you can then do is solve the easy version repeatedly on smaller and smaller pieces.
