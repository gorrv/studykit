Topic 09 · Randomised Computation

Getting It Right Most of the Time

probability, expectation, and the classes a coin buys you

Every machine so far has been given the same input twice and done the same thing twice. This topic hands the machine a coin. That changes what “M decides L” can mean: an answer may now be right with some probability, and a running time may now be right on average. Where you allow the randomness to hurt you — in the answer, or in the clock — is exactly what separates the two classes at the end.

Probability, expectation, variance

Write these out exactly
Sample space S = { all possible outcomes } = { s₁, s₂, …, sₙ }.
Probability measure Prob : S → [0, 1].
Event — any subset E ⊆ S, i.e. E ∈ 𝒫(S), with Prob(E) = Σs∈E Prob(s).
Random variable X : S → ℝ — a measurement of a random outcome, not an outcome.
Prob(X = k) = Prob({ s ∈ S : X(s) = k }), and similarly for X ≤ k.
Probability mass function pX(k) = Prob(X = k).

Expectation E[X] = Σk k · pX(k).
Variance Var[X] = E[(X − μ)²] where μ = E[X], and Var[X] = E[X²] − E[X]².
Standard deviation σX = √Var[X].

The definition of a random variable is worth pausing on, because the name is misleading: X is neither random nor a variable. It is a function from outcomes to numbers, fixed once and for all. What is random is which outcome you get, and X merely measures it. That is why questions about X reduce to questions about sets of outcomes — Prob(X = k) is shorthand for the probability of the event on which X happens to take the value k.

Why the first attempt at variance fails
The slide tries Var[X] = E[X − μ] first and gets zero, always. That is not an accident of the example: by linearity E[X − μ] = E[X] − μ = 0 for every random variable there is. Deviations above and below the mean cancel exactly, which is what “mean” means. Squaring first is what stops the cancellation, and it is also what makes the units of Var[X] the square of the units of X — hence taking the root at the end to get σ back into the units you started in.

Properties of expectation
For any random variables X and Y and any real a, b:
(i) E[aX + b] = a·E[X] + b
(ii) E[X + Y] = E[X] + E[Y]

Part (ii) is called linearity of expectation and it needs no assumption about X and Y. They may be as dependent as you like — Y may literally be X — and it still holds. That is unusual enough to be worth a line of its own in an answer, because the corresponding statement for variance is false: Var[X + Y] = Var[X] + Var[Y] + 2·Cov[X, Y], so variances add only when the covariance vanishes, which independence guarantees and nothing else does.

Markov’s inequality

The theorem, with the hypothesis the slide omits
Let X be a non-negative random variable with expectation E[X]. Then for any a > 0:

Prob( X ≥ a · E[X] ) ≤ 1/a

In words: a non-negative quantity cannot be far above its average very often. It is the only tail bound you get from knowing the mean alone, and it is tight — a variable that is a·E[X] with probability 1/a and 0 otherwise meets it with equality — so no better bound is possible without more information.
The slide states it without X ≥ 0, and then it is false
As printed, the theorem reads “let X be a random variable with expectation E[X]”, with no condition on X. Take X = −10 always. Then E[X] = −10, and for a = 2 the claim is Prob(X ≥ −20) ≤ ½ — but that probability is 1.

The reason is visible once you look: with a negative mean, multiplying by a larger a moves the threshold down, so the event becomes more likely as the bound gets tighter. Every actual use of Markov in this topic is on a running time, which is non-negative, so nothing downstream breaks — but write the hypothesis down. Probabilistic Turing machines

Write this out exactly
A probabilistic Turing machine is M = ⟨Σ, Q, qinit, qaccept, qreject, δ⟩ — the same six-tuple as before — where

δ( current state, symbol read ) ↦ a probability distribution over possible instructions,
drawn from the sample space S = Q × (Σ ∪ {␣}) × {←, →}.

Configurations are as for an ordinary machine: (current state, left substring, right substring). The computations are all sequences of configurations obtainable by running M — which now form a tree rather than a single path.
Reading the tree
Prob(a branch) = the product of the probabilities along it, because each choice is made afresh.
Prob(M(w) = 1) = Σ over all accepting branches — a sum, because distinct branches are mutually exclusive events. Two different sequences of choices cannot both happen.

Any number you can attach to a computation is a random variable on that tree: the termination time T(n), the space S(n), the number of visits to a given state. T(n) is the one the next section needs.

It accepts with probability ½ at each round and otherwise goes back to where it started. Its probability of eventually halting is 1 — the surviving mass halves every two steps, so it tends to zero — and yet there is no k such that it always halts within k steps. Halting with probability 1 and halting within a bound are different properties, and the gap between them is precisely the gap between ZPP and BPP below.

BPP and ZPP

Write these out exactly
Bounded-error probabilistic polynomial time (BPP). L ∈ BPP if some machine M is
  probabilistically sound: w ∉ L ⇒ Prob(M(w) = 1) ≤ 1/3
  probabilistically complete: w ∈ L ⇒ Prob(M(w) = 1) ≥ 2/3
  polynomial-time: T(n) ∈ O(nk)  (worst case)

Zero-error probabilistic polynomial time (ZPP). L ∈ ZPP if some machine M is
  sound: w ∉ L ⇒ Prob(M(w) = 1) = 0
  complete: w ∈ L ⇒ Prob(M(w) = 1) = 1
  expected polynomial-time: E[T(n)] ∈ O(nk)  (expected)
Monte Carlo and Las Vegas
A Monte Carlo algorithm has a deterministic running time but may return the wrong answer. BPP = the problems with a polynomial-time Monte Carlo algorithm.

A Las Vegas algorithm is always sound and complete, but its running time varies. ZPP = the problems with a polynomial-time Las Vegas algorithm.

The names are worth keeping straight by the mnemonic that in Las Vegas you can always leave with your money, you just cannot say when; in Monte Carlo you leave on schedule and might have lost.
Theorem: ZPP ⊆ BPP
Step 1. Let L ∈ ZPP, so some M is sound and complete with E[T(n)] < c·nk.
Step 2. Build M′: run M for at most K = 3·E[T(n)] steps. If it finished, answer what it answered. If it did not, flip a fair coin.
Step 3. M′ always terminates within O(nk) steps, by construction.
Step 4 (sound). If w ∉ L then M never accepts, so M′ can only accept by guessing: Prob(M′(w) = 1) ≤ Prob(T(n) > 3E[T(n)]) ≤ 1/3 by Markov.
Step 5 (complete). If w ∈ L then M accepts whenever it finishes, so Prob(M′(w) = 1) ≥ 1 − Prob(T(n) > 3E[T(n)]) ≥ 2/3.
Step 6. M′ is a polynomial-time Monte Carlo algorithm, so L ∈ BPP. ∎

Markov is doing all the work, and it is legitimate here because T(n) is a running time and therefore non-negative — the hypothesis the earlier slide omitted.
The proof gives away more than it claims
Steps 4 and 5 bound the error by Prob(T > K) alone, dropping the coin’s factor of ½. Putting it back gives 1/6 and 5/6 rather than 1/3 and 2/3 — the construction lands comfortably inside the definition rather than exactly on its boundary. Both versions are correct, since throwing away slack can only weaken a bound you are trying to satisfy, but it is worth seeing that the theorem is not as tight a squeeze as the numbers suggest. The hierarchy, and what is actually known
Proved: P ⊆ ZPP ⊆ BPP ⊆ PSpace, and P ⊆ NP ⊆ PSpace, and P ⊆ co-NP ⊆ PSpace.

Open, and on the slide as questions: BPP ⊆ NP? NP ⊆ BPP? ZPP = P? BPP = P?

The last one is the surprise. Most people meeting BPP for the first time assume randomness must buy something, and the current expectation among complexity theorists is the opposite: BPP = P is widely believed to be true. Randomness looks like power, but for decision problems it is increasingly thought to be a convenience — one that good enough pseudorandom generators would remove. Nobody has proved it.

Exam takeaways

What is most likely to be asked
Compute E[X] and Var[X] from a table. Build the k·pX(k) row and sum it; use E[X²] − E[X]² rather than the definition, and check Σp = 1 first.

State Markov’s inequality and apply it. Include X ≥ 0 and a > 0. Typical use: bound the chance of running more than a few times the expected time.

Read a computation tree. Multiply along a branch, add across accepting branches, and check the leaves total 1.

Define BPP and ZPP. Three clauses each. The examinable contrast is worst-case time with bounded error against expected time with no error.

Prove ZPP ⊆ BPP. Cut off at 3·E[T], flip a coin, apply Markov. Say why Markov applies.

Say which containments are known. P ⊆ ZPP ⊆ BPP is proved; BPP versus NP is open in both directions.
The one-sentence version
Randomness lets a machine trade certainty for speed, and the two classes differ only in which one they refuse to give up: ZPP keeps the answer exact and lets the clock slip, BPP keeps the clock exact and lets the answer slip — and Markov’s inequality is the bridge, because a machine that is usually quick cannot be slow very often.
