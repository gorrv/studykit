Topic 05 · SAT Solving

Fast, Correct, or Restricted — Pick Two

what you can actually do about an NP-complete problem

Topic 2 established that SAT is NP-complete and left it there. This topic is about what to do next, because the problem does not go away: every NP problem reduces to SAT, logic is a natural specification language, and industrial solvers routinely handle formulas with millions of literals. Three honest responses to a hard problem, and this topic covers all three.

The three responses, and what each gives up
Be fast, give up correctness. GREEDY-SAT runs in polynomial time and gets the answer wrong.
Be correct, give up speed. DPLL always answers correctly, in exponential time on the worst case, but with two rules that make the typical case survivable.
Restrict the problem. 2SAT and Horn formulas are genuinely in P — not heuristically fast, provably polynomial.
Why SAT is worth this much effort
  • The first problem shown to be NP-complete (Cook–Levin, Topic 3).
  • Every problem in NP reduces to it, so a polynomial algorithm for SAT would prove P = NP.
  • Reductions to SAT are usually straightforward, which makes it a practical target rather than only a theoretical one.
  • Even if P ≠ NP, real instances still need answering — and real instances are rarely worst-case.

A greedy approach, and where it fails

The obvious idea: guess an assignment, then keep flipping whichever single variable improves the count of satisfied clauses, until no flip helps.

GREEDY-SAT(C)
1. Randomly select a variable assignment V
2. While there is some unsatisfied clause in C:
  3. Count the number of unsatisfied clauses
  4. For each variable P: count the clauses satisfied by flipping P
  5. If no improvement: Return False
  6. Update V to the best improvement
7. Return True
Theorem: GREEDY-SAT runs in polynomial time
Proof. Choosing a random assignment and scoring it are both linear. Each iteration scores at most n assignments differing in one variable, so it is polynomial. And since the score strictly increases every iteration and is bounded by |C|, there are at most |C| iterations. ∎
The proof is correct. The algorithm is still wrong.
Nothing in that theorem says the answer is right — only that it arrives quickly. GREEDY-SAT is sound but incomplete: when it returns True it hands you an assignment you can check yourself, but when it returns False it has proved nothing at all. All it means is “I ran out of uphill moves”.

This is not a hypothetical. On the lecture’s own seven-clause example, starting from the assignment the slides pick — P := True, Q := False, R := False — greedy scores 6, finds that no single flip does better than 6, and returns False. The formula is satisfiable: P := False, Q := True, R := True satisfies all seven. Greedy cannot get there because the route passes through assignments that score worse.

Branching, and the DPLL algorithm

To be right, an algorithm has to consider both values of a variable. That is the naïve branching algorithm: pick a variable, try False, try True, recurse. It is divide-and-conquer — each branch is the same problem with one fewer variable.

BRANCH-SAT(C, U)
1. If U contains a conflict: Return False
2. If C = ∅: Return True
3. Simplify the clauses in C as much as possible
4. Select a variable P appearing in C
5. If BRANCH-SAT(C, U ∪ {¬P}) = True: Return True
6. If BRANCH-SAT(C, U ∪ {P}) = True: Return True
7. Return False

This is correct and it is exponential — it is a systematic walk over 2n assignments. DPLL (Davis, Logemann and Loveland, 1962, building on Davis and Putnam, 1960) is the same algorithm with two rules inserted before the branch. Neither rule is needed for correctness. Both are there to make branching unnecessary as often as possible.

Unit propagation — what MUST be assigned
A unit clause has exactly one literal left. There is no choice: that literal must be true, or the clause is dead.

Assign it, delete every clause it satisfies, and delete its negation from the rest. That often creates new unit clauses, so the rule cascades.

Because it forces things, it can produce a conflict — and that is how DPLL discovers a branch is hopeless before exploring it.
Pure literal elimination — what SHOULD be assigned
A pure literal appears with only one sign in the whole formula: always P, or always ¬P, never both.

Make it true. Every clause containing it is satisfied at a stroke, and because its negation appears nowhere, nothing is damaged.

It can never cause a conflict. It is free progress — which is exactly why the deck calls it “should” rather than “must”.
DPLL(C, U)
1. If U contains a conflict: Return False
2. If C = ∅: Return True
3. Simplify the clauses in C as much as possible
4. Apply PURE-LITERAL-ELIMINATION to C
5. Apply UNIT-PROPAGATION to C
6. Select a variable P appearing in C
7. If DPLL(C, U ∪ {¬P}) = True: Return True
8. If DPLL(C, U ∪ {P}) = True: Return True
9. Return False
Follow the lecture's unit propagation to its end
The slides propagate ¬Q and R, which forces P, which leaves S and ¬S both as unit clauses — and then the deck moves on. That pair is the conclusion: S is forced both ways, so the branch has a conflict, and since no branching happened at all, that clause set is unsatisfiable. Restricted versions: N SAT

Write this out exactly
The Boolean Satisfiability Problem N SAT
Input) A propositional formula F in CNF with at most N literals in each clause.
Output) True if and only if F is satisfiable.

One direction of reduction is trivial. A formula with at most k literals per clause also has at most k+1, so 2SAT ≤p 3SAT ≤p 4SAT ≤p … ≤p SAT with no work at all — the identity map is the reduction.

The other direction is the surprising one: SAT ≤p 3SAT. Unbounded clauses can be chopped down to three literals without changing satisfiability.

1 Take any CNF formula, e.g. (P ∨ ¬Q ∨ R ∨ S) ∧ (Q ∨ ¬R ∨ ¬T).
2 Find a clause with more than 3 literals — here the first.
3 Break it in the middle.
4 Introduce a fresh variable X to bridge the gap: (P ∨ ¬Q ∨ X) ∧ (¬X ∨ R ∨ S).
5 Repeat until every clause has at most 3 literals.
Why the bridge works, in both directions
If X is false, the first clause needs P or ¬Q. If X is true, the second needs R or S. Either way something from the original clause must be true — so satisfying the new formula satisfies the old.

Conversely, given a satisfying assignment for the original, some literal in the wide clause is true; set X to send the obligation to the other side. So the two are satisfiable together or not at all — which is what ≤p requires, and the half that is easy to forget.

The chain stops at 3
Putting the two theorems together, 3SAT, 4SAT, …, SAT are all equivalent — each reduces to the others, so all are NP-complete. The obvious next question is whether the trick continues: 3SAT ≤p 2SAT?

It does not, and the next section shows why not by showing that 2SAT is easy. If 3SAT reduced to 2SAT then 3SAT would be in P, and so would every problem in NP.

2SAT is in P

Theorem: 2SAT is solvable in polynomial time
Proof. By the strongly connected component algorithm from Topic 4.

Step 1) Write each clause as two implications. (a ∨ b) is equivalent to (¬a → b) ∧ (¬b → a) — if one disjunct fails the other must hold.
Step 2) Build the implication graph: one vertex per literal, one edge per implication.
Step 3) Compute the strongly connected components.
Step 4) If any component contains both a literal and its negation, F is unsatisfiable. Otherwise it is satisfiable.

All four steps are polynomial, so 2SAT is in P. ∎

Step 4 is the one to understand rather than memorise. A path x ⇝ y in the implication graph means “x forces y”. If x and ¬x lie in the same component then x forces ¬x and ¬x forces x. Setting x true makes it false; setting it false makes it true. Neither value survives, so nothing satisfies the formula.

And when no component contains such a pair, an assignment can be read straight off: make a literal true when its component sits downstream of its negation’s in the condensation. Implications only ever run from earlier components to later ones, so choosing the downstream literal can never contradict something already settled.

Horn clauses, easy for a different reason

A definite Horn clause has exactly one positive literal, which lets it be written as a rule with a single head:

The same clauses, two ways
P,   (¬P ∨ Q),   (¬P ∨ ¬Q ∨ R),   (¬Q ∨ S),   (¬S ∨ ¬R ∨ T)
becomes
P,   P → Q,   P ∧ Q → R,   Q → S,   S ∧ R → T

The negative literals are the body, the single positive literal is the head. A clause with no positive literal is a goal: it says not all of its atoms may hold.

Horn formulas are decided by forward chaining: start from the facts, fire every rule whose body is satisfied, repeat until nothing new appears. One pass, no backtracking, linear time. It works because a Horn formula has a unique minimal model — the set of atoms the rules force. If that model breaks a goal clause, every larger model breaks it too, so there is nothing else to try.

Two easy fragments, two unrelated reasons
2SAT is easy because it is secretly a graph problem. Horn is easy because it has a unique minimal model reachable by a fixed-point computation. Neither contains the other: (P ∨ Q) is 2SAT but not Horn (two positive literals); (¬P ∨ ¬Q ∨ R) is Horn but not 2SAT (three literals). That is why the lecture’s diagram draws them as overlapping circles inside P, rather than one inside the other.

Exam takeaways

Six one-liners
  • GREEDY-SAT is polynomial and incomplete. True means true; False means “stuck”.
  • Unit propagation assigns what must be — and can conflict.
  • Pure literal elimination assigns what should be — and never can.
  • Neither rule is needed for correctness. Both are there for speed.
  • SAT ≤p 3SAT by splitting wide clauses with fresh bridging variables, so 3SAT and SAT are equally hard.
  • 2SAT and Horn are in P; 3SAT is not known to be. The line falls between 2 and 3.
Traps
  • Reading “polynomial time” as “solves the problem”. Greedy is the counterexample, and it is on the slides.
  • Swapping the two DPLL rules. Unit = one literal left in a clause. Pure = one sign across the whole formula.
  • Claiming pure literal elimination can cause a conflict. It cannot — that is its defining property.
  • Reusing an existing variable as the bridge in SAT ≤p 3SAT. It must be fresh, or you constrain something you had no right to.
  • Giving only one direction of the ≤p argument. Both are required.
  • Concluding 2SAT is easy “because clauses are small”. 3SAT’s clauses are small too. It is easy because two literals make an implication.
  • Saying a component containing P and Q makes a formula unsatisfiable. It must contain a literal and its own negation.
