Topic 07 · Approximation & TSP

When You Cannot Win, Bound the Loss

approximation ratios, 2OPT, and the limits of approximating

Topic 5 asked what to do about an NP-complete decision problem. This topic asks the same about an optimisation problem, where the answer is not yes or no but “the best one”. If you cannot find the best in polynomial time, the next question is how close you can guarantee to get — and, less comfortably, whether any guarantee is possible at all.

Decision versus optimisation
DecisionDoes a solution exist? SAT, HALTING, HAMILTONIAN, GRAPH ISOMORPHISM
OptimisationWhat is the best solution? CLIQUE, VERTEX COVER, TSP

An optimisation problem is fixed by a solution space S of all candidate solutions and a cost function h. A global optimum beats every s ∈ S; a local optimum beats only its neighbours — and what counts as a neighbour depends entirely on which moves your algorithm is allowed to make.

The Travelling Salesman Problem

Write these out exactly
TSPdec
Input) A complete weighted graph M = (V, d) with d : V × V → ℚ, and a value D ∈ ℚ.
Output) True iff G contains a Hamiltonian cycle H with length_of(H) ≤ D.

TSP
Input) A complete weighted graph G = (V, d).
Output) The shortest Hamiltonian cycle.

S = { all possible routes H }     h(H) = length_of(H) = ∑(x,y)∈H d(x, y)

Theorem. TSPdec is NP-complete.
Theorem: TSP is in P iff TSPdec is
(⇒) Trivial. Solve TSP for the optimal route H, then answer length_of(H) ≤ D.

(⇐) Binary search on D. Start with D⁻ = 0 and D⁺ = the total weight of all edges, an interval that must contain the answer, and halve it with each call to TSPdec until it is narrower than the shortest edge — at which point only one achievable tour length remains inside it.

Each call is polynomial and there are O(log) of them, so the whole thing is polynomial. This is why we can talk about “TSP is NP-complete” loosely: the two versions live or die together.
The loop condition on the slide is inverted
The lecture writes While (D⁺ − D⁻) < shortest edge of G. That is the stopping condition, not the continuing one. The interval starts at the total edge weight, which is far bigger than the shortest edge, so the test is false on the first evaluation and the loop body never runs — the algorithm then returns a route of length mid that was never assigned.

It should be While (D⁺ − D⁻) ≥ shortest edge. The tool below runs both so you can see the difference; the idea is right, only the inequality is backwards.

The approximation ratio

Write these out exactly
The approximation ratio of an algorithm M on input w is the value RM(w) ≥ 1 given by
RM(w) = max( Capprox/Cglobal ,   Cglobal/Capprox ) where Capprox is the cost of the approximate solution and Cglobal the cost of the optimal one.

A problem L is R-approximable if there is a polynomial-time algorithm M with RM(w) ≤ R for all w ∈ Σ*, equivalently Capprox ≤ R × Cglobal.

L is unapproximable if it is not R-approximable for any fixed R — every polynomial-time algorithm gives arbitrarily bad answers on some inputs.

The symmetric max is there so the ratio is at least 1 whether you are minimising or maximising. For TSP, a minimisation, the approximate tour can never be shorter than the optimum, so the ratio is always Capprox/Cglobal in practice.

“For all w” is the whole definition
A ratio is a worst-case guarantee, not an average. An algorithm that returns the optimum on a million inputs and something ten times too long on the next one is not 2-approximable. This is why you can refute a claimed ratio with one example but never establish one that way — establishing it takes a proof about every input, which is what the 2OPT argument below provides.

The 2OPT approximation algorithm

SWAP-MOVE(H)
1. For each pair of non-adjacent edges (x,y) and (u,v) from H
  2. If d(x,v) + d(u,y) < d(x,y) + d(u,v):
    3. Let H′ be H with (x,y),(u,v) replaced by (x,v),(u,y)
    4. Return H′
5. Return H unchanged if no improvement found
2OPT(G)
1. Construct a minimum spanning tree T0 of G
2. Let H0 be the preorder traversal of T0
3. While Hi is not (locally) optimal:
  4. Hi+1 ← SWAP-MOVE(Hi)
5. Return H
Which two edges do you add back?
Removing two edges from a cycle leaves two paths, with four ends between them. There are two ways to rejoin them and only one is a tour:

Join each path to the other — one Hamiltonian cycle ✓
Join each path to itself — two disjoint cycles ✗

That second case is what Step 4 of the slides — “make sure the swap does not disconnect the graph!” — is warning about. In tour terms the valid move is just “reverse the segment between the two removed edges”, which is why 2-opt is normally stated that way instead.

Its final tour, at ≈14.71, is not merely a local optimum — brute force over all 5040 tours confirms it is the global one. The achieved ratio is 1.00 while the guarantee is 2, which is the normal state of affairs: the bound is worst-case and typical inputs are not the worst case.

Also: the slides reach it in two swaps, but SWAP-MOVE as written returns the first improving pair, which takes six. The worked example is silently taking the best one each round. Both are valid 2-opt — the control above switches between them.

Proving the ratio

Theorem: 2OPT has approximation ratio R = 2
Write Happrox for the local optimum 2OPT returns and Hglobal for the true shortest cycle. We want length_of(Happrox) ≤ 2 × length_of(Hglobal).

Step 2) Delete one edge from Hglobal to get a path T. Then length_of(T) ≤ length_of(Hglobal).
Step 3) T is a spanning tree, and T0 is a minimum one, so length_of(T0) ≤ length_of(T).
Step 4) The preorder traversal walks each tree edge at most twice, so length_of(H0) ≤ 2 × length_of(T0).
Step 5) Every swap strictly shortens the cycle, so length_of(Happrox) ≤ … ≤ length_of(H0).

Step 6) Chaining them:
length_of(Happrox) ≤ length_of(H0) ≤ 2·length_of(T0) ≤ 2·length_of(T) ≤ 2·length_of(Hglobal)  ∎
The hypothesis the proof needs and the slide omits
Step 4 is where the work happens, and it is not free. The preorder traversal of the tree revisits vertices; turning it into a Hamiltonian cycle means shortcutting past the ones already seen. That shortcut is only an improvement if d(x,z) ≤ d(x,y) + d(y,z) — the triangle inequality.

The slide states “TSP is 2-approximable” without qualification, and the very next deck proves TSP is unapproximable. Both are correct. The first is about metric TSP and the second about the general case, and the whole difference between them is this one assumption. If an exam asks you to state the 2-approximation result, say metric TSP.

Note also what the swaps contribute to the bound: nothing. The factor of 2 is already earned at step 4, by the tree and the traversal alone. Steps 5 only says the swaps do not make things worse. They improve the answer in practice — often dramatically — but the guarantee would hold if you skipped them entirely.

Christofides, 1976
Theorem. Metric TSP is 3/2-approximable — build the MST, then add a minimum-weight perfect matching on its odd-degree vertices to get an Eulerian multigraph, and shortcut that. It stood as the best known ratio for metric TSP for over forty years.

When nothing can be guaranteed

Theorem: TSP is unapproximable when d violates the triangle inequality
Step 1) Suppose some polynomial-time algorithm achieves a fixed ratio R, so length_of(Happrox) ≤ R × length_of(Hglobal).
Step 2) Take any instance G = (V, E) of HAMILTONIAN, which is NP-complete.
Step 3) Build the complete weighted graph G′ = (V, d) with
d(x,y) = 1 if (x,y) ∈ E,    nR + 1 if (x,y) ∉ E Step 4) Then length_of(Happrox) ≤ nR ⟺ G has a Hamiltonian cycle.
  (⇒) A tour that short can only use edges of cost 1, so it is a Hamiltonian cycle of G.
  (⇐) If G has one, then length_of(Hglobal) = n, so the assumed ratio gives length_of(Happrox) ≤ R × n.
Step 5) So length_of(Happrox) ≤ nR decides HAMILTONIAN in polynomial time.
Step 6) Assuming P ≠ NP, no such algorithm exists. ∎

The trick is that nR + 1 is chosen after R is fixed. Whatever ratio you claim, the construction makes the penalty for using a single missing edge bigger than that ratio can absorb. That is why the conclusion is not “there is no 2-approximation” but “there is no R-approximation for any R at all”.

What this means outside the exam
The slides put it well: routing to minimise distance is approximable, because distances obey the triangle inequality — a detour cannot be shorter than going direct. Routing to minimise duration is not, because travel times need not: a motorway detour really can be quicker than the direct road through town.

So the same problem, on the same map, is 2-approximable or hopeless depending on what you put in the cells of d. That is a genuinely practical distinction, not a technicality.

Exam takeaways

Six one-liners
  • RM(w) = max(Ca/Cg, Cg/Ca) ≥ 1, and R-approximable means RM(w) ≤ R for all w.
  • TSP and TSPdec are polynomially equivalent, by binary search on D.
  • 2OPT = minimum spanning tree, preorder traversal, then swaps. Ratio 2.
  • The factor of 2 comes from the traversal walking each tree edge twice — not from the swaps.
  • That proof needs the triangle inequality. So the result is about metric TSP.
  • General TSP is unapproximable, by making non-edges cost nR + 1 — chosen after R.
Traps
  • Saying “TSP is 2-approximable” without the word metric. The unqualified claim is false, and the next slide proves it false.
  • Treating an approximation ratio as typical rather than worst-case.
  • Thinking the 2-opt swaps are what earn the factor of 2.
  • Reconnecting a 2-opt swap the wrong way and producing two disjoint cycles.
  • Forgetting TSP needs a complete graph — that is what makes every permutation a candidate tour.
  • Claiming a ratio from examples. Examples refute; only a proof establishes.
  • Confusing a local optimum with a global one. 2OPT returns the first, and only the bound relates it to the second.
