Topic 02 · Complexity

P, NP and the Million Dollar Problem

why checking an answer and finding one are not the same job

Topic 1 asked what a machine can do at all. This one assumes the machine can do it and asks what it costs. The answer turns out to depend on a distinction so simple it sounds like a trick: for a great many problems, nobody knows how to find an answer quickly, but anybody can check one quickly. Whether that gap is real or just a gap in our knowledge is the open question the topic is named after.

The shape of the argument
Measure a machine's running time as a function of input length, and throw away everything but the growth rate. Call a problem P if a deterministic machine decides it in polynomial time, and NP if a non-deterministic one does. Every P problem is an NP problem; nobody knows whether the reverse holds. Then reductions let you transfer hardness from one problem to another, and it turns out there is a family of problems — the NP-complete ones — that are all exactly as hard as each other, so that solving any one of them quickly would solve them all.

Measuring what a machine costs

Running time is measured in steps of the machine, not seconds, because seconds depend on the hardware and steps do not. Two definitions do the work.

The definitions to memorise
tM(w) — the number of steps machine M takes on the specific input word w.

TM(n) := max { tM(w) : |w| = n } — the worst input of length n.

The max is the part people skip. Complexity here is always worst case: a machine that is instant on almost every input and catastrophic on one of them is judged by the catastrophe.

Every problem in this topic is phrased as a decision problem — a question with a yes/no answer — so that it can be treated as a language, exactly as in Topic 1. The problem “does this graph have a clique of size k?” becomes the language of all encoded (graph, k) pairs for which the answer is yes, and “solving the problem” becomes “deciding the language”. Nothing is lost: an optimisation problem can usually be answered by asking the decision version a few times.

O, Ω and Θ

TM(n) is typically an ugly expression, and most of it is noise. Asymptotic notation keeps the part that survives as n grows.

The definitions to memorise
f ∈ O(g) ⟺ ∃c ∃N ∀n > N : f(n) ≤ c · g(n)   (upper bound)
f ∈ Ω(g) ⟺ ∃c ∃N ∀n > N : f(n) ≥ c · g(n)   (lower bound)
Θ(g) = O(g) ∩ Ω(g)   (both at once — a tight bound)

Two quantifiers, in this order: there exists a constant and a threshold such that for all larger n the inequality holds. You are allowed to pick c as large as you like and ignore as much of the start of the function as you like.

Which is why constant factors and lower-order terms vanish. 3n² + 500n + 9000 is Θ(n²): the 500n and the 9000 are eventually swamped, and the 3 is absorbed into c. Below n ≈ 40 the lower-order terms actually dominate — the tool shows the ratio starting near 9500 and sliding down to 3 — but “eventually” is the only word the definition uses.

O is an upper bound, not an estimate
n ∈ O(n!) is perfectly true and perfectly useless. Saying an algorithm is O(n²) does not say it is slow, and does not say it is Θ(n²). If you want to claim a running time is exactly that, you need Θ, which means proving a matching lower bound too. Exam questions exploit this.

P and NP

Here are the two definitions side by side. Read them carefully, because they differ by exactly one word.

PNP
Definition L ∈ P if some deterministic Turing machine decides L with TM(n) ∈ O(nk) for some fixed k L ∈ NP if some non-deterministic Turing machine decides L with TM(n) ∈ O(nk) for some fixed k
Intuition can be solved quickly a proposed answer can be checked quickly

The second row needs justifying, because it is not what the definition says. A non-deterministic machine, as in Topic 1, may branch — and accepts when some branch accepts. So an NDTM can guess a candidate answer in one burst of branching and then verify it deterministically. That is why “non-deterministic polynomial time” and “has a certificate you can check in polynomial time” come to the same thing, and the second phrasing is the one worth carrying around: NP is the class of problems whose yes-answers have short, quickly checkable evidence.

P ⊆ NP is the easy half
A deterministic machine is a non-deterministic machine that never branches. So anything decidable in deterministic polynomial time is decidable in non-deterministic polynomial time, and P ⊆ NP falls out immediately. Whether the containment is strict — whether there is anything in NP that is not in P — is the open problem, and it carries a million-dollar prize.
NP does not mean "not polynomial"
It means non-deterministic polynomial. Every problem in P is also in NP. If you catch yourself using "NP" to mean "hard", you are reaching for NP-hard, which is a different thing entirely and is defined further down.

The Boolean satisfiability problem

SAT
Input) A Boolean formula F over variables P, Q, R, …
Output) True if and only if there is an assignment of truth values to those variables that makes F true.

A formula with a satisfying assignment is satisfiable. One with none is unsatisfiable. One true under every assignment is a tautology.

The obvious method is a truth table: n variables give 2n rows, and you look for a true one. That decides the problem, so SAT is certainly decidable — but 2n is not polynomial, so it does not put SAT in P. Add one variable and the work doubles.

SAT is in NP, though, and the argument is the general one above. A non-deterministic machine branches once, guessing a row of the truth table, and then evaluates the formula along that single row. Evaluating costs at most one step per connective, which is linear in the size of the formula. Guess in parallel, check in polynomial time.

Normal forms: DNF and CNF

Any formula, however it is written, can be rewritten into either of two standard shapes without changing what it means.

FormShapeExample
DNF
disjunctive normal form		 An ∨ of ∧s — a disjunction of conjunctions of literals (P ∧ Q ∧ ¬R) ∨ (¬P ∧ Q ∧ R)
CNF
conjunctive normal form		 An ∧ of ∨s — a conjunction of disjunctions of literals (¬P ∨ ¬Q ∨ ¬R) ∧ (P ∨ Q ∨ R)

A literal is a variable or a negated variable, and nothing else. If you find a bracket or an implication inside what you are calling a clause, it is not in normal form yet.

Converting by rewriting — the four steps
1. Remove implications: A → B becomes ¬A ∨ B.
2. Push negations inward with De Morgan: ¬(A ∨ B) ≡ ¬A ∧ ¬B and ¬(A ∧ B) ≡ ¬A ∨ ¬B.
3. Cancel double negations: ¬¬A ≡ A.
4. Distribute. For DNF distribute ∧ over ∨ so the disjunctions rise to the top; for CNF distribute ∨ over ∧ so the conjunctions do.

Only the last step differs between the two, and it is the step where the formula can blow up in size.

There is a second route, and for exam purposes it is faster and far harder to get wrong: read the normal form straight off the truth table.

Reading normal forms off a truth table
DNF — use the TRUE rows. Each true row becomes one ∧-term describing exactly that row: a variable that is T appears plain, one that is F appears negated. Join the terms with ∨. The formula is then true precisely when you are in one of those rows.

CNF — use the FALSE rows. Each false row becomes one ∨-clause whose job is to exclude that row, so every literal is flipped: a variable that is T in the row appears negated. Join the clauses with ∧.

The flip is the only fiddly part, and it is where marks are lost. The clause exists to be false on that one row and true on all the others.

Cook–Levin
SAT is NP-complete. Stated here, proved later in the course. It matters now because it is the anchor: it is the first problem known to be NP-hard, so every later hardness proof can start from SAT instead of arguing about all of NP from scratch. Note also that SAT stays NP-complete when the input is restricted to CNF — which is why every reduction below takes a CNF formula as its input.

Polynomial reductions

A reduction is a way of saying “this problem is at least as hard as that one” without solving either.

The definition to memorise
A polynomial reduction from X to Y is a function f : Σ* → Σ*, computable in polynomial time, such that

w ∈ X  ⟺  f(w) ∈ Y

Written X ≤p Y, read “X is polynomially reducible to Y”.

Three things about that definition are worth pausing on. It is an if and only if, so f must preserve no-instances as well as yes-instances — a reduction that turns every input into a yes-instance of Y is not a reduction. The function must be computable in polynomial time, or the reduction could smuggle in the work of solving X. And the direction is the opposite of what the notation suggests to most people: X ≤p Y means Y is the harder one, because a fast algorithm for Y would give you a fast algorithm for X.

The direction, since it is the classic exam trap
To prove your problem X is hard, reduce a known-hard problem to it: SAT ≤p X. To prove X is easy, reduce it to something you can already solve: X ≤p (something in P). Reducing X to SAT proves nothing about X being hard — it only says X is no harder than SAT.

NP-hardness and NP-completeness

Two definitions, and they are not the same
X is NP-hard if Y ≤p X for every Y ∈ NP. X is at least as hard as everything in NP. Note that X need not itself be in NP — an NP-hard problem can be far worse, including undecidable.

X is NP-complete if (i) X is NP-hard (a lower bound) and (ii) X ∈ NP (an upper bound). Both halves are required, and an exam answer giving only one is giving half the marks away.

Proving NP-hardness from the definition would mean reducing every one of infinitely many NP problems to yours. The following theorem is what makes it practical.

Theorem — if Y is NP-hard and Y ≤p X, then X is NP-hard
1. Suppose (i) Y is NP-hard and (ii) Y ≤p X. the two assumptions
2. By (i), Z ≤p Y for every Z ∈ NP. unfolding the definition of NP-hard
3. So Z ≤p Y ≤p X for every Z ∈ NP. by (ii), and transitivity of ≤p
4. Hence X is NP-hard.  ∎

Transitivity is doing the real work in step 3, and it holds because composing two polynomial-time functions gives a polynomial-time function — a polynomial of a polynomial is a polynomial. So the recipe for showing a new problem X is NP-complete is two steps: show X ∈ NP by describing the certificate and the check, then show SAT ≤p X by constructing the reduction.

The Clique problem

CLIQUE
Input) An undirected graph G = (V, E) and an integer k > 2.
Output) True if and only if G contains a clique of size k — a set of k vertices with an edge between every pair.

CLIQUE ∈ NP. Checking every k-subset means checking (nk) of them, which is not polynomial. But a non-deterministic machine branches once to pick a subset, and each branch then checks only the k(k−1)/2 pairs within its subset — the k² quoted loosely elsewhere, which is polynomial. Guess in parallel, check quickly.

SAT ≤p CLIQUE. Given a CNF formula F, build a graph:

The construction
Vertices — one per literal occurrence. The same literal in two clauses gives two distinct vertices, so they are labelled with their clause number: P₁, ¬Q₁, P₃.

Edges — join L¹i and L²j exactly when i ≠ j (different clauses) and L¹ ≢ ¬L² (not each other's negation).

k — the number of clauses in F.

Each half of the edge rule enforces one half of what a satisfying assignment has to do. Because vertices in the same clause are never joined, a clique of size k must take exactly one literal from every clause — which is what “every clause has a true literal” means. Because complementary literals are never joined, it can never pick both P and ¬P — which is what “this is a consistent assignment” means. Put those together and a k-clique is a satisfying assignment, written in a different alphabet.

Since SAT is NP-hard and SAT ≤p CLIQUE, the theorem above makes CLIQUE NP-hard; and CLIQUE is in NP. So CLIQUE is NP-complete.

The Hamiltonian Cycle problem

HAMILTONIAN
Input) An undirected graph G = (V, E).
Output) True if and only if G contains a Hamiltonian cycle — a cycle visiting every vertex exactly once and returning to its start.
Not the same as an Eulerian circuit
A Hamiltonian cycle visits every vertex once; an Eulerian circuit uses every edge once. They sound like siblings and behave nothing alike: Euler's problem is decided in linear time by looking at the degrees (a connected graph has one exactly when every vertex has even degree), while Hamilton's is NP-complete. Two nearly identical questions, on opposite sides of the divide.

HAMILTONIAN ∈ NP, by the same shape of argument. Checking every permutation of the vertices means n! of them, which is not polynomial. But a non-deterministic machine guesses a permutation and each branch checks only the n edges along it. Guess in parallel, check quickly.

SAT ≤p HAMILTONIAN too, via a graph assembled from gadgets. Each variable becomes a small component that a Hamiltonian cycle can traverse in exactly two ways — left-to-right or right-to-left — and those two ways stand for “true” and “false”. Each clause becomes an extra vertex, wired into the variable gadgets whose literals appear in it, and reachable only if the cycle traverses at least one of them in the direction that makes the clause true. A cycle through the whole graph must therefore choose a direction per variable (an assignment) and satisfy every clause vertex. So the graph has a Hamiltonian cycle exactly when F is satisfiable, and HAMILTONIAN is NP-complete.

What a gadget is doing
Every reduction of this kind works the same way: find a piece of the target problem that has exactly two stable configurations, and use it to store a bit. The rest of the construction is plumbing that forces those bits to be consistent and forces every clause to be satisfied. Once you see the two-way gadget, the CLIQUE and HAMILTONIAN proofs stop looking like different tricks.

The Petersen graph has none either — but it is not bipartite, every vertex has degree 3, and no short argument explains it. The only way the tool knows is by exhausting the search. It does have a Hamiltonian path, which makes the near-miss concrete. This is the honest picture of the problem: sometimes there is a reason, and usually there is not.

Exam takeaways

What gets asked, and what loses marks
Give both halves of NP-completeness. NP-hard and in NP. Half an answer for half the definition.

Get the reduction direction right. To show X is hard, reduce a known-hard problem to X. SAT ≤p X, never X ≤p SAT.

Both directions of ⟺. A reduction must map no-instances to no-instances. Say so explicitly; it is often worth a mark on its own.

For "X ∈ NP", name the certificate. The subset, the permutation, the assignment — then say what checking it costs. That is the entire proof.

Θ needs two bounds. An upper bound alone gives you O, not Θ.

Flip the literals for CNF. Reading CNF off a truth table uses the false rows with every literal negated. The commonest slip in the topic.

NP means non-deterministic polynomial, not "not polynomial". P ⊆ NP.
The one-paragraph version
Cost is measured in worst-case steps as a function of input length, and asymptotic notation keeps only the growth rate. P is what a deterministic machine decides in polynomial time; NP is what a non-deterministic one does, equivalently what has a quickly checkable certificate. P ⊆ NP, and whether that is strict is open. A polynomial reduction X ≤p Y transfers hardness upward to Y; NP-hard means everything in NP reduces to you, NP-complete means that and membership in NP. SAT is NP-complete by Cook–Levin, and reductions out of it make CLIQUE and HAMILTONIAN NP-complete too — so all three stand or fall together.
