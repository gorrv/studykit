Topic 01 · Automata and Computability

Machines, Languages and Their Limits

from three states to the halting problem, in one topic

This topic asks one question in four increasingly ambitious forms: what can a machine recognise? Start with a machine that has nothing but a handful of states, and find out exactly what that buys you. Then find a language it provably cannot handle. Then give the machine a writable tape, watch its power jump, and discover that the new power comes with a price — it might never stop.

The shape of the argument
Finite automata recognise exactly the regular languages, which is also exactly what regular expressions describe. Some perfectly simple languages are not regular, and the pumping lemma is the tool for proving it. Turing machines lift the ceiling, and the Church–Turing thesis claims they lift it as high as it goes — but a Turing machine may run forever, so "recognise" and "decide" stop meaning the same thing.

Alphabets, words, languages

Three definitions, and they are almost aggressively simple. The work is in remembering that a language here is just a set of strings — it carries no meaning, no grammar, no interpretation.

TermDefinitionExample
Alphabet ΣAny finite set of symbols{0, 1}
WordAny finite string of symbols from Σ1001
Σ*The set of all finite words over Σε, 0, 1, 00, 01, …
εThe empty word — length zero, always in Σ*
Language LAny subset of Σ*, finite or infinite{ w : w has even length }
Two that trip people up
ε is not the same as ∅. The language {ε} contains one word (the empty one); the language ∅ contains no words at all. A machine that accepts {ε} accepts something; a machine that accepts ∅ accepts nothing.

"Any subset" really means any. The set of binary strings encoding prime numbers is a language. So is the set of programs that halt. Nothing so far says a machine can recognise either.

Deterministic finite automata

A DFA is a machine with a fixed, finite number of states and no memory beyond which state it is in. It reads its input once, left to right, and never writes anything down.

The definition to memorise
A DFA is a five-tuple A = ⟨ Σ, Q, qinit, F, δ ⟩: an alphabet Σ; a finite set of states Q; a start state qinit ∈ Q; a set of accepting states F ⊆ Q; and a transition function δ : Q × Σ → Q.

The word "function" is doing all the work. A function gives exactly one answer for every input, so from any state, on any symbol, there is exactly one place to go. That is what "deterministic" means, and it is why the computation below is a line rather than a tree.

A configuration is everything you would need to resume the machine: the state it is in, and the input it has not read yet. Written (q, w). A computation is the sequence of configurations you pass through, and the machine accepts when that sequence ends in an accepting state with nothing left to read.

A worked example worth knowing by heart
Three states, alphabet {0,1}, and the state is the value of the input so far modulo 3. Reading a bit doubles the number and adds the bit, so from state r on bit b you go to (2r + b) mod 3. Make q0 accepting and the machine recognises exactly the binary strings divisible by three — with three states and no arithmetic. Load it into the tool below and step through 1001 (that's 9).

Non-determinism

Change one thing: let δ return a set of states instead of one.

NFA versus DFA — the only difference
δ : Q × (Σ ∪ {ε}) → 𝒫(Q)

The tuple is otherwise identical. Two consequences follow. A configuration can have several successors, so the computation is a tree. And the machine may move on ε, changing state without reading anything.

Accept criterion: the word is accepted if any branch of the tree finishes in an accepting state with the whole word read. Not all of them — any.
The mistake this causes in exams
Students reject a word because they followed one branch, hit a dead end, and stopped. A dead branch means nothing on its own. You have to show that every branch fails before you can reject — which is exactly why the tool draws the whole tree rather than one path.

Non-determinism looks like it should be more powerful. It is not — only more convenient.

Theorem
Every NFA can be converted into a DFA accepting the same language. So NFAs and DFAs recognise exactly the same class of languages, and you may use whichever is easier to write down.

The proof is a construction, and it is the reason the theorem is believable: a state of the new machine is a set of old states — "everywhere the NFA could be right now". Since there are finitely many subsets, the new machine is still finite. Its start state is the ε-closure of the old start state, and a subset accepts exactly when it contains any old accepting state.

Regular expressions

The same class of languages, described from the other end. Instead of building a machine that recognises the words, you write a pattern that generates them.

Three operations, and that is the lot
Concatenationwvw then v
Alternation(w ∪ v)either w or v
Kleene starw*zero or more copies of w
A language is regular if some regular expression describes it.
The equivalence that ties the topic together
L is regular ⟺ some DFA (equivalently, some NFA) recognises L.

Left to right is Thompson's construction: build one little NFA gadget per operator and glue them together. Right to left turns a machine back into an expression by eliminating states one at a time. The tool below does the first direction for real — it compiles your expression into an NFA and answers membership by running it.
Star binds tighter than you think
ab* is a followed by any number of b: a, ab, abb, abbb…
(ab)* is any number of copies of ab: ε, ab, abab, ababab…
These differ at the second word. The enumeration in the tool makes the mistake obvious immediately, which is why it is there.

(0 ∪ 1(01*0)*1)* describes the binary multiples of three — the same language as the three-state machine further up. Compile it, note the DFA it produces has the same behaviour, and you have watched both directions of the equivalence theorem happen on one example.

Not every language is regular

Here is a language a five-year-old could check and no finite automaton can recognise:

Theorem
L = { anbn : n ≥ 0 } is not regular.

The argument is pigeonhole, and it is worth following once slowly because every later non-regularity proof is this one in disguise.

1 Suppose it were. Then some DFA A recognises it. Let p be A's number of states — a fixed, finite number, whatever it is.
2 Feed it a long word. Run A on akbk for some k > p. While reading the a's, A visits k + 1 states.
3 Pigeonhole. k + 1 visits, only p different states available, and k > p. So some state is visited twice while reading a's. This is the whole proof. Everything after it is bookkeeping.
4 Cut out the loop. Say A is in state q after i a's and again after j a's, with i < j. The machine went round a loop reading (j − i) a's and came back to exactly where it was.
5 A shorter word looks identical. Now run A on ak−(j−i)bk. It reaches the same state q, and from there the remaining input is the same bk. A cannot tell the two words apart — it ends in the same state on both.
× Contradiction. So A accepts both or rejects both. But akbk is in L and ak−(j−i)bk is not — fewer a's than b's. No such A exists. The machine failed because it could not count past p. A finite state set is a finite memory, and remembering "how many a's so far" needs unbounded memory.

The pumping lemma

That argument generalises. Rather than redo the pigeonhole every time, the pumping lemma packages it once.

The statement
Let L be an infinite language. If L is regular, then there is some p > 0 such that every word w ∈ L with |w| ≥ p can be written w = xyz where
  • |xy| ≤ p — the loop happens near the start
  • |y| > 0 — the loop is not empty
  • xynz ∈ L for every n ≥ 0 — going round it any number of times stays in L
Read the quantifiers as a turn order
∃p ∀w ∃xyz ∀n. Whoever picks a variable gets to see everything picked before it, so the alternation is a game:
  1. They pick p. You do not get to choose it, so your argument must work for any p.
  2. You pick w ∈ L with |w| ≥ p. This is your only real freedom — choose well.
  3. They pick the split x, y, z. You must beat every legal split, not just one.
  4. You pick n with xynz ∉ L.
Win however they play and L is not regular.
The lemma is one-directional
It says regular ⟹ pumpable. It does not say pumpable ⟹ regular. Failing to win the game tells you nothing at all — there are non-regular languages that pump perfectly happily. Use it only to prove a language is not regular, and never the other way round.

Turing machines

The finite automaton failed because it had nowhere to write anything down. Give it a tape it can write on and move around freely, and almost everything changes.

Where the machines sit relative to each other
MachineMemory it has
Finite automatonThe state, and nothing else
Pushdown automatonA stack — enough for aⁿbⁿ, not for ww
Linear bounded automatonA writable tape, but only as long as the input
Turing machineA writable tape, unbounded in both directions
The definition
M = ⟨ Σ, Q, qinit, qaccept, qreject, δ ⟩ with δ : Q × (Σ ∪ {␣}) → Q × (Σ ∪ {␣}) × {←, →}

Read as: seeing this symbol in this state, go to that state, write that symbol, and move one cell that way. Two changes from a DFA are worth naming. The blank symbol ␣ is part of the tape alphabet, because the tape is infinite and mostly empty. And there are now two named halting states rather than a set F — the machine says accept or reject and stops, rather than being asked at the end.

A configuration needs one more piece than before, because the head can move backwards: (state, everything left of the head, everything from the head rightwards). The machine accepts w when the computation starting from (qinit, ε, w) terminates in qaccept.

That word "terminates" is the whole topic
A DFA always stops: it reads n symbols and it is done. A Turing machine need not. It can move back and forth forever, and nothing in the definition prevents it. So there are now three possible outcomes, not two:
M(w) = 1M halts in qaccept
M(w) = 0M halts in qreject
M(w) = ↑M never halts at all
Deciding versus recognising
M decides L when it is sound (if M(w) = 1 then w ∈ L), complete (if w ∈ L then M(w) = 1), and terminating (M halts on every input, in L or not).

Drop the third condition and M merely recognises L: it says yes to every word of L eventually, but on a word outside L it may simply never answer. Every decidable language is recognisable; the converse is false, and that gap is where the halting problem lives.

Non-deterministic Turing machines, and Church–Turing

Do to a Turing machine what an NFA does to a DFA: let δ return a set of possible instructions.

NDTM
δ : Q × (Σ ∪ {␣}) → 𝒫( Q × (Σ ∪ {␣}) × {←, →} )

Configurations are unchanged; the computations now form a tree, exactly as with an NFA. M accepts w if any branch reaches qaccept.
Theorem, and its one-line proof
Every language recognised by a non-deterministic Turing machine is recognised by a deterministic one.

Why: build M′ which writes out the configurations of M's computation tree, breadth-first, and accepts as soon as it writes one whose state is qaccept. Nothing is lost — but note it must go breadth-first. Depth-first would risk diving down an infinite branch and never reaching the accepting one next to it.
Same power, not same speed
The simulation is exponentially slower — M′ explores a tree that M merely guesses its way through. Non-determinism costs nothing in what can be computed and a great deal in how long it takes. That gap, made precise, is the P versus NP question.
The Church–Turing thesis
Any language that can be computed by some finite mechanical process can be recognised by a Turing machine.

This is not a theorem and cannot be one — "finite mechanical process" is an informal idea, so there is nothing to prove it against. It is a claim about the world that has survived every attempt to beat it: λ-calculus, register machines, cellular automata, every programming language ever written, all turn out to recognise exactly the same class. Calling it a thesis rather than a theorem is deliberate, and examiners like you to notice.

Exam takeaways

The eight things worth having cold
  1. Both tuples. DFA ⟨Σ, Q, qinit, F, δ⟩ and TM ⟨Σ, Q, qinit, qaccept, qreject, δ⟩, and the type of δ in each case. Marks are given for these verbatim.
  2. NFA accepts if any branch does. Never reject on one dead branch.
  3. Subset construction. States are sets of states; a subset is accepting if it contains any accepting state; up to 2n but usually far fewer.
  4. Regular ⟺ recognised by a finite automaton. Both directions, and which construction proves which.
  5. aⁿbⁿ is not regular, by pigeonhole on the states visited while reading the a's.
  6. The pumping lemma's quantifier order, and that it only ever proves non-regularity.
  7. Deciding = sound + complete + terminating. Recognising drops termination.
  8. Church–Turing is a thesis, not a theorem, and why that distinction is forced.
Three answers that lose easy marks
Writing δ : Q × Σ → Q for an NFA (it returns a set). Concluding a language is regular because you failed to pump it. Saying a Turing machine "rejects" when it actually never halts — those are different outcomes and the difference is the examinable point.
