StudyKit

Revision notes that compute.

Each module builds into one self-contained HTML file — no server, no runtime dependencies, nothing fetched as you read. Open it and you get the notes, interactive tools that run the actual algorithms, self-marking questions generated fresh every time, full-text search, and a mock exam that scores you per topic.

§What makes it different

Most revision notes are static text. These run.

The tools execute the algorithms

Value iteration really sweeps the grid, UCB really picks the arm, the decision tree really computes every Gini-Split. Change an input and everything downstream recomputes.

Questions are generated, not stored

Numbers are randomised on every draw and marked by the same code the tools use, so you can't memorise answers. Every question explains its own working when you get it wrong.

Every figure is computed

No screenshots. The overfitting plots come from a real polynomial fit; the ε-greedy curves from a 400-run simulation; the dendrogram from an actual complete-linkage merge.

The numbers are verified

Each module ships with a jsdom test suite that drives the real page and cross-checks results against independent implementations. Several errors in the source course material were caught this way.

A note on the content. The explanatory writing, tools, figures and question banks in these files are original. The underlying subject matter — standard definitions, classic worked examples and exercises — comes from the usual sources any course on these topics draws on, and is reproduced here for study. The engine is the part built to be reused: see docs/AUTHORING.md to point it at your own material.

§Who made this

I'm Gor, a computer science undergraduate. I started this because revising from slide decks wasn't working — I could follow a worked example on paper and still not be able to reproduce it under exam conditions. So I built the tools first: a scheduler that actually simulates the clock, a value-iteration grid that actually sweeps, a page-replacement tracer that shows you Belady's anomaly rather than asserting it.

The notes grew around the tools, and the test suite grew around both — 512 assertions that drive the real pages and check the results against published worked examples and, where none exists, against exhaustive search. That turned out to be the most useful part: it caught several genuine errors in the material I was revising from, and a few of my own.

It's organised by topic rather than by anyone's timetable, so it should be usable whatever course you're taking — or none. If you adapt it for your own module I'd be glad to hear about it.
